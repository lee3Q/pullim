# 양방향 사다리 + 이면 사고 레이어 설계 결정

**날짜**: 2026-03-26
**방법**: 대표 직접 결정 (구현 전 설계 확정)

## 확정 사항

### 1. 사다리 단계 — 5단계 확정

```
직접 말하기 (자유 텍스트)
  ↕
선택지 + 추천
  ↕
분석 제안 ("이렇게 보이는데 맞아?")
  ↕
감각 변형 ("이쪽이 더 끌려?")
  ↕
감각 ("이거 좋아?")
```

- 더 세분화하면 탁상공론. 써봐야 안다.
- 5단계로 시작, 실사용 데이터 보고 조정.

### 2. 트리거

**내려가기**: "모르겠어" 버튼 (확정). 사용자가 명시적으로 누른다.

**올라가기**: 유도가 아니라 자연스럽게 직접 하는 것.
- 감각 단계에서 선택지를 확실히 고르게 되면 = 이미 올라간 것.
- 선택지를 직접 고를 수 있는 것 자체가 확실한 가치.
- AI가 "직접 말해볼래?"를 제안할 수는 있지만, 핵심은 사용자가 스스로 올라가는 것.

### 3. 기존 세션 파이프라인 — 갈아엎기 허용

- 기존 listen→research→analyze→debate→judge→conclude 파이프라인은 **재료**일 뿐.
- 현재 UX(양방향 사다리)를 추구하기 위해 처음부터 재설계해도 됨.
- 기존 코드에서 쓸 수 있는 건 가져오되, 구조에 얽매이지 않는다.

### 4. 이면 사고 레이어 — 가능한 모든 부분

MVP에서도 수집 가능한 모든 행동 데이터 활용:
- 응답 시간 (당연)
- 선택 패턴 (당연)
- 메시지 길이 변화
- 참여도 변화
- 추천 수락/거부 패턴

**추가 — "치트 선택지"**:
- "뭔가 대답이 별로면 이 버튼을 눌러줘!" 같은 명시적 피드백 버튼
- 사용자가 불만족을 직접 표현할 수 있는 치트 선택지 항상 존재
- 이것도 이면 사고 레이어의 입력으로 활용

## Ouroboros Seed 작성 방향

- 기존 세션 파이프라인 제약 없음 → 양방향 사다리 중심으로 새 세션 플로우 설계
- AC에 행동 기준 포함: "모르겠어를 3번 눌러도 끝까지 진행 가능하다"
- 치트 선택지 포함
- 이면 사고 레이어: 최소 응답시간+선택패턴+치트피드백 3종 수집
