# 치트 버튼 개선 + 세션 중 테마 전환 설계 결정

**날짜**: 2026-03-27
**방법**: 대표 직접 결정 (철학 토론에서 도출)
**배경**: 대표 개인 경험에서 "바꾸려 하지 않고 기다리는 것" 인사이트 → 풀림 철학 토론 → 구체 설계로 발전

## 확정 사항

### 1. 치트 버튼 — 2탭 확인 (실수 방지)
- 1탭: 확인 표시 ("정말?")
- 2탭: 실제 치트 발동
- 현재: 즉시 발동 → 실수 가능성 있음

### 2. 치트 후 분기 — AI 맥락 판단 3가지
- **a) "답만 별로"** → 같은 레벨에서 다시 생성
- **b) "테마 자체가 안 맞는 듯"** → "분위기 바꿔볼까?" 제안 (AI가 자동 전환하지 않음, 물어봄)
- **c) 누적 3회** → "접어둘까?" (기존 유지)

### 3. 테마 전환 판단 기준 (이면사고 레이어)
- 감각 선택 계속 거부 + 분석적 텍스트 입력 → 전략실 제안
- 분석 단계에서 감정적 반응 → 달빛정원 제안
- 등. 프롬프트 레벨에서 설계.

### 4. 핵심 원칙
- AI는 틀릴 수 있다고 전제한다
- 사용자에게 항상 교정 수단을 준다
- 테마 전환은 제안만, 결정은 사용자

## 구현 시점
- UI 피드백 수집 → 피드백 반영 → **이 기능 구현** → Claude API 실제 테스트
- API 테스트 전에 UI 레벨에서 완성해놓는다

## 철학적 근거
- "파악 없이 이끄는 것"이 문제. 파악 + 실시간 교정 수단이 있으면 이끄는 것도 OK.
- 사용자는 입체적 — 한 세션 안에서도 감각 ↔ 분석 모드를 오감.
- 3테마는 고정 프로필이 아니라 현재 경향.
