# 요금제 구조 설계 결정

**날짜**: 2026-03-28
**방법**: 대표 직접 결정 (사다리형 토론)
**상태**: 구조 확정, 숫자 미확정 (Phase 0 실측 후)

## 확정 사항

### 1. 과금 구조 — 양 제한, 동일 품질
- 무료/유료 모두 **동일 모델(Sonnet)** 사용
- 품질로 차등 두지 않음
- **이유**: 품질 차이가 나면 유료 전환 동기가 사라짐. "이게 이 정도구나" 하고 떠남. 풀 품질을 주고 "더 쓰고 싶다"를 만들어야 전환 동기가 생긴다.

### 2. 무료 vs 유료 차등 — 양 + 깊이 + 기록

| | 무료 | 유료 |
|--|------|------|
| **품질** | Sonnet (동일) | Sonnet (동일) |
| **양** | 주 N회 (미확정) | 무제한 |
| **깊이** | 사다리 세션만 | + 풀 파이프라인 (리서치/다중모델분석/토론) |
| **기록** | 세션 끝나면 사라짐 | 히스토리 저장 + 패턴 분석 |

- **기록이 유료의 핵심 잠금장치**: 양과 깊이만으로는 "필요할 때 무료 쓰면 되지"가 됨. 기록/패턴이 쌓여야 "이걸 잃기 싫다"가 생긴다.

### 3. 세션 규칙
- 세션 시작하면 끝까지 간다 (중간 차단 없음)
- 주간 리밋 도달 시에만 세션 중이라도 중단 (악용 방지, 예외 없음)

### 4. 전환 UX — 세션 중 유료 언급 절대 없음
- 세션 안에서는 온전히 함께한다
- 세션 끝난 뒤 요약 화면에서:
  - "오늘도 찾아와줘서 고마워요"
  - [풀림과 더 깊이 함께하기 →] — 작은 텍스트 링크 (버튼 아님)
- 리밋 도달 시: "이번 주는 여기까지. 다음 주에 또 만나요" + 같은 링크
- **톤**: 권유가 아니라 안내. 거부감 0에 가깝게.
- **금지**: "유료면 이런 패턴이 보여요" 같은 중간 힌트 — 의욕을 깎음

### 5. 온보딩 유료 체험 (CC 보강 → 대표 채택)
- 가입 후 첫 N일간 유료 기능 무료 체험 (기록 저장, 패턴 분석, 풀 파이프라인)
- 체험 끝나면 무료 티어로 자연스럽게 전환 (무료 기능은 그대로 유지)
- **이유**: 기록의 가치를 먼저 경험해야 "잃기 싫다"가 생김. 무료에서 기록이 처음부터 없으면 가치를 모름.
- N일 = 미확정 (7일 or 14일, Phase 1에서 테스트)

### 6. 넛지 톤 — 풀림다운 따뜻함
- 종료 후 알림: "기다리고 있어요" 느낌. 딱딱한 마케팅 문구 금지.
- 예: "지난번 이야기, 아직 기억하고 있어요. 또 오고 싶을 때 올게요."
- 세션 중 유료 언급 금지 정책 유지 + 종료 후 넛지 파이프라인 별도 설계 (Phase 1 이후)

### 7. API 남용 방지 (필수, 즉시 구현)
- Per-session 토큰 캡 (예: 50K tokens)
- Per-session 시간 제한 (30분, 25분에 마무리 유도)
- 주간 세션 횟수 제한 (무료: 주 N회, 유료: 일 10회 상한)
- API Route IP rate limiting (분당 10요청)
- 톤: 에러가 아니라 자연스러운 마무리 ("오늘은 여기까지 이야기했어요")

## 교차검증 결과 (2026-03-28, 3-model)
- **3자 일치**: 구조 부합 (업계 Best Practice), 동일 품질+양 제한 효과적, 세션 중 유료 없음 = 업계 표준
- **보강 채택**: 온보딩 체험기간 (5번), 넛지 톤 (6번), API 남용 방지 (7번)
- **Sonnet 지적**: 무료 100명 × 주3회 = 월 22만원 비용. 전환율 5%면 유료 5명으로 회수 필요
- **GLM-5 제안**: 무료도 "오늘의 요약" 1회성 다운로드 제공 — 미결정 (Phase 1에서 검토)

## 미확정 (Phase 0 실측 후 결정)
- 무료 주 N회 구체적 숫자
- 유료 월 가격
- 온보딩 체험기간 (7일 vs 14일)
- 무료 사용자당 비용 감수 한도
- → 실제 API 비용 실측 + 마진 목표 설정 후 /cross-check로 확정
