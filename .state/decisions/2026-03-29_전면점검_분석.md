## 결정 기록

### D1. 스트리밍 태그 처리 방식
- **선택지**: (A) 스트리밍 중 parseResponse 실시간 적용, (B) 첫 구조화 태그 이전 텍스트만 표시
- **결정**: B — regex split으로 태그 이전 텍스트만 표시
- **근거**: 부분 파싱은 불완전한 태그에서 깨짐. 태그 전 텍스트만 표시하면 안전.
- **즉시 수정 완료**: LadderSession.tsx:608

### D2. 텍스트 게임 모드 구현 방향
- **선택지**: (A) 새로운 TextGameSession 컴포넌트 생성, (B) 기존 사다리 레벨 1-4에 게임 UX 래핑
- **결정**: B — 기존 사다리 구조에 배경 이미지 + 내러티브 텍스트 추가
- **근거**: "진짜UX" 문서의 양방향 사다리 구조는 이미 올바름. 부족한 건 시각적 체험(이미지, 서사). 이미 /images/levels/ 에 레벨별 이미지 5테마×5레벨=25장 있음. 진입 화면에서 "텍스트 게임 / 대화" 선택지 추가.
- **철학 참조**: "텍스트 게임이라고 착각할 만큼 부담없고 즐겁게" (진짜UX 6장), "게임 식이든, 질문으로 고르게 하든 자신을 알고있냐 모르냐 파악 후" (진짜시작)

### D3. 약속 기능 구현 범위
- **선택지**: (A) 풀 구현 (반복 감지+약속 생성+다음 세션 확인), (B) 기반 코드만 (타입+스토어+UI 스텁)
- **결정**: B — 타입 정의 + 스토어 확장 + 세션 종료 시 "약속" 제안 UI 스텁
- **근거**: 풀 구현은 세션 히스토리 저장이 선행 조건(Supabase Auth 이후). 지금은 UI 흐름만 만들어두고 localStorage 기반으로 동작하게.
- **철학 참조**: "아는데 행동 못 하는 사용자에게 if/then 약속을 권유" (철학개선.md)

### D4. 데모 모드 개선 범위
- **결정**: 레벨당 8개 응답 + 5테마별 변형 + 데모 전용 요약 생성 + 전체 플로우 완주 가능하게
- **근거**: "뒷부분은 왜 작동 안되냐" 피드백. 데모가 제품 첫인상. 끝까지 가야 한다.

## 교차 검증 결과 (2-model, GLM-5 타임아웃)

### 질문 (3인칭)
한 1인 AI 멘탈케어 앱 창업자가 전면 점검 후 5개 밤배치 하네스를 작성했다. 실행 순서, 누락 문제, 타임아웃 리스크, 코드 충돌, 의사결정 재고 여부를 검증.

### 메인(Opus) 상세 분석

**1. 순서 적절성**: H4→H1→H5→H2→H3 ✅
- H4가 먼저: 빌드+배포 기반 확보
- H1이 두 번째: CRITICAL 사용자 체감 우선
- H2/H3이 후순위: 기능 추가

**2. 누락 문제**: 대표 피드백 전부 커버됨 ✅
- "리서치+분석+내면사고 돌아본 적 없음" → H5가 내면사고 커버, 리서치/분석은 유료 전용이라 보류 타당

**3. 40분 리스크**: H2에 집중 ⚠️
- H1: 데모 응답 40개(8×5) 작성 → 빡빡하나 가능
- H2: 25개 내러티브 + 배경이미지 연결 + 진입UI → **Task 1-2 필수, 3-4 시간 허용 시로 분리**
- **대응 완료**: 배치 스크립트에 우선순위 분리 지시 추가, 타임아웃 45분으로 확장

**4. 코드 충돌**: 순차 실행이므로 충돌 없으나 주의 필요 ⚠️
- H1, H2 모두 LadderSession.tsx 수정
- **대응 완료**: H2 프롬프트에 "기존 코드 먼저 읽고 최신 위에 수정" 명시

**5. D1-D4 재고**: 없음 ✅
- D1 regex split: 안전 (태그명 명시 열거)
- D2 기존 사다리 래핑: 구조 변경 최소화로 올바른 선택
- D3 기반 코드만: Auth 이후 확장 맞음
- D4 레벨당 8×5: 충분한 다양성

### 결론
2-model 기준 특별한 불일치 없음. H2 타임아웃 리스크에 대한 대응(우선순위 분리 + 45분 확장) 완료. GLM-5 관점 부재로 비즈니스/전략적 블라인드스팟 가능성은 있으나, 이번 작업은 기술 코드 수정이라 영향 제한적.
