# Handoff — 2026-03-28 (6) 요금제 구조 설계

## 이번 세션 요약 (3줄 이내)
무료/유료 요금제 구조를 사다리형 토론으로 설계. 3-model CC(Opus+Sonnet+GLM-5) 검증 완료. API 테스트 설계 + API 남용 방지 구현 프롬프트를 별도 세션용으로 작성.

## 핵심 맥락 (다음 세션이 반드시 알아야 할 것)
- **요금제 결정 파일**: `.state/decisions/2026-03-28_요금제_구조설계.md` — 7개 항목 확정
- **핵심 구조**: 동일 품질(Sonnet) + 양 제한 + 깊이 차등 + 기록 잠금장치
  - 품질 깎으면 이탈. 풀 품질로 "더 쓰고 싶다" 유도가 전환 동기
  - 기록(히스토리/패턴)이 유료의 핵심 잠금장치 — 양만으로는 "필요할 때 무료 쓰면 되지"
- **CC 보강 채택 3건**:
  1. 온보딩 유료 체험기간 (첫 N일간 유료 기능 무료 → 이후 무료 티어 전환)
  2. 넛지 톤 = 풀림다운 따뜻함 ("기다리고 있어요" 느낌, 딱딱한 마케팅 금지)
  3. API 남용 방지 필수 (토큰 캡/시간 제한/주간 횟수/IP rate limit)
- **세션 중 유료 언급 절대 없음** — 끝나고 "고마워요" + 텍스트 링크 1줄만
- **숫자는 전부 미확정** — Phase 0 API 실측 후 결정 (주 N회, 가격, 체험기간)
