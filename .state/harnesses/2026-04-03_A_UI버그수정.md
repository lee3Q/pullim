## 작업 항목

### Task 1: Stale Closure 패턴 스캔 + 수정
대상 파일: `src/components/session/LadderSession.tsx`

점검 포인트:
1. `sendToAI` (line 330) — `store`를 deps에 포함하지만 내부에서 `store.messages`, `store.turnCount` 등을 직접 읽음. Zustand의 `useLadderStore()`는 매 렌더 최신값이지만, useCallback 내부에서 캡처된 `store` 객체가 stale할 수 있음. `useLadderStore.getState()` 패턴과 비교 검증할 것.
2. `handleUserResponse` (line 511) — `store`와 `sendToAI` 의존. 내부에서 `store.messages`를 읽은 뒤 바로 `sendToAI`에 `store.messages` 전달 (line 559). `addMessage` 직후라 아직 업데이트 안 된 messages일 수 있음. `useLadderStore.getState().messages` 사용 여부 확인.
3. `handleOptionSelect` (line 565) — `currentResponse`를 의존성에 포함. 정상.
4. `handleCheat` (line 670) — `store.cheatCount`를 직접 읽고 +1 계산. 이건 이미 수동 보정됨. 정상.
5. `generateSummary` (line 600) — `store`만 의존. `store.messages` 직접 접근. 스냅샷 시점 확인.

수정 원칙:
- useCallback 내부에서 `store.xxx` 대신 `useLadderStore.getState().xxx`로 최신값 보장이 필요한 경우만 수정
- deps 배열에 불필요한 항목 있으면 정리
- 동작이 정상인 부분은 건드리지 마라

### Task 2: 조건부 렌더링 엣지 케이스 점검
대상 파일: `src/components/session/LadderSession.tsx`

점검 포인트:
1. `turns[cardIndex]` 접근 — `cardIndex >= 0 && cardIndex < turns.length` 가드 확인. `turns`가 빈 배열이고 `cardIndex`가 -1일 때 블록 자체가 스킵되는지 확인.
2. `currentResponse.sensoryCards.length > 0` — `currentResponse`가 null이 아님은 상위 조건에서 보장. 정상.
3. `currentResponse.comparisonCards![0]` — non-null assertion. `comparisonCards`가 truthy이면 반드시 2개 원소가 있는지 타입으로 보장됨. 방어 코드 추가 고려.
4. 폴백 TextInputLevel — 레벨 1에서 sensoryCards가 빈 배열일 때 폴백이 중복 표시되지 않는지 확인.

수정 원칙:
- 실제 런타임에서 undefined 접근이 가능한 경우만 수정
- optional chaining 추가가 안전한 곳은 추가
- 불필요한 non-null assertion(!) 제거하고 가드로 대체
