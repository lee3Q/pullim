## Task 1: GLM API 직접 진단

**읽기**: `pullim/.env.local`, `pullim/src/lib/providers/glm.ts`

**할 일**:
1. `pullim/.env.local`에서 `GLM_API_KEY` 값 확인 (키 존재 여부)
2. curl로 z.ai 게이트웨이 직접 테스트 — 응답 시간 측정:
   ```bash
   time curl -s -X POST "https://api.z.ai/api/anthropic/v1/messages" \
     -H "x-api-key: $GLM_API_KEY" \
     -H "anthropic-version: 2023-06-01" \
     -H "content-type: application/json" \
     -d '{"model":"GLM-5","max_tokens":100,"messages":[{"role":"user","content":"안녕"}]}' \
     2>&1 | head -20
   ```
   (GLM_API_KEY 값을 .env.local에서 읽어 대입)
3. 응답 시간 기록 + 에러 유무 확인

**산출물**: 진단 결과를 Task 2 수행 전 인라인 메모 (파일 저장 불필요)

**핵심**: 응답이 90초 내 오는지, 에러 코드가 무엇인지 파악해야 수정 방향이 결정됨

## Task 2: 원인별 수정

**읽기**: `pullim/src/lib/providers/glm.ts`, `pullim/src/lib/demo.ts`

### 2-A. glm.ts — timeout 추가 (필수 수정)

`messages.create()` 호출에 `timeout` 옵션 추가:

```typescript
const response = await getClient().messages.create({
  model: GLM_MODEL,
  max_tokens: params.maxTokens,
  temperature: params.temperature,
  system: params.system,
  messages: params.messages.map((m) => ({
    role: m.role === "system" ? "user" : m.role,
    content: m.content,
  })),
}, { timeout: 180_000 });  // 180초 — z.ai 게이트웨이 특성 반영
```

### 2-B. 서버 로그 추가 (원인 파악용)

API 라우트에서 GLM/demo 모드 로그 출력:
- `pullim/src/app/api/` 내 사다리 세션 API 라우트 찾아서
- 라우트 진입 시 `console.log('[mode]', isDemoMode() ? 'demo' : 'glm')` 추가
- **주의**: dev 서버 로그에서만 보임. 프로덕션 배포 전 제거 불필요 (dev-only 로그)

### 2-C. 빌드 확인

```bash
cd ~/study/main/pullim/pullim && npx next build 2>&1 | tail -20
```

빌드 성공 시 커밋:
```bash
cd ~/study/main/pullim && git add -A && git commit -m "fix: GLM 프로바이더 타임아웃 180초 + 모드 로그 추가"
```

**산출물**: `pullim/src/lib/providers/glm.ts` (수정), API 라우트 파일 (로그 추가)

**핵심**: timeout 옵션은 Anthropic SDK `RequestOptions` 두 번째 인자로 전달. `{ timeout: 180_000 }` 형식.
