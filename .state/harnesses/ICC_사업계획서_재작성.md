## 이 하네스의 목적

대표가 자는 5시간 동안 최대한 많은 검증을 돌려서, 대표가 일어났을 때 **복붙만 하면 되는** 최종본을 만든다. 판단이 안 서는 부분은 버전을 여러 개 만들어 대표가 고르게 한다.

## 절대 규칙 (위반 시 산출물 무효)

1. em dash(—) 사용 금지. 0개여야 한다.
2. 내부 용어 금지. v1, v2, v3, v4, v5, 끝판왕, 엔드게임 등.
3. 대표가 승인하지 않은 내용 금지. 팩트시트에 없는 사실을 쓰면 안 된다.
4. AI 과장 수사 금지. 극대화, 완벽한 시너지, 강력하고, 혁신적인, 획기적, 차별화된 가치, 고객 중심의, 선도적, 압도적, 독보적, 유례없는, 최적의, 최고 수준, 핵심 경쟁력을 확보, 새로운 패러다임, 게임 체인저.
5. 근거 없는 주장 금지. "전 세계에 확인되지 않는다" 등. 주장에는 반드시 출처/근거.
6. 공허한 종결 금지. "이를 통해~", "따라서~중요합니다", "~를 달성할 것입니다".
7. 동일 문장 구조 3회 이상 반복 금지.
8. 각 섹션은 해당 섹션이 묻는 것에만 답한다.

## 검증 자동화

```bash
./scripts/check_ai_patterns.sh <파일>
```
**PASS가 아니면 수정. PASS 없이 다음 단계 불가.**

## Phase 2: 3개 버전 작성 (2시간)

### 버전 C: 문제-해결형
- "이런 문제가 있다 → 이렇게 풀었다" 구조에 집중
- 기존 솔루션의 한계를 구체적으로 짚고, 풀림이 어떻게 다른지
- 가장 직관적이고 읽기 쉬운 구조

각 버전 작성 시:
1. **신청서/ICC_양식_가이드.md에서 해당 섹션의 "양식 원문"과 "답해야 할 것"을 먼저 확인한다**
2. 양식이 묻는 것에만 답한다. 묻지 않은 내용은 쓰지 않는다.
3. 팩트시트에서 필요한 사실만 골라 쓴다
4. 해당 버전의 톤으로 작성
5. **"이 내용이 이 자리에 맞는가?" 자문. 다른 섹션에 더 적합한 내용이면 삭제.**
6. check_ai_patterns.sh 실행 → PASS 필수
7. 파일 저장: 신청서/ICC_v6_최종/v6-A.md, v6-B.md, v6-C.md

→ `touch .state/.gate-1-written`

## Evolve Loop 규칙 (Ouroboros 참조)

- 같은 섹션이 3회 연속 FAIL(스크립트 또는 에이전트)이면, 부분 수정을 멈추고 해당 섹션을 **백지에서 완전히 새로 쓴다.** 이전 텍스트를 참고하지 않는다.
- 새로 쓸 때는 이전과 다른 접근을 시도한다. (예: 서술형이 안 되면 Q&A형, 추상적이면 구체 사례부터, 길면 반으로 줄여서)
- 5회 연속 FAIL이면 해당 섹션을 2개 버전으로 남기고 대표 선택에 맡긴다. 무한 루프에 빠지지 않는다.
- 검증 통과한 섹션은 다시 건드리지 않는다. 다른 섹션 수정 시 통과된 섹션의 내용과 모순이 생기면 새 섹션을 수정한다.

## 합리화 차단 규칙

- "시간이 부족하니 이 정도면 충분하다" → **금지. 게이트 건너뛸 수 없다. 시간 부족하면 버전 수를 줄이되 검증 라운드는 줄이지 않는다.**
- "이 표현은 괜찮을 것 같다" → **check_ai_patterns.sh가 FAIL이면 괜찮지 않다.**
- "심사위원 에이전트가 통과시켰으니 OK" → **Round 6(AI 탐지)에서 30% 초과면 불합격. 모든 라운드를 통과해야 한다.**
- "CC까지 하면 시간이 너무 걸린다" → **CC 없이 최종 산출물을 만들 수 없다.**
- "대표가 안 봐도 될 정도로 잘 썼다" → **대표가 승인하지 않은 내용이 있으면 무조건 삭제.**
- "이미 충분히 검증했다" → **Phase 6을 건너뛸 수 없다. 시간이 남으면 반드시 추가 검증.**
- "이 정도 AI 확률이면 넘어가자" → **30% 이하만 통과. 31%면 불합격.**

## 산출물 형식

- 줄글 (마크다운 테이블, 불릿 포인트 없음)

- 다른 칸에 들어가는 내용만 한 줄 띄운다
- em dash, 불릿(-), 번호(1.) 등 형식 기호 최소화
- [직접 기입] 표시 유지

## 세션 관리

- **매 섹션 작성 완료 즉시 파일에 저장한다.** 메모리에만 들고 있지 않는다.
- .state/.gate-* 파일로 진행 상태 추적
- 세션이 죽으면 새 세션에서 이 하네스를 읽고, .gate-* 파일을 확인하여 마지막 완료 지점부터 이어간다.
- **절대 멈추지 않는다. Phase 6까지 끝나면 추가 검증을 반복한다.**

## 팩트시트 (코드베이스 검증 완료)

### 풀림이란
AI 기반 의사결정 코칭 플랫폼. 타로의 의식적 경험과 AI의 데이터 분석을 결합. 구슬을 고르면 AI가 분석해주는 서비스.

### 현재 개발 상태
- Next.js 16 + React 19 + TypeScript 웹앱, PWA 지원
- pullim.vercel.app 에 배포되어 있음
- 3개 테마(모험가/전략실/달빛정원) 페이지 전부 구현됨 (동등한 수준)
- 프론트엔드 UI 컴포넌트 전부 구현: 테마 선택, 구슬 선택, 분석 뷰, 결론 뷰, 게임 대화, 진행 표시
- 백엔드 API 라우트 6개 구현됨: listen, research, analyze, debate, judge, conclude
- 멀티 모델 프로바이더 시스템 코드 완성: Claude + GPT + Gemini + local, 병렬 호출 함수(parallelChat) 구현
- 위기 감지 시스템 구현
- BGM, 배경 이미지, 아바타 에셋 적용
- Supabase SDK 설치됨 (인증/DB 연동은 미완)
- 데모 모드 존재 (API 키 없을 때 폴백)
- **요약: API 키만 넣으면 3테마 전부 실제 동작하는 수준. 프론트엔드+백엔드 코드 구현 완료.**

### 구현된 핵심 기능 (6개)
1. 자동 라우팅: 고민 복잡도에 따라 Quick Mode 또는 풀 파이프라인 분기
2. 선택형 질문: 프롬프트 대신 선택지 탭으로 진행
3. 3관점 병렬 분석: Claude/GPT/Gemini 이종 모델 독립 분석 + 교차 토론
4. 의사결정 정리 문서: 상황 요약, 선택지, 두려움, 첫 행동
5. 위기 감지(RED 프로토콜): 위기 키워드 감지 시 AI 중단 + 109 안내
6. 게임화 UI: 구슬 선택 애니메이션, 테마별 배경/캐릭터/BGM
