# 풀림 철학 개선

## 개요
풀림의 핵심 철학을 사상적 근거와 대조하며 정제하는 상시 프로젝트.
대표의 개인 경험, 외부 사상가 연구, 제품 설계 반영을 순환적으로 수행.

   - 현재 구현과 철학 대조 분석: 85~90% 일치 확인
   - 치트 버튼 개선 + 테마 전환 설계 결정 도출

## 확정된 철학 (2026-03-27 기준)

### 핵심 원칙
1. **"파악 없이 이끄는 것"이 문제** — 이끄는 것 자체는 OK. 파악이 선행되어야 함.
2. **AI는 틀릴 수 있다고 전제** — 사용자에게 항상 교정 수단 존재 (치트/모르겠어/직접 말하기).
3. **사용자는 입체적** — 고정 프로필이 아닌 확률 분포. 한 세션 안에서도 모드가 바뀜.
4. **Socratic 방식** — 답이 아니라 질문. "질문과 함께 사는 법"을 경험하게.
5. **holding environment** — 완벽한 AI가 아니라, 틀려도 무너지지 않는 관계.

### 사상적 매핑
| 원칙 | 일치 | 비판 |
|------|------|------|
| 옆에 있는 것 | 로저스(무조건적 긍정적 존중), 위니캇(holding) | 엘리스(소극적), 싱어(방관) |
| 질문으로 이끄기 | 소크라테스(산파술), 릴케(질문을 살기) | 한병철(또 다른 성과 압박) |
| 사다리 구조 | 비고츠키(ZPD/비계) | — |
| 보이지 않는 AI | 노자(무위) | — |

### 미해결 긴장
- 엘리스 비판: Level 1 무한 루프 사용자 — 기다리기만으로 충분한가?
- 한병철 비판: "고민을 풀어야 한다" 전제 자체가 압박일 수 있음
- 싱어 비판: 위기 아닌 상황에서의 개입 기준이 모호

### 새 기능 방향: "약속" (2026-03-29, 대표 인사이트)
**출처**: /decide 스킬의 Model F (반복→규칙 자동화)에서 발전
**핵심 아이디어**: "아는데 행동 못 하는" 사용자에게 if/then 약속을 권유

**메커니즘:**
1. 파악 중 반복 패턴 감지 (같은 고민, 같은 축 반복 선택)
2. "전에도 이런 고민 했었어. 그때는 이렇게 했었고." (기록 기반)
3. "이거 하나만 약속해볼래?" → 작은 if/then 규칙 생성
4. 다음 세션에서 "그거 했어?" 확인 → 성공/실패 둘 다 데이터

**왜 이게 풀림다운가:**
- 약속 = 실험 (틀려도 데이터)
- 리텐션 장치 (다시 와야 확인 가능)
- 유대 강화 ("풀림이 기억하고 있어")
- 실패해도 "풀림을 켜는 것만으로 발전" — 혼자면 실패에 포기하지만, 풀림이 있으면 실패가 관찰 데이터
- 자기이해 도구 → 자기변화 도구로의 전환점

**구현 시점**: PMF 이후, 기록(Recording) 기능과 함께. 유료 기능 후보.
**엘리스 비판 해소**: "기다리기만" 대신 "작은 약속"으로 행동유도 — 강제가 아닌 권유
