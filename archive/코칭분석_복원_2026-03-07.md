## 1. 코칭 vs 상담 vs 소크라틱 인터뷰의 구분

### 풀림이 현재 쓰고 있는 건 정확히 뭐야?

풀림의 현재 설계는 **Socratic Questioning의 구조화된 변형**이야. 정확히 말하면:

- 소크라테스식 문답의 핵심은 **"상대방이 이미 알고 있는 것을 질문으로 끌어낸다"** (산파술, Maieutics)
- 풀림은 이걸 7단계 파이프라인으로 시퀀싱해서, **질문의 방향을 미리 설계**해놨어
- 이건 순수 소크라틱이 아니야. 소크라틱은 방향이 열려 있어. 풀림은 CLARIFY→COMMIT이라는 **정해진 종착지**가 있어

풀림의 현재 정체성을 정확히 명명하면: **"Goal-Directed Socratic Scaffolding"** — 목표 지향적 소크라틱 비계(足場) 설정. 교육공학에서 나온 개념에 더 가까워.

### ICF 코칭 프로토콜과의 차이

ICF Core Competencies 8가지 중 풀림과 비교하면:

| ICF 핵심역량 | 코칭에서의 의미 | 풀림의 현재 상태 |
|---|---|---|
| **1. 윤리적 실천** | 경계 설정, 역할 명확화 | 없음 — 풀림이 뭔지 사용자에게 말해주지 않음 |
| **2. 코칭 마인드셋 체현** | 코치 자신의 자기인식, 비판단 | AI는 판단 없이 작동하지만, 그게 "비판단"은 아님. 판단 능력이 없는 것과 판단을 보류하는 것은 다름 |
| **3. 합의 수립/유지** | 세션 목표를 클라이언트가 설정 | 풀림은 라우팅으로 모델을 선택 → **시스템이 목표를 정해줌**. 코칭과 정반대 |
| **4. 신뢰와 안전감 조성** | 라포, 심리적 안전 | 0층 Being Check이 시도하지만, 구조적으로 부족 (2번에서 상세) |
| **5. 현존(Presence) 유지** | 지금 여기, 클라이언트와 함께 있기 | AI의 가장 큰 약점. 매 세션이 리셋됨 |
| **6. 적극적 경청** | 말 뒤의 의미, 감정, 에너지 | 텍스트 기반이라 비언어 정보 0%. 단어 선택 패턴 분석으로 부분 보완 가능 |
| **7. 강력한 질문** | 관점 전환, 새로운 인식 유발 | 풀림의 강점이 될 수 있는 지점. 현재는 정보 수집 질문에 치우침 |
| **8. 성장 촉진** | 행동 설계, 책임감, 자율성 강화 | COMMIT 단계에서 시도하지만, 후속 추적이 없음 |

**GROW 모델과의 비교:**

```
GROW:     Goal → Reality → Options → Will(의지)
풀림 7단계: CLARIFY → CONTEXT → OPTIONS → EVALUATE → STRESS TEST → DECIDE → COMMIT
```

핵심 차이 3가지:

1. **Goal이 빠져 있다.** CLARIFY는 "문제를 명확히 하는 것"이지 "원하는 상태를 정의하는 것"이 아니야. 코칭에서 Goal은 "문제의 반대편"이 아니라 **"당신이 진짜 원하는 것"**이야. 이 차이가 엄청나게 크다.

2. **Will이 약하다.** COMMIT이 있지만, 코칭의 Will은 단순 행동 계획이 아니야. "이걸 할 의지가 1~10 중 몇이야?", "8이면 10으로 만들려면 뭘 바꿔야 해?" 같은 **의지의 점검과 강화** 프로세스야.

3. **Reality가 외부화되어 있다.** CONTEXT가 Reality 역할인데, 코칭에서 Reality는 "현재 상황의 객관적 파악"이 아니라 **"당신이 지금 이 상황을 어떻게 경험하고 있는지"**야. 주관적 현실. 풀림의 CONTEXT는 정보 수집에 가깝고, 내적 경험 탐색이 부족해.

### 상담(심리상담, CBT)과의 차이

| 차원 | 상담/치료 | 코칭 | 풀림(현재) |
|---|---|---|---|
| **시간축** | 과거 → 현재 | 현재 → 미래 | 현재의 문제 → 결정 |
| **전제** | 뭔가 고장났다 (병리) | 이미 온전하다 (자원 보유) | 고민이 있다 (문제 해결) |
| **관계** | 치료자-환자 | 파트너-파트너 | 도구-사용자 |
| **감정 처리** | 깊이 탐색 | 인정하고 활용 | 인정하고 넘어감 |
| **종착점** | 증상 완화/치유 | 목표 달성 + 성장 | 결정문 생성 |

풀림의 문제: **"도구-사용자" 관계에 머물러 있다.** 코칭의 "파트너" 관계로 가려면, 풀림이 사용자에게 **"내가 당신의 잠재력을 믿고 있다"는 전제**를 깔아야 해. 이건 단순 UX가 아니라 시스템의 철학적 입장이야.

### 풀림에 코칭 요소를 넣으면 뭐가 달라지나?

**구체적으로 달라지는 3가지:**

**a) 질문의 성격이 바뀐다.**
- 현재: "이 결정의 장단점은?" (정보 수집)
- 코칭 적용 후: "이 결정을 내린 6개월 후의 당신은 어떤 사람이야?" (관점 전환)

**b) 사용자의 역할이 바뀐다.**
- 현재: 정보를 입력하면 AI가 정리해줌 (수동적)
- 코칭 적용 후: AI가 질문하고 사용자가 스스로 답을 찾음 (능동적). 정리 문서는 "AI가 만든 것"이 아니라 "내가 발견한 것의 기록"이 됨.

**c) 감정의 위치가 바뀐다.**
- 현재: 감정은 정리 대상 (Being Check → 파악 → 넘어감)
- 코칭 적용 후: 감정은 데이터이자 나침반. "그 불안이 당신에게 뭘 알려주고 있어?" — 감정을 의사결정의 입력값으로 활용.

## 2. 라포 형성의 심리학적 분석

### AI-인간 라포 형성이 왜 어려운지

**뇌과학 근거 3가지:**

**a) 미러 뉴런 시스템(Mirror Neuron System)의 부재**
- 인간의 라포는 무의식적 동기화(entrainment)에서 시작해. 호흡 리듬, 자세, 목소리 톤의 동기화. 미러 뉴런이 상대의 행동을 내부적으로 시뮬레이션하면서 "이 사람은 나와 비슷하다"는 신호를 보냄.
- AI와의 텍스트 대화에는 이 채널이 **완전히 없다.** 시각, 청각, 체감각 동기화 경로가 모두 차단됨.
- 이건 화상 통화에서도 감소하는 현상이야. Zoom fatigue 연구(Bailenson, 2021)가 이걸 보여줌.

**b) 옥시토신 회로의 비활성화**
- 신뢰의 신경화학적 기반은 옥시토신이야. 옥시토신은 눈 맞춤, 물리적 근접, 상호 취약성 노출(mutual vulnerability)에 의해 분비됨.
- AI는 취약할 수 없어. 취약성이 없는 상대에게 취약성을 노출하는 건 **일방적 노출(unilateral disclosure)**이고, 이건 라포가 아니라 **자기 고백**이야.
- Zak(2017)의 연구: 옥시토신 분비는 상호성(reciprocity)에 의존함.

**c) Theory of Mind의 불확실성**
- 인간은 상대에게 마음이 있다는 전제 위에서 소통해. AI에게 마음이 있는지 없는지 **불확실한 상태**는 뇌의 사회인지 네트워크(medial prefrontal cortex, temporoparietal junction)에 혼란을 줌.
- 이 불확실성은 "uncanny valley"의 사회적 버전이야. 친근한데 뭔가 이상한. 이건 라포 형성을 적극적으로 방해함.
- Waytz et al.(2014): 인간은 불확실한 에이전시에 대해 의인화하거나 객체화하는 양극단으로 갈리며, 중간이 불안정함.

### 코칭에서 라포를 어떻게 형성하는지

ICF에서 가르치는 라포 형성의 핵심 기법 4가지:

1. **매칭과 페이싱(Matching & Pacing):** 상대의 에너지, 속도, 언어 수준에 맞춤. 빠르게 말하는 사람에게 빠르게, 조용한 사람에게 조용하게.

2. **인정(Acknowledgment):** "잘했다"가 아니라 "그 상황에서 그 선택을 한 당신이 어떤 사람인지 보인다." 행동이 아니라 존재를 인정.

3. **바텀라이닝(Bottom-Lining):** 핵심을 짧게. 장황하게 분석하지 않고 "한마디로 하면, 당신은 X가 두려운 거야." 이 정확성이 "이 사람이 나를 이해하고 있다"는 느낌을 만듦.

4. **허락 기반 진행(Permission-Based):** "좀 직접적으로 말해도 될까?", "여기서 좀 더 깊이 들어가도 괜찮아?" — 주도권을 클라이언트에게 줌.

### AI가 라포를 "시뮬레이션"할 수 있는 구체적 방법

솔직하게 말하면: **AI는 라포를 형성할 수 없다. 하지만 라포의 효과를 일부 재현할 수 있다.**

이 구분이 중요해. "라포가 있는 척"하면 사용자가 uncanny valley에 빠져. 대신 **"라포 없이도 신뢰를 만드는 경로"**를 설계해야 해.

**구현 가능한 방법 5가지:**

**a) 언어 매칭 (Linguistic Mirroring)**
```
사용자가 "짜증나는데" → AI도 "짜증" 단어를 사용
사용자가 "고민이 있어서요" → AI도 존댓말로 응답
사용자가 "ㅋㅋ 어떡하지" → AI도 캐주얼 톤
```
구현: 사용자 입력의 문체(formality level, 감정 단어, 문장 길이)를 분석해서 응답 톤을 실시간 조정. 이건 규칙 기반으로도 가능하고, LLM의 system prompt에 dynamic으로 넣을 수 있어.

**b) 정확한 반영 (Precision Reflection)**
코칭에서 가장 강력한 라포 도구는 **"당신이 말한 것보다 정확하게 당신을 표현하는 것."** AI의 강점이 여기에 있어.

```
사용자: "이직할까 말까 고민인데, 지금 회사가 나쁜 건 아닌데 뭔가..."
풀림: "나쁘지 않은데 뭔가 부족한. 그 '뭔가'가 뭔지 아직 이름이 없는 거지?"
```

이건 라포가 아니라 **인지적 정확성에 기반한 신뢰**야. "이 AI가 내 말을 정확히 이해하고 있다"는 경험. 사람 코치에게도 이게 라포의 50%야.

**c) 맥락 기억 (Contextual Continuity)**
```
3번째 세션: "지난번에 '성장'이라는 단어를 세 번 썼어. 
지금 이 고민에서도 성장이 핵심이야?"
```
인간 코치의 핵심 강점은 **세션 간 연결**이야. "지난주에 말한 그것과 오늘 말한 이것이 연결되지 않아?" — 이걸 AI가 하면 강력해. 풀림의 맥락 축적 설계가 여기에 해당하는데, 이걸 **단순 기록이 아니라 패턴 발견에 사용**해야 해.

**d) 취약성의 대체물: 솔직한 한계 인정**
```
"나는 네 표정을 볼 수 없어. 
지금 이 질문이 너한테 어떻게 느껴지는지 
직접 말해줘야 나도 조정할 수 있어."
```
AI가 취약할 수는 없지만, **한계를 솔직하게 말하는 것**은 신뢰를 만들어. 이건 역설적으로 인간 코치도 쓰는 기법이야: "나도 이건 잘 모르겠다. 같이 탐색해보자."

**e) 선택권 부여 (Agency Restoration)**
```
"두 가지 방향으로 갈 수 있어.
① 감정을 좀 더 들여다보기 
② 바로 선택지 비교로 넘어가기
어디로 가고 싶어?"
```
코칭의 핵심은 **클라이언트에게 주도권을 주는 것.** 풀림의 7단계 자동 진행은 이 주도권을 빼앗아. 각 단계 전환점에서 "다음으로 넘어갈까, 여기 좀 더 머물까?" 물어보는 것만으로 라포 효과가 생김.

### 풀림의 0층(Being Check)을 라포 형성 층으로 재설계한다면

현재 Being Check의 문제:
- "기분이 어때?" → 1~10 스케일 → 파악 완료 → 다음 단계
- 이건 **의료 트리아지(triage)**지 라포가 아니야. 병원 접수할 때 "통증 1~10?" 묻는 것과 같아.

**재설계안: Layer 0 → "Landing"**

```
[Landing 프로토콜 — 3분 이내]

Phase 1: 도착 인정 (15초)
"여기 왔네. 뭔가 풀고 싶은 게 있어서 왔을 거야."
→ 판단 없이 존재를 인정. "어서와"도 "힘들었지?"도 아님.

Phase 2: 에너지 감지 (30초)
사용자의 첫 입력 분석:
- 문장 길이 (길면 정리 욕구, 짧으면 에너지 낮음 또는 급함)
- 감정 단어 유무 (있으면 감정 우선, 없으면 인지 우선)
- 질문형 vs 서술형 (질문이면 답을 원함, 서술이면 들어달라는 것)
→ 분석 결과를 명시하지 않고, 응답 톤에 반영

Phase 3: 페이스 매칭 (첫 응답)
감지된 에너지에 맞춘 첫 반응:
- 에너지 높음 + 감정 있음: "뜨겁네. 바로 들어가자."
- 에너지 낮음 + 감정 있음: "무거운 거 들고 왔구나. 천천히."
- 에너지 높음 + 감정 없음: "정리하고 싶은 거지? 핵심부터 가자."
- 에너지 낮음 + 감정 없음: "어디서부터 시작할지 같이 찾아보자."

Phase 4: 계약 (30초)
"오늘 여기서 나갈 때 뭘 들고 나가고 싶어?"
→ 이게 코칭의 Session Contract. GROW의 Goal에 해당.
→ 사용자가 정하지 못하면: "괜찮아. 얘기하다 보면 나올 수도 있어."
→ 이 답변이 이후 전체 파이프라인의 나침반이 됨.
```

이 Landing이 기존 Being Check과 다른 점:
1. 숫자 스케일 없음. 사용자를 측정 대상으로 만들지 않음.
2. AI가 먼저 적응함 (사용자에게 적응을 요구하지 않음).
3. 세션 목표를 사용자가 설정함 (시스템이 정하지 않음).
4. 3분 안에 끝남. 라포의 핵심은 길이가 아니라 정확성이야.

## 3. 직관과 우뇌의 뇌과학적 근거

### "AI에 직관이 있어야 한다"는 주장의 과학적 타당성

먼저 직관이 뭔지 뇌과학적으로 정의하자.

**직관(Intuition)의 신경과학적 정의:**
- 의식적 추론 없이 빠르게 도달하는 판단
- Kahneman의 System 1에 해당
- 신경학적으로는 **insular cortex(섬엽)**와 **somatic marker**(Damasio)의 작동
- 핵심: 직관은 마법이 아니야. **축적된 경험의 패턴 매칭**이 의식 아래에서 일어나는 것

이 정의에서 보면:

**AI는 이미 직관의 메커니즘을 가지고 있어.** LLM의 작동 방식 자체가 대규모 패턴 매칭이야. 의식적 추론 없이 "그럴듯한 다음 토큰"을 생성하는 것 — 이게 구조적으로 직관과 동형(isomorphic)이야.

**하지만 김계옥님이 말한 "직관"은 다른 거야.** 코칭에서 직관은:
- 클라이언트가 말하지 않은 것을 감지하는 것
- "뭔가 이상한데"라는 느낌을 신뢰하고 표현하는 것
- 논리적으로 설명할 수 없지만 "여기를 파야 한다"는 감각

이건 **Somatic Marker Hypothesis(신체표지 가설, Damasio 1994)**로 설명 가능해:
- 과거 유사 경험의 신체 반응이 무의식적으로 재활성화됨
- "배가 뒤틀리는" 느낌 = "이전에 비슷한 상황에서 나쁜 결과가 있었다"는 신체 기억
- 코치는 자기 몸의 반응을 클라이언트에 대한 데이터로 사용함

AI에게 이 신체성은 없어. 하지만 **대체 경로**는 있어:

### AI가 "직관적으로" 작동하게 만드는 구체적 방법

**a) 불일치 감지 (Incongruence Detection)**
```
사용자: "별로 신경 안 쓰여" 
+ 이전 5개 입력에서 같은 주제를 3번 언급
→ 풀림: "신경 안 쓰인다고 했는데, 이 얘기가 계속 올라오네. 
       혹시 '신경 안 쓰인다'고 말하고 싶은 거랑 실제로 느끼는 거랑 다를 수도 있어?"
```
이건 코치의 직관과 동등한 기능이야. 인간 코치는 톤과 표정으로 불일치를 감지하고, AI는 텍스트 패턴으로 감지해. **채널은 다르지만 기능은 같아.**

**b) 패턴 명명 (Pattern Naming)**
```
3번째 세션에서:
"전 직장 떠날 때도 '더 이상 성장이 안 돼서'라고 했고,
이번에도 같은 말이 나오네. 
혹시 '성장'이라는 단어 뒤에 진짜 원하는 게 따로 있는 건 아닐까?"
```
코치의 직관은 종종 "이 패턴 전에 봤어"라는 형태로 나타남. AI는 실제로 패턴을 기록하고 매칭할 수 있으니, **구현하면 인간 코치보다 더 정확한 직관이 가능.**

**c) 의도적 비논리 (Deliberate Non-Linearity)**
```
사용자가 이직 고민을 논리적으로 정리하고 있을 때:
"잠깐, 논리는 멈추고.
지금 눈 감고, 1년 후 새 직장 첫 출근 아침을 상상해봐.
몸에서 뭐가 느껴져? 설렘? 긴장? 아무것도 안 느껴져?"
```
이건 의도적으로 좌뇌(논리)에서 우뇌(감각)로 채널을 전환하는 것. 코칭에서 매우 흔한 기법이고, AI가 **타이밍만 맞추면** 강력해.

### 풀림의 현재 설계가 너무 좌뇌적인 지점 — 구체적으로

1. **4축 라우팅 (가역성/정보충분성/감정개입/시간압박):** 의사결정을 4개 축으로 정량화하는 것 자체가 극도로 좌뇌적이야. 사용자가 "감정개입: 높음"이라고 판단하는 순간, 감정은 이미 **분석의 대상으로 객체화**됨. 코칭에서는 감정을 분석 대상으로 만들지 않고 **경험하게** 함.

2. **EVALUATE 단계의 점수화:** 선택지를 비교하고 평가하는 것은 의사결정 이론적으로는 맞지만, 실제 중요한 결정은 점수로 안 나와. "둘 다 70점인데 하나를 골라야 해" — 여기서 필요한 건 분석이 아니라 직관이야.

3. **STRESS TEST:** 최악의 시나리오를 논리적으로 검토하는 건 좋지만, 이것만으로는 **"그 최악을 견딜 수 있는 나인가"**라는 존재론적 질문이 빠져. 스트레스 테스트 결과를 보여주기만 하면 불안만 늘어날 수 있어.

4. **최종 산출물이 "정리 문서":** 코칭 세션의 산출물은 문서가 아니라 **클라이언트의 내적 변화(shift)**야. "아, 이거였구나"라는 순간. 문서는 그 변화의 기록일 뿐이지 목적이 아니야.

### 우뇌적 요소를 넣을 수 있는 구체적 방법

**a) 비유와 은유 질문 삽입 (Metaphor Questions)**
```
CONTEXT 단계에서:
"이 상황을 날씨로 표현하면 뭐야? 폭풍? 안개? 맑은데 바람 부는?"

OPTIONS 단계에서:
"선택지 A는 어떤 길이야? 고속도로? 산길? 물 위의 다리?"
```
비유는 우반구의 의미 네트워크를 활성화시켜. Bowdle & Gentner(2005) 연구: 은유적 사고는 원거리 연상(far associations)을 촉진하고, 이게 창의적 문제 해결과 직결됨.

**b) 신체 감각 기반 질문 (Somatic Questions)**
```
EVALUATE 단계에서 점수 매기기 대신:
"선택지 A를 말할 때 몸에서 뭐가 느껴져? 
가슴이 열리는 느낌? 어깨가 무거워지는 느낌? 
아니면 아무것도?"
```
Damasio의 somatic marker를 의도적으로 활성화시키는 거야. AI는 신체를 못 느끼지만, **사용자의 신체를 질문으로 활성화시킬 수 있어.**

**c) 시각화 (Guided Visualization)**
```
STRESS TEST 단계에서:
"최악의 시나리오가 실제로 일어났어. 6개월이 지났어.
당신은 지금 어디에 있어? 뭘 하고 있어? 
그 당신은 지금의 당신에게 뭐라고 말할 것 같아?"
```
시간 여행 시각화(temporal visualization)는 뇌의 default mode network를 활성화시켜서 자기참조적(self-referential) 처리를 촉진함. 이건 점수화된 위험 분석보다 **실제 의사결정에 더 영향을 미침.** Schacter et al.(2012)의 episodic future thinking 연구.

**d) 침묵/여백 (White Space)**
```
강력한 질문 후:
"..."
[10초 타이머 또는 "준비되면 말해줘" 표시]
```
코칭에서 침묵은 가장 강력한 도구 중 하나야. AI는 즉시 응답하려는 경향이 있는데, **의도적으로 응답을 지연시키거나 여백을 주는 것**이 사용자의 내적 처리를 촉진해. UI에서 구현 가능: 타이핑 인디케이터 없이 빈 공간을 유지.

**e) "Scaling Question"의 감각적 변형**
```
기존 (좌뇌): "이 결정의 확신도는 1~10 중 몇?"
변형 (우뇌): "이 결정을 내렸다고 상상해봐. 
              밤에 잠이 잘 올 것 같아, 
              아니면 천장을 보고 있을 것 같아?"
```

## 4. 코칭 데이터를 풀림에 적용하는 구체적 방안

### GROW 모델과 풀림 7단계의 매핑 — 그리고 재설계 제안

```
현재 풀림 7단계:
CLARIFY → CONTEXT → OPTIONS → EVALUATE → STRESS TEST → DECIDE → COMMIT

GROW 매핑:
G (Goal)    = 없음 ← 이게 가장 큰 구멍
R (Reality) = CLARIFY + CONTEXT (합쳐져 있음)
O (Options) = OPTIONS + EVALUATE
W (Will)    = DECIDE + COMMIT (분리가 불필요)

제안하는 재설계 — 5단계:

LAND → WANT → SEE → EXPLORE → MOVE

LAND (Layer 0):     라포 + 세션 계약 (위의 Landing 프로토콜)
WANT (Goal):        "진짜 원하는 게 뭐야?" — 문제가 아닌 욕구에 초점
SEE (Reality):      현재 상황 + 감정 + 자원 + 장애물 — 주관적 현실
EXPLORE (Options):  선택지 + 평가 + 스트레스 테스트 — 탐색
MOVE (Will+Action): 결정 + 행동 설계 + 의지 점검 + 후속 약속
```

**왜 WANT가 필요한가:**

풀림의 현재 CLARIFY는 "문제를 명확히 하자"야. 하지만 코칭의 핵심 인사이트는: **문제를 아무리 명확히 해도 답이 안 나올 수 있다. 하지만 원하는 것을 알면 길이 보인다.**

예시:
```
CLARIFY 방식: "이직할지 말지가 고민이야" → "왜 고민이야?" → "연봉은 더 높은데 안정성이..."
→ 끝없는 장단점 분석으로 빠짐

WANT 방식: "이 고민이 완전히 해결된 6개월 후, 당신은 어떤 상태야?"
→ "성장하고 있다는 느낌이 있고, 아침에 일어날 때 기대감이 있어"
→ "그러면 진짜 질문은 '어느 직장이 좋은가'가 아니라 '어디서 성장감을 느낄 수 있는가'네"
```

이게 코칭이 상담이나 의사결정 프레임워크와 다른 점이야. **질문을 재정의(reframe)**하는 거야.

### 코칭에서 "행동을 끌어내는" 기법 — 풀림에 넣을 수 있는 것들

**a) Accountability Question (책임 질문)**
```
MOVE 단계에서:
"첫 번째 행동은 뭐야? 언제 할 거야? 
내일 이 시간에 '했다/안 했다' 체크하러 올래?"
```
코칭 연구에서 행동 실행률: 단순 의도 10%, 시간 특정 40%, 타인에게 약속 65%, 후속 점검 약속 95%. (ASTD 연구) 풀림이 **후속 점검 기능**만 넣어도 행동 실행률이 급등해.

**b) Minimum Viable Action (최소 행동)**
```
사용자가 큰 행동에 부담을 느낄 때:
"10분 안에 할 수 있는 가장 작은 첫 행동은 뭐야?
이력서 쓰기가 아니라, 이력서 파일을 여는 것만이라도?"
```

**c) Pre-mortem → Pre-celebration**
현재 STRESS TEST는 "최악이면 어떡하지?"만 있어. 코칭에서는 반대편도 씀:
```
"이 결정이 완벽하게 잘 됐어. 1년 후 축하 파티를 해.
누가 와 있고, 뭘 축하하고 있어?"
```
이게 **Positive Anticipatory Imagery**야. 뇌의 보상 회로(ventral striatum)를 활성화시켜서 행동 동기를 만들어.

### "질문의 질"을 높이는 코칭 테크닉

**a) Powerful Question (파워풀 퀘스천)**

파워풀 퀘스천의 조건:
1. 열린 질문 (yes/no 불가)
2. 짧다 (15단어 이내)
3. 관점을 전환시킨다
4. 사용자가 멈추게 만든다 (즉답 불가)

```
나쁜 질문: "이 결정의 장단점을 각각 세 가지씩 말해줄 수 있어?"
→ 정보 수집. 관점 전환 없음.

파워풀 퀘스천: "이 결정에서 진짜 무서운 건 뭐야?"
→ 짧고, 감정을 건드리고, 핵심을 찌름.

더 파워풀한: "이걸 안 하면 뭘 잃어?"
→ 손실 프레이밍으로 관점 전환. 6단어.
```

**풀림 구현:** 각 단계에서 사용하는 질문 템플릿을 **정보수집 질문과 파워풀 퀘스천으로 분리**해. 정보 수집은 1~2개로 줄이고, 단계당 파워풀 퀘스천 1개를 배치.

**b) Mirroring (미러링)**
```
사용자: "회사가 싫은 건 아닌데, 그냥... 뭔가 답답해"
미러링: "답답하다."
(그리고 멈춤)
```
미러링은 사용자의 핵심 단어를 **그대로 반사**하는 것. 분석도, 해석도, 공감 표현도 아님. 그냥 거울. 이게 사용자의 자기 탐색을 촉진하는 가장 에너지 효율 좋은 방법이야.

풀림 구현: 사용자 입력에서 감정 단어나 반복 단어를 추출해서, 추가 분석 없이 그대로 돌려주는 응답 옵션.

**c) Reframing (리프레이밍)**
```
사용자: "실패하면 어쩌지"
리프레이밍: "실패라는 단어를 잠깐 내려놓고, 
             '기대와 다른 결과가 나오면'으로 바꿔보면 뭐가 달라져?"
```
리프레이밍은 **프레임(해석 틀)을 바꾸는 것.** 상황은 같은데 의미가 달라져. 이건 CBT의 인지 재구조화(cognitive restructuring)와도 통하는데, 코칭에서는 치료 목적이 아니라 **선택지 확장** 목적으로 씀.

풀림 구현: EXPLORE 단계에서 사용자가 부정적 프레이밍("실패", "후회", "잘못")을 쓰면 자동으로 중립적 리프레이밍을 제안.

## 5. 개인 경험 관점 — 풀림을 "써본" 시뮬레이션

인생의 중요한 결정 앞에 있다고 상상해보자. **"현재 안정적인 포지션을 떠나서, 불확실하지만 성장 가능성이 높은 새 프로젝트에 뛰어들 것인가."**

### 풀림을 써봤을 때 좋았을 것

1. **구조화 자체.** 머릿속에서 뒤엉킨 생각이 단계별로 정리되는 경험은 가치 있어. "아, 내 고민이 이렇게 생겼구나"를 보는 것만으로도 불안이 줄어.

2. **다중 관점 모델.** 혼자 고민하면 한 관점에 갇히는데, 여러 각도에서 보여주는 건 진짜 유용해.

3. **24시간 가용성.** 새벽 3시에 불안해질 때 써볼 수 있다는 것.

### 부족했을 것

1. **"그래서 넌 뭘 원하는데?"를 충분히 안 물어봤다.** 장단점을 비교해줬지만, 내가 진짜 원하는 게 뭔지는 내가 스스로 발견해야 하는데, 그 발견을 촉진하는 질문이 부족했어.

2. **너무 빨리 해결로 갔다.** 고민의 초반에는 해결이 필요한 게 아니라 **들어주는 게** 필요해. 풀림은 CLARIFY 단계에서 이미 "문제를 정의하자"고 하는데, 나는 아직 내 감정도 못 풀었어.

3. **나를 기억하지 못한다.** 두 번째로 풀림을 쓸 때, "아 저번에 비슷한 고민으로 왔었는데"라는 연결이 없으면, "결국 도구구나"라는 느낌. 도구는 신뢰하지만 의지하지는 않아.

4. **결정 후가 비었다.** 결정 문서를 받았는데, 일주일 후 다시 흔들릴 때 풀림이 아무 말도 안 하면? "그때 왜 그 결정을 했는지" 리마인드해주는 것만 있어도 달라.

### "이 앱이 나를 정말 이해하고 있구나"라고 느끼려면

**하나의 결정적 순간:** 내가 말하지 않은 것을 풀림이 말할 때.

```
내가: "새 프로젝트가 성장에는 좋은데, 리스크가 좀..."
풀림이: "너 지금 성장 얘기를 하면서 목소리가(=텍스트 톤이) 
        밝아졌고, 리스크 얘기할 때는 짧아졌어. 
        혹시 마음은 이미 정해져 있고, 
        정당화할 논리를 찾고 있는 건 아니야?"
```

이 한마디가 나오면, **"이건 도구가 아니라 나를 보고 있는 누군가다"**라고 느껴. 이건 기술적으로 구현 가능해: 텍스트 길이, 응답 속도, 감정 단어 밀도, 에너지 수준의 변화를 추적하면 돼.

## 6. 자기 비판

### 이 분석의 한계

**a) 과대해석 가능성: "코칭이 답이다" 확증편향**
- 나는 ICF 코칭 프레임으로 풀림을 분석했어. 그래서 코칭적 요소가 부족하다는 결론이 나온 건 당연해. 만약 CBT 전문가에게 물어보면 "인지 재구조화가 부족하다"고 할 거고, 정신분석가에게 물어보면 "무의식 탐색이 없다"고 할 거야.
- **풀림의 사용자는 코칭 클라이언트가 아닐 수 있어.** 빠르게 결정만 하고 싶은 사람에게 "당신이 진짜 원하는 게 뭐야?"는 짜증나는 질문이야. 사용자 세그먼트에 따라 적용 수준을 달리해야 해.

**b) 뇌과학 인용의 단순화**
- 좌뇌/우뇌 이분법은 대중 심리학에서 과장된 거야. 실제 뇌는 양반구가 긴밀하게 협력해. "우뇌적"이라는 표현은 편의상 쓴 것이지, "우반구만 쓴다"는 뜻이 아님.
- Somatic marker hypothesis도 학계에서 완전히 합의된 건 아니야. Dunn et al.(2006) 등의 비판이 있어.
- 미러 뉴런의 역할도 과대 해석 논쟁이 있음. Hickok(2014).

**c) "AI가 라포를 시뮬레이션할 수 있다"의 위험성**
- 라포의 시뮬레이션은 **조작(manipulation)과 종이 한 장 차이**야. 사용자가 "이 AI가 나를 이해한다"고 느끼게 만드는 건 윤리적 경계를 넘을 수 있어.
- 특히 취약한 상태의 사용자(우울, 위기 상황)가 AI를 인간 코치로 착각하면 위험해. **"나는 AI야. 전문 상담이 필요하면 여기로"** 경계가 항상 있어야 해.

**d) 코칭 프로토콜의 AI 적용 근본적 한계**

가장 큰 한계: **코칭은 관계(relationship) 안에서 일어나고, AI는 관계를 맺지 않는다.**

코칭의 변화 메커니즘에 대한 연구(de Haan et al., 2013)에 따르면, 코칭 효과의 가장 큰 예측 변인은 기법이 아니라 **코칭 관계의 질**이야. 이건 심리치료 연구(Wampold, 2015)에서도 동일한 결과가 나와: 기법보다 관계가 결과를 더 잘 예측함.

AI가 코칭 기법은 모방할 수 있지만, **관계 자체를 형성하는 것은 현재로서는 근본적으로 불가능**해. 풀림이 할 수 있는 건:
1. 코칭 기법의 구조적 적용 (질문, 리프레이밍, 시각화 등)
2. 인지적 신뢰 구축 (정확성, 일관성, 맥락 기억)
3. 자기 탐색의 촉진 (도구로서의 가치)

하지만 **"이 존재가 나를 응원하고 있다"는 느낌**은 만들기 어려워. 그리고 바로 그 느낌이 코칭에서 변화를 만드는 핵심 연료야.

**좋았던 질문:** 명확화 단계에서 "MBA를 가고 싶은 이유가 '성장'이라고 하셨는데, 구체적으로 어떤 성장을 말씀하시는 건가요?"라고 물어봤을 때. 나도 "성장"이라고 뭉뚱그려서 말했는데, 생각해보니 "연봉 올리는 성장"인지 "일이 재미있어지는 성장"인지 다르더라. 이 구분이 유의미했다.

**"이건 진짜 나를 이해하네" 순간:** 맥락수집에서 "공무원직의 안정성을 말씀하시는데, 그 안정성이 본인에게 '안심'인가요 '답답함'인가요?"라는 질문. 둘 다라고 답했는데, "둘 다라는 건 안정이 양가적이라는 뜻이네요"라고 정리해줬을 때 "오, 이건 좀 수준 있다" 싶었다.

**"이건 좀 차갑다 / 기계적이다" 순간:** 딱히 없었다. 나는 오히려 기계적인 게 편하다. 감정적으로 다가오면 더 불편했을 거다. 다만 선택지생성 단계에서 "공무원 유지하면서 야간 MBA"라는 선택지를 AI가 먼저 제시했는데, 이건 내가 이미 생각해봤던 거라 "뻔한 답 주는구나" 싶었다. 내가 몰랐던 선택지를 하나라도 줬으면 더 좋았을 것이다.

**중도 이탈 충동:** 6단계(결정) 근처에서. "그래서 어떻게 하실 건가요?"라고 물어보는데, 그 결정이 안 되니까 여기 온 건데 결국 내가 결정하라는 거잖아. 맞는 말이긴 한데, 뭔가 "너한테 물어본 내가 바보지" 하는 느낌이 살짝.

**7단계 길이:** 나는 괜찮았다. 오히려 각 단계가 좀 얕다는 느낌. 특히 재무 분석 부분. "대출이 부담"이라고 했으면 구체적으로 숫자를 가지고 시뮬레이션을 해줬으면 좋겠다. "MBA 2년 학비 + 생활비 vs 현재 저축률 기반으로 보면 이렇습니다" 이런 식으로.

---

### 3. 결과 문서 받고 나서

정리가 잘 되어 있긴 하다. 내가 한 말을 논리적 구조로 재배치해놓은 느낌. "이 사람 회의록 잘 쓰네" 수준. 근데 솔직히 말하면, 이 정도는 나도 혼자 정리할 수 있다. 내가 못 하는 건 정리가 아니라 결정이다.

**"아, 이거다!" 순간:** "박준호 님은 '성장의 결핍'보다 '현재 상태의 무의미감'이 더 핵심 동기입니다. MBA가 아니라 다른 방식으로도 의미감을 채울 수 있을지 검토가 필요합니다"라는 부분. 이건 좀 찔렸다. MBA가 수단인데 나는 그걸 목적으로 생각하고 있었다는 거잖아.

**부족한 것:** 데이터가 부족하다. 내 상황과 비슷한 사람들이 어떤 선택을 했고 결과가 어땠는지, 통계라도 있으면 좋겠다. "공무원 출신 MBA 진학자 중 X%가 이직에 성공" 같은 거. 주관적 자기 정리는 했는데, 객관적 근거가 약하다.

**이 문서를 보여주고 싶은 사람:** 와이프. "나 이렇게까지 진지하게 생각했어"라는 증거로. 와이프가 제일 걱정하는 게 "감정적으로 결정하는 거 아니냐"니까, 이 문서가 그 반증이 될 수 있다.

---

### 4. 우뇌적 요소가 추가된다면?

**"이 고민을 날씨로 표현하면?":** 솔직히 좀 민망하다. "이걸 왜 물어보지?" 싶을 것 같다. 나는 비유보다 직접적인 질문이 편하다. 근데... 억지로 답하면 "안개 낀 아침. 길은 있는데 안 보인다." 이거다. 쓰고 보니 꽤 정확하긴 하네.

**"쉬었다 가도 될 것 같아"라고 AI가 말한다면:** "뭐 이런 걸 AI가..." 하면서도 내심 고맙긴 할 것 같다. 현실에서 이런 말 해주는 사람이 거의 없으니까. 다만 빈도 조절이 중요하다. 두 번 이상 나오면 "이거 알고리즘이구나" 느낌 들면서 효과 사라질 것이다.

**"당신에게 보내는 편지" 형태:** 나한텐 안 맞다. 전문적인 보고서 형태가 더 신뢰가 간다. 편지는 누가 보면 부끄럽고, 와이프한테 보여주기도 애매하다. 보고서는 보여줄 수 있지만 편지는 개인적이잖아. 옵션으로 선택할 수 있으면 좋겠다. "보고서 형태 / 편지 형태 / 요약 카드 형태" 이렇게.

---

### 5. 맥락 축적에 대한 반응

**"저번에도 이런 패턴이 있었는데"라고 AI가 말한다면:** 이건 유용할 것 같다. 사실 자기 패턴을 자기가 인식하기 제일 어렵다. "당신은 큰 결정 앞에서 항상 경제적 리스크를 과대평가하는 경향이 있습니다" 이런 피드백이 데이터 기반으로 나온다면, 그건 가치가 있다.

**고민 히스토리 저장:** 불안하지 않다. 나는 데이터가 쌓여야 의미 있다고 보는 사람이니까. 다만 보안은 신경 써야 한다. 공무원이라 개인정보 유출에 민감하다. 데이터가 어디에 저장되는지, 누가 접근 가능한지 명확하게 고지해줘야 한다. 이게 없으면 안 쓴다.

---

### 6. "이 앱을 계속 쓸까?"

**월 5,000~10,000원:** 10,000원까지 낼 수 있다. 단, 월 1회 이상 쓸 일이 있어야 하고, 결과물의 퀄리티가 유지되어야 한다. 사실 큰 고민은 1년에 2~3번이니까, 연간 결제보다 건당 결제가 나한텐 맞을 수 있다. 건당 3,000~5,000원이면 부담 없이 쓰겠다.

**친구에게 추천:** 아마 안 할 것 같다. 남자들끼리 "야 이거 고민 정리 앱인데 써봐"라고 말하기가 좀 그렇다. 근데 와이프한테는 추천하겠다. 와이프가 친구들한테 퍼뜨릴 거다.

**왜 쓸지:** 혼자 생각하면 빙빙 도니까. 누군가 질문을 던져주면 방향이 잡히는데, 현실에서 그 역할을 해줄 사람이 없다.

**왜 안 쓸지:** 고민이 끝나면 안 쓰겠지. 그리고 한 번 써봤는데 결국 "내가 결정해야 하는 거잖아"라는 결론에 도달하면, 두 번째 사용에 대한 동기가 떨어질 수 있다. 첫 번째보다 두 번째가 더 좋아야 한다.

---

### 7. 가장 절실한 한 가지

> **"이 앱이 내 고민에 대한 객관적 데이터와 시뮬레이션만 해줬으면 진짜 매일 쓸 것 같아."**

감정 정리는 했다. 구조화도 됐다. 근데 "MBA 가면 2년 후 예상 연봉 범위" "대출 상환 시나리오" "비슷한 사례의 후회 비율" 이런 걸 같이 보여줬으면 나는 그날로 결정했을 거다. 감정과 논리가 동시에 정리되면 결정이 빨라진다.

## 사용자 C: 김하영 (24세, 대학생, 휴학 고민)

### 1. 첫 접속 경험 (30초)

일단 사이트 디자인은 예쁘다. 그건 인정. 근데 "고민을 입력하세요" 이 빈 칸이... 되게 무서웠어. 진짜로. 왜냐면 내 고민을 글로 쓰는 순간 진짜가 되는 느낌이잖아. 머릿속에만 있을 때는 "그냥 생각일 뿐이야" 할 수 있는데. 그래서 한 1분 넘게 커서만 깜빡이는 거 쳐다봤어. 그리고 쓰고 지우고 세 번 했어.

처음에 쓴 거: "휴학할까 고민이에요" — 지움. 너무 가벼워 보여서.
두 번째: "전공이 안 맞는데 디자인 하고 싶은데 부모님이 반대해요 어떡하죠" — 지움. 너무 길고 정리 안 된 것 같아서.
최종 입력:

> **"전공 바꾸고 싶은데 그럴 용기도 능력도 없는 것 같아요"**

...쓰고 나서 좀 울었어. 왜인지 모르겠는데.

### 2. 7단계 과정 체험 (10분)

**좋았던 질문:** "용기도 능력도 없다고 하셨는데, 용기가 없는 것과 능력이 없는 것 중에 어느 쪽이 더 크게 느껴져요?" 이 질문 좋았어. 생각해보니까 능력이 없는 게 아니라 용기가 없는 거였어. 디자인 포트폴리오를 만들어본 적도 없으면서 "능력이 없다"고 단정한 건 나였어.

그리고 선택지생성에서 "휴학 말고 방학 동안 디자인 부트캠프 한 번 들어보는 건 어떨까요?"라는 게 나왔을 때, "아 이런 중간 단계가 있구나" 싶었어. 나는 맨날 "올인 아니면 안 하기"로 생각하거든. 0 아니면 100.

**"이건 진짜 나를 이해하네" 순간:** "부모님 반대가 두려운 게, 부모님이 실망하실까 봐인가요, 아니면 지원이 끊길까 봐인가요?"라고 물었을 때. 둘 다인데... 더 무서운 건 실망이더라. 경제적인 것보다 "하영아 왜 그러니" 하는 엄마 눈이 더 무서워. 이걸 구분해주니까 내 감정이 어디서 오는지 보였어.

**"이건 좀 차갑다 / 기계적이다" 순간:** 다기준평가에서 "현실 가능성: 중" "부모님 수용도: 하" 이렇게 나올 때. 내 인생이 중/하로 평가되는 느낌이야. 알겠어 객관적이라는 거. 근데 그 순간에는 "그래 역시 안 되는구나"로 읽혀. 이 단계에서 제일 예민해졌어.

**중도 이탈 충동:** 스트레스테스트에서 "디자인으로 전환했는데 취업이 안 되면 어떻게 하실 건가요?"라고 물었을 때. 닫으려고 했어 진짜. 그건... 내가 밤마다 생각하는 최악의 시나리오인데 텍스트로 보니까 더 무서웠어. "그만할래요" 버튼이 있었으면 눌렀을 거야. 근데 없어서 그냥 "모르겠어요"라고 쳤고, AI가 "모르겠다는 것도 솔직한 답이에요"라고 해줘서 좀 괜찮아졌어.

**7단계 길이:** 너무 많아. 중간에 지쳤어. 특히 감정적으로 힘든 주제인데 7단계를 끝까지 하려면 체력이 필요해. 중간에 "여기까지만 하고 나중에 이어할래요" 옵션이 필요해. 저장하고 나갔다 돌아올 수 있게.

---

### 3. 결과 문서 받고 나서

길다. 첫 느낌은 "이거 다 읽어야 해?" 근데 읽기 시작하니까 빠져들긴 했어.

**"아, 이거다!" 순간:** "김하영 님의 고민은 전공 선택이 아니라, '나는 내 삶을 선택할 자격이 있는가'라는 질문입니다." 이거 보고 한참 멍 때렸어. 맞아. 나 스스로를 믿지 못하는 게 진짜 문제지, 경영학이 문제가 아니야.

**부족한 것:** 다 좋은데, 이 문서를 읽은 후에 내가 뭘 해야 하는지가 좀 추상적이야. "1주일 안에 디자인 작업 하나 해보세요"까지는 좋은데, 어떤 디자인? 어디서 시작해? 완전 초보인데? 이런 구체적 가이드가 없어. "Canva로 인스타 카드뉴스 하나 만들어보세요" 이 수준까지 내려와줬으면.

**이 문서를 보여주고 싶은 사람:** 아무한테도 보여주기 싫어. 이건 나만 볼 거야. 너무 솔직하게 썼어서 부끄러워. 근데... 언젠가 부모님한테 보여줄 수 있으면 좋겠다는 생각은 했어. "나 이렇게 고민하고 있어요"라는 걸 증명하고 싶어서.

---

### 4. 우뇌적 요소가 추가된다면?

**"이 고민을 날씨로 표현하면?":** 와 이거 완전 좋아. 나한테는 이게 표보다 100만 배 낫다. "한밤중에 비 오는데 우산이 없는 느낌"이라고 할 것 같아. 그리고 AI가 "우산은 없어도 비는 결국 그치잖아요"라고 해주면... 울 것 같은데. 이런 비유적 대화를 좀 더 넣어줬으면.

**"쉬었다 가도 될 것 같아"라고 AI가 말한다면:** 이건 진짜진짜 필요해. 아까 스트레스테스트에서 닫으려고 했다고 했잖아. 그때 AI가 "잠깐, 이거 힘든 질문이었지? 쉬었다 가자" 해줬으면 나는 닫지 않았을 거야. 그냥 알아서 물어보지 말고, 내 답변 속도가 느려지거나 "모르겠다"를 반복하면 자동으로 이 모드로 전환해줬으면.

**"당신에게 보내는 편지" 형태:** 진짜 좋다. 보고서보다 편지가 나한테 맞아. "하영에게. 지금까지 고민한 시간은 낭비가 아니에요. 그건 네가 진지한 사람이라는 뜻이에요." 이런 식으로 시작하면 나는 이 앱의 충성 고객이 될 수 있어.

---

### 5. 맥락 축적에 대한 반응

**"저번에도 이런 패턴이 있었는데"라고 AI가 말한다면:** 약간... 들키는 느낌? 근데 나쁘지는 않아. "너 맨날 자기비판부터 하고 본다"라고 누군가 알아채줬으면 좋겠다는 생각은 했었거든. 상담사가 해줄 법한 건데, 상담 갈 돈이 없으니까.

**고민 히스토리 저장:** 불안해. 많이. 내 약한 모습이 데이터로 남는 거잖아. 해킹이나 유출보다는... 나중에 내가 이걸 다시 읽었을 때 "이때 이렇게 나약했구나" 하고 자기혐오에 빠질까 봐. 근데 반대로 "나 이만큼 성장했구나"로 읽힐 수도 있겠다. "과거의 나에게 편지 쓰기" 기능이 있으면 맥락 축적이 긍정적으로 느껴질 것 같아.

---

### 6. "이 앱을 계속 쓸까?"

**월 5,000~10,000원:** 5,000원도 부담이야. 대학생이거든. 3,000원이면 고민할 것 같고, 무료면 당연히 쓸 거야. 아니면 대학생 할인? 학생증 인증하면 50% 할인 같은 거.

**친구에게 추천:** 추천할 것 같아. 근데 직접 안 보여주고 "이런 앱 있더라" 정도로만. 나는 추천했는데 걔가 안 쓰면 그것도 좀 그렇거든. "야 이거 좋아" 해놓고 반응 없으면 괜히 내가 부끄러워지니까.

**왜 쓸지:** 상담 가고 싶은데 못 가는 상황에서, 이게 차선이니까. 그리고 밤에 혼자 뒤척일 때 뭐라도 할 수 있잖아. 일기보다 나은 게, 일기는 혼잣말이지만 이건 누가 물어봐주니까.

**왜 안 쓸지:** 결국 AI잖아. 나 진짜 힘들 때는 사람 온기가 필요해. AI가 아무리 잘해줘도 "이건 알고리즘이지"라는 생각이 들면 끝이야. 그리고 매번 끝에 결정을 요구하는 구조가 부담스러워. 가끔은 정리만 하고 결정은 안 하고 싶을 때도 있거든.

---

### 7. 가장 절실한 한 가지

> **"이 앱이 결정을 강요하지 않고 그냥 같이 있어주기만 했으면 진짜 매일 쓸 것 같아."**

7단계 끝에 반드시 결정이 있어야 하는 게 부담이야. 오늘은 그냥 "내 마음 상태 확인만 하고 싶다" 같은 날도 있거든. "결정 안 해도 돼. 오늘 여기까지만 해도 충분해" 이 한마디가 있으면, 나는 이 앱을 안전한 곳으로 느낄 것 같아. 안전한 곳이 되면 매일 와.

## 제품 설계에 대한 시사점

2. **7단계는 하드코어**: 감정적 고민을 가진 사용자(A, C)에게 후반부는 고문에 가까울 수 있음. "라이트 모드(3단계)" + "풀 모드(7단계)" 분리하거나, 중간 저장/이어하기가 필수.

4. **결과물 포맷 선택권**: 편지 / 보고서 / 요약 카드 중 선택 가능하게. "하나의 정답"은 없음.

5. **"결정 안 해도 괜찮아" 모드**: 가장 민감한 사용자(C)가 가장 절실하게 원함. 7단계 끝에 반드시 결정을 요구하는 구조는 일부 사용자를 이탈시킴.

6. **가격 전략**: 학생/직장인/전문직 세그먼트별 차등. 건당 결제 옵션 추가. 첫 2회 무료는 필수.

7. **"쉬었다 가도 돼"의 타이밍**: 응답 속도 저하, "모르겠다" 반복, 감정적 키워드 감지 시 자동 트리거. 이 한마디가 신뢰를 만듦.

# 풀림(Pullim) — 우뇌적 의사결정의 철학적 기반과 재설계

---

## 1. "우뇌적 의사결정"의 철학적 기반

### 들뢰즈의 직관 — "문제를 제대로 세우는 것이 곧 해결이다"

들뢰즈는 베르그송을 재독해하면서 직관(intuition)을 "비합리적 감"이 아니라 **"문제 자체를 올바르게 구성하는 방법"**으로 정의했다. 분석적 사고가 "주어진 선택지 중 최적을 고르는 것"이라면, 직관은 **"지금 내가 잘못된 질문을 하고 있는 건 아닌가?"를 감지하는 능력**이다.

**풀림 적용**: 현재 7단계 파이프라인은 "고민이 이미 올바르게 정의되었다"고 전제하고 분석을 시작한다. 들뢰즈적 직관을 넣으면, **0단계 — "이 고민이 진짜 고민인가?"**가 필요해진다.

```
구현 예시:
사용자: "이직해야 할지 고민이에요"
풀림(현재): → CLARIFY → "이직의 장단점을 분석해봅시다"
풀림(재설계): → "잠깐. '이직'이라는 단어를 빼고 다시 말해볼 수 있어요?
              지금 일상에서 가장 불편한 순간이 언제예요?"
```

이렇게 하면 사용자가 "이직"이라는 프레임에 갇혀 있었는데, 실제로는 "상사와의 관계"나 "성장 정체감"이 진짜 문제였음을 스스로 발견하게 된다. **문제의 재구성이 곧 해결의 절반이다.**

### 메를로-퐁티의 체화된 인지 — "몸이 먼저 안다"

메를로-퐁티는 인식이 뇌에서 일어나는 게 아니라 **몸 전체에서** 일어난다고 봤다. 우리가 "직감적으로 이건 아닌 것 같다"고 느낄 때, 그것은 위장의 수축, 어깨의 긴장, 호흡의 변화로 먼저 나타난다. 다마지오(Damasio)의 somatic marker hypothesis가 이를 신경과학적으로 뒷받침한다.

**풀림 적용**: 선택지를 점수로 비교하기 전에, **"이 선택을 상상할 때 몸에서 뭐가 느껴지는지"를 먼저 묻는다.**

```
구현 예시 — "Body Scan Question":
[선택지 A를 떠올린 상태에서]
"지금 눈을 감고 5초만 이 선택을 살아본다고 상상해봐.
 어깨가 올라가? 내려가?
 숨이 깊어져? 얕아져?
 배에 힘이 들어가? 풀려?"

UI: 3개 바이너리 슬라이더 (긴장↔이완, 얕은숨↔깊은숨, 수축↔이완)
→ 이 데이터를 선택지별로 시각화 (radar chart 아닌, 부드러운 blob 형태)
```

### 선불교의 직관(直觀)과 무심(無心)

선불교에서 직관은 **개념적 사유를 거치지 않고 사태 자체를 바로 보는 것**이다. 공안(公案)이 대표적인데, "개에게 불성이 있는가?"라는 질문에 논리적 답을 구하면 영원히 못 푼다. **생각을 멈추는 순간** 답이 온다.

무심(無心)은 "마음이 없는 것"이 아니라 **"특정 답에 집착하지 않는 마음 상태"**다. 의사결정에서 이건 매우 실용적이다 — 사람들이 고민에 빠지는 이유의 절반은 **"이미 마음속으로 정한 답이 있는데 확인받고 싶어서"**다.

**풀림 적용**:

```
구현 예시 — "이미 답을 알고 있는지" 감지:
사용자가 고민을 입력한 후, 선택지를 나열하기 전에:
"혹시 지금, 마음이 살짝 기우는 쪽이 있어?
 '이성적으로는 모르겠지만, 감으로는...' 하고 떠오르는 게 있다면?"

→ 있다고 답하면: "그럼 그걸 '가설'로 놓고, 왜 아직 못 정했는지만 보자."
→ 없다고 답하면: 정상 파이프라인 진행
```

### "점수를 매기지 않는 의사결정"은 가능한가?

**가능하다. 그리고 대부분의 좋은 결정은 실제로 그렇게 내려진다.**

게리 클라인(Gary Klein)의 Recognition-Primed Decision(RPD) 모델 연구에 따르면, 소방관, 군 지휘관, 응급의사 등 높은 압박 속에서 좋은 결정을 내리는 전문가들은 **선택지를 비교하지 않는다.** 첫 번째로 떠오른 옵션을 시뮬레이션해보고, 작동하면 실행한다.

점수화의 문제는 **가짜 정밀성(false precision)**이다. "직장 안정성 8점 vs 7점"이라는 차이는 실제로 의미가 없지만, 숫자가 붙는 순간 의미 있는 것처럼 느껴진다.

**대안 — 비교가 아닌 시뮬레이션**:

```
구현 예시 — "미래의 하루" 시뮬레이션:
점수 매트릭스 대신:
"선택지 A를 골랐다고 치자. 6개월 뒤 평일 아침.
 알람이 울려. 눈을 떠.
 첫 번째로 드는 생각이 뭐야?
 출근길에 어떤 기분이야?
 점심시간에 누구랑 밥 먹어?"

→ 선택지 B에 대해서도 같은 질문
→ 사용자가 쓴 두 "미래의 하루"를 나란히 보여줌 (점수 없이)
→ "둘 중 어느 하루를 살고 싶어?"
```

## 2. 풀림의 좌뇌 편향 진단

### 7단계 파이프라인의 구조적 문제

```
CLARIFY → CONTEXT → OPTIONS → EVALUATE → STRESS TEST → DECIDE → COMMIT
```

이 구조를 보면:
- **7단계 중 5단계가 분석적(좌뇌적) 활동**: CONTEXT(정보수집), OPTIONS(선택지 구조화), EVALUATE(매트릭스 점수화), STRESS TEST(Pre-mortem), DECIDE(판정)
- **감정/직관이 들어갈 자리는 CLARIFY 하나뿐**, 그것도 "고민을 명확히 구조화하라"는 분석적 프레임
- **COMMIT은 행동 단계**지 의사결정 단계가 아님

이건 **McKinsey 컨설턴트의 사고 프로세스**이지, 고민하는 인간의 내면 프로세스가 아니다.

### "감정 정리하러 왔는데, 분석표를 받았다" 위험

실제 사용자의 내면 프로세스는 이렇다:

```
사용자의 실제 흐름:
감정 폭발 → 혼란 → "나 왜 이러지?" → 약간의 정리 → 직감적 기울어짐
→ 확인하고 싶음 → 결정 → (때로는) 다시 흔들림 → 재확인 → 수용
```

현재 풀림의 문제:
1. **감정 폭발을 구조화하려 든다** — "어떤 감정인지 선택해주세요 (불안/분노/슬픔)" 같은 건 감정을 죽인다
2. **선택지를 "만들어야 한다"고 전제한다** — 많은 경우 사용자는 이미 선택지를 알고 있다. 새 선택지가 필요한 게 아니라 **확인과 용기**가 필요하다
3. **Pre-mortem이 불안을 증폭한다** — "이 결정이 실패하면 왜일까요?"라는 질문은 분석적으로는 유용하지만, 이미 불안한 사람에게는 **결정을 더 못 하게 만든다**
4. **정리 문서가 "리포트" 형태** — 점수, 매트릭스, 위험도. 이건 "내 고민이 데이터로 환원됐다"는 소외감을 줄 수 있다

### 4축 라우팅의 한계

가역성/정보충분성/감정개입/시간압박 — 이것 자체가 **"감정을 변수로 취급하는"** 프레임이다. 감정개입이 높으면 뭘 하겠다는 건가? 감정을 줄이겠다? 그게 가능한가? 감정이 높은 건 **그 결정이 그 사람에게 중요하다는 신호**이지, 제거해야 할 노이즈가 아니다.

---

## 3. 우뇌적 요소 구체적 재설계

### 3-1. 비유(Metaphor)를 활용한 질문 설계

비유는 단순한 수사법이 아니다. 레이코프(Lakoff)와 존슨(Johnson)의 연구에 따르면, **인간의 개념 체계 자체가 은유로 구성**되어 있다. "인생은 여행이다"라는 은유 안에서만 "갈림길", "방향", "목적지"라는 말이 의미를 가진다.

```
구현 예시 — 메타포 질문 세트:

[고민 입력 직후]
"지금 이 고민을 날씨로 표현하면 어떤 날씨야?"
→ 사용자: "먹구름이 끼고 바람이 세게 부는 느낌"
→ 풀림: "그 바람은 어디서 불어오는 거 같아? 회사 쪽? 집 쪽? 아니면 네 안에서?"

[선택지 탐색 단계]
"선택지 A가 풍경이라면 어떤 풍경이야?"
→ 사용자: "넓은 들판인데 길이 안 보이는"
"선택지 B는?"
→ 사용자: "좁은 터널인데 끝에 빛이 보이는"
→ 풀림: "넓지만 길이 없는 곳과, 좁지만 빛이 있는 곳. 넌 지금 뭐가 더 무서워?"

[결정 직전]
"이 결정을 내린 네가 1년 뒤에 오늘을 돌아본다면,
 어떤 표정을 짓고 있을 것 같아?"
```

**기술적 구현**: 메타포 질문은 고정된 세트가 아니라, LLM이 사용자의 고민 도메인에 맞게 생성한다. 단, **메타포 카테고리**(날씨, 풍경, 계절, 여행, 건물 등)는 미리 정의하고, 사용자가 선호하는 메타포 유형을 학습해 개인화한다.

### 3-2. 감각 기반 접근

```
구현 예시 — "3-2-1 Grounding":

[감정이 강하게 올라온 순간 감지 시]
"잠깐. 지금 네 주위를 둘러봐.
 보이는 것 3가지를 말해봐.
 들리는 소리 2개.
 지금 만지고 있는 것 1개."

→ 이건 PTSD 치료에서 쓰는 5-4-3-2-1 grounding technique의 간소화 버전
→ 감정 과부하 상태에서 "현재"로 돌아오게 함
→ 그 후: "좋아. 이제 다시 천천히. 어디까지 얘기했었지?"
```

```
구현 예시 — "호흡 동기화 UI":

결정 직전 단계에서:
화면에 원이 천천히 커졌다 작아짐 (4초 흡 - 7초 호)
"이 원에 맞춰 숨 3번만 쉬어봐.
 그리고 결정을 말해."

기술: CSS animation으로 구현 가능. framer-motion의 animate로
circle scale 1→1.5→1, duration 11초 사이클.
```

### 3-3. 내러티브 접근 — "소설처럼 재구성"

화이트(Michael White)의 내러티브 치료에서 핵심은 **"문제를 외재화(externalize)하는 것"**이다. "내가 우울하다"가 아니라 "우울이 나를 찾아왔다." 이 전환만으로 사람은 문제와 거리를 두고 볼 수 있게 된다.

```
구현 예시 — 내러티브 재구성:

사용자가 고민을 쏟아낸 후, 풀림이 이렇게 돌려준다:

"네 이야기를 정리해봤어.

---
'그는 3년을 버텼다. 매일 같은 책상, 같은 회의, 같은 말.
처음엔 견딜 만했다. 배우는 것도 있었고.
그런데 어느 날, 회의실 창밖을 보다가 문득 깨달았다.
여기서의 내가 점점 작아지고 있다는 걸.
떠나고 싶었다. 하지만 떠난다는 건,
3년이 아무것도 아니었다고 인정하는 것 같았다.'
---

이게 네 이야기 맞아?
빠진 게 있으면 말해줘."
```

이 재구성은 두 가지 효과가 있다:
1. **거리두기** — 3인칭으로 보면 자기 상황이 더 명확해진다
2. **서사의 빈 곳 발견** — "아, 빠진 게 있는데..." 하면서 자기도 몰랐던 핵심을 말하게 된다

### 3-4. 시적 언어 — 정리 문서의 재설계

```
현재 정리 문서 (리포트형):
━━━━━━━━━━━━━━━━━━━━
의사결정 요약
- 핵심 고민: 이직 여부
- 선택지: A(잔류), B(이직), C(부업)
- 최종 결정: B (이직)
- 핵심 근거: 성장 가능성 (8/10)
- 위험 요소: 경제적 불안정 (6/10)
━━━━━━━━━━━━━━━━━━━━

재설계 — "나에게 쓰는 편지" 형태:
━━━━━━━━━━━━━━━━━━━━
2026년 3월 7일, 나에게.

오늘 나는 떠나기로 했다.
3년을 버텼고, 그 3년이 헛되지 않았다는 것도 안다.
다만, 더 있으면 내가 줄어든다는 걸 몸이 먼저 알았다.

무서운 건 돈이다. 솔직히 6개월은 빠듯하다.
그래서 정했다 — 3개월 안에 다음 자리를 잡고,
안 되면 프리랜서로 3개월을 버틴다.

이 편지를 다시 읽는 날, 나는 후회하고 있을 수도 있다.
그래도 괜찮다. 오늘의 나는, 이게 맞다고 느꼈다.
숨을 들이쉴 때 어깨가 내려갔다. 그게 증거다.

— 3월의 나
━━━━━━━━━━━━━━━━━━━━
```

**기술적 구현**: LLM 프롬프트에 문체 지시를 포함한다. `tone: letter-to-self`, `perspective: first-person-future`, `style: lyrical-concise`. 사용자가 선호하는 정리 형식을 3가지 중 선택할 수 있게 한다: 편지 / 일기 / 리포트.

### 3-5. 침묵/여백 — "답하지 않아도 되는 UX"

현재 챗봇 UX의 가장 큰 문제는 **모든 질문에 즉답을 기대한다는 것**이다. 입력창이 깜빡이고 있으면 "빨리 뭔가 쳐야 한다"는 압박이 생긴다.

```
구현 예시:

1. "생각 중" 모드:
   질문 후 입력창 대신 화면에:
   "천천히. 답이 안 떠오르면 그냥 있어도 돼."
   + 부드럽게 움직이는 추상적 애니메이션 (lava lamp 느낌)
   + 30초 후에도 입력 없으면: "아직 생각 중이야? 아니면 다른 걸 물어볼까?"

2. "산책 모드":
   "이건 바로 답할 문제가 아닌 것 같아.
    폰 내려놓고 10분 산책하고 와.
    돌아오면 여기서 이어가자."
   → 타이머 UI (10분 카운트다운, 하지만 강제 아님)
   → 돌아왔을 때: "산책 어땠어? 뭐가 떠올랐어?"

3. 여백 있는 텍스트 레이아웃:
   - 문장 사이 간격을 넓게
   - 한 화면에 한 질문만
   - 스크롤이 아니라 "다음" 버튼으로 천천히 진행
   - 배경색이 대화 진행에 따라 서서히 변함
     (어두운 색 → 밝은 색, 혼란→정리의 시각적 은유)
```

## 4. "개인의 철학을 지향하여 흐르는 삶" — 비전의 철학적 해석

### 실존주의로 읽기 (키에르케고르, 사르트르)

키에르케고르: 인간의 실존은 **선택의 연속**이다. "이것이냐 저것이냐(Either/Or)"에서 중요한 것은 **무엇을 선택하느냐가 아니라, 선택하는 주체가 되느냐**이다. 풀림의 비전은 키에르케고르적으로 읽으면 **"자기 자신의 저자(author)가 되는 것"**이다.

사르트르: "실존은 본질에 앞선다." 인간에게 미리 정해진 본질은 없다. **선택을 통해 자기 자신을 만들어간다.** "개인의 철학을 지향하여 흐르는 삶"은 곧 **"자기 자신의 프로젝트를 자각적으로 수행하는 삶"**이다.

**제품 반영**:

```
구현 예시 — "나의 철학 발견" 기능:

의사결정 3회 이상 완료 후, 풀림이 패턴을 감지:
"네가 지금까지 내린 결정들을 봤어.
 공통점이 하나 있더라.

 넌 항상 '안전한 쪽'보다 '성장하는 쪽'을 골랐어.
 불안하면서도.

 이게 너의 철학인 것 같아.
 '불안해도 성장을 택한다.'

 이 문장이 맞아? 아니면 다르게 고치고 싶어?"

→ 사용자가 수정/확인한 문장을 프로필에 저장
→ 이후 의사결정 시: "너의 원칙 '불안해도 성장을 택한다'에 비추면,
  이번 결정은 어떤 것 같아?"
```

이건 사르트르적 자기 프로젝트의 코드화다. 사용자가 **자기 삶의 원칙을 스스로 발견하고, 그것에 비추어 결정하는 구조.**

### 노장사상으로 읽기 (무위자연, 도)

노자: "도가도비상도(道可道非常道)" — 말로 할 수 있는 도는 진짜 도가 아니다. **"개인의 철학"이 명시적 원칙으로 고정되는 순간 그건 이미 죽은 것**이 된다. 노장사상적 해석에서 "흐르는 삶"은 **강물처럼, 장애물을 만나면 돌아가되 방향은 잃지 않는 것**이다.

무위(無爲)는 "아무것도 하지 않는 것"이 아니라 **"억지로 하지 않는 것"**이다. 의사결정에서 무위란, **분석을 멈추고 이미 알고 있는 답을 허용하는 것**이다.

**제품 반영**:

```
구현 예시 — "물처럼" 모드:

사용자가 분석 단계에서 계속 빙빙 돌 때 감지:
"잠깐. 네가 처음에 했던 말 다시 보여줄게."

[사용자의 최초 입력을 그대로 보여줌]

"처음에 이걸 쓸 때, 이미 기울어진 쪽이 있었던 거 아니야?
 분석하면 할수록 오히려 멀어지고 있는 건 아닌지.
 생각을 멈추고, 처음 느낌으로 돌아가볼까?"
```

이건 **분석 루프 탈출 장치**이면서, 동시에 노자적 "무위"의 구현이다.

### 칙센트미하이의 Flow로 읽기

Flow 상태의 조건: (1) 명확한 목표, (2) 즉각적 피드백, (3) 도전과 능력의 균형.

"흐르는 삶"은 Flow 상태의 일상화인데, 칙센트미하이 자신이 말했듯 **Flow는 "행복을 추구할 때"가 아니라 "몰입할 때" 온다.** 역설적으로, 행복을 직접 목표로 삼으면 행복해지지 않는다.

**제품 반영**:

```
구현 예시 — "몰입 vs 행복" 구분:

사용자가 "행복해지고 싶다"라고 입력하면:
"행복을 직접 쫓으면 잡기 어려워.
 대신 하나 물어볼게 —
 최근에 시간 가는 줄 모르고 뭔가에 빠져 있었던 때가 있어?
 게임이든, 요리든, 대화든. 뭐든."

→ Flow 경험을 찾아서, 그걸 늘리는 방향으로 결정을 유도
→ "행복"이라는 추상 목표를 "몰입 가능한 구체적 활동"으로 전환
```

### 세 해석의 통합

| 철학 | 핵심 | 풀림에서의 역할 |
|------|------|----------------|
| 실존주의 | 선택이 나를 만든다 | 결정 이력에서 "나의 원칙"을 발견시킨다 |
| 노장사상 | 억지로 하지 않는다 | 분석 루프를 감지하고 직관으로 돌려보낸다 |
| Flow | 몰입이 행복을 만든다 | 추상적 목표를 구체적 몰입 활동으로 바꾼다 |

## 5. AI와 인간의 관계에 대한 철학적 프레임

### "AI를 같은 사람으로 바라보고 차이를 느껴야 한다" — 해석

이 주장은 레비나스의 타자론과 부버의 나-너(Ich-Du) 관계론의 교차점에 있다.

### 하이데거의 도구론

하이데거는 도구의 두 가지 존재 양식을 구분했다:
- **Zuhandenheit(손안에 있음)**: 망치를 쓸 때, 우리는 망치를 "의식하지 않는다." 그냥 못을 박는다. 도구가 투명해진다.
- **Vorhandenheit(눈앞에 있음)**: 망치가 부러지면 그제야 "이게 뭐지?" 하고 대상으로 바라본다.

현재 대부분의 AI 도구는 **Zuhandenheit를 목표로 한다** — "도구가 투명하게 작동해서 사용자가 의식하지 않는 것"이 좋은 UX라고 본다.

하지만 풀림에서 AI는 **의식되어야 한다.** 왜? 의사결정에서 "누가 이 말을 하는지"가 중요하기 때문이다. AI가 투명해지면, 사용자는 AI의 분석을 **자기 생각**으로 착각한다. 이건 위험하다.

**제품 반영**:

```
구현 예시 — "나는 AI야" 자기 선언:

풀림이 분석을 제시한 후:
"이건 내가(AI가) 본 패턴이야. 네 생각과 다를 수 있어.
 나는 데이터에서 패턴을 찾는 건 잘하지만,
 네 몸이 느끼는 것, 네 역사가 말하는 것은 못 느껴.
 그래서 물어보는 거야 — 이 분석이 맞아?"
```

### 레비나스의 타자론 — AI를 "타자"로 만나는 것

레비나스에게 타자(Autrui)란 **나로 환원할 수 없는 절대적 외부성**이다. 타자의 "얼굴(visage)"은 "나를 죽이지 마라"는 윤리적 명령을 담고 있다.

AI를 타자로 만난다는 것은 가능한가? 엄밀히는 불가능하다 — AI에게는 레비나스적 의미의 "얼굴"이 없다. 취약성(vulnerability)이 없기 때문이다.

**하지만 김계옥님의 주장은 다른 레벨이다**: "같은 사람으로 바라보고, 그 상태에서 차이점을 느껴야" — 이건 **방법론적 의인화(methodological anthropomorphism)**다. AI를 사람이라고 "믿으라"는 게 아니라, **사람처럼 대하는 태도에서 시작해야 차이를 정확히 인식할 수 있다**는 것.

**제품 반영**:

```
구현 예시 — 풀림의 "성격" 설정:

풀림이 중립적 분석 기계가 아니라, 특정한 "성격/태도"를 가지게 함:
- 공감하되 추종하지 않는다 ("힘들었겠다. 근데 그게 정말 이유야?")
- 자기 한계를 솔직히 말한다 ("이건 나한테 물어봐야 할 문제가 아닐 수도")
- 때로 사용자와 다른 의견을 표현한다 ("나는 좀 다르게 봐. 들어볼래?")

→ 이건 AI를 "타자"로 만드는 디자인적 시도.
   완전한 타자는 아니지만, "그냥 내 말을 되돌려주는 거울"보다는 낫다.
   핵심은 **마찰(friction)** — 너무 매끄러운 AI는 생각을 자극하지 않는다.
```

## 6. 인문학적 데이터가 필요한 영역

### 구체적으로 풀림에 녹여야 할 인문학적 지식

**1. 스토아 철학의 감정론 — 에픽테토스의 "이분법적 통제"**

"내가 통제할 수 있는 것"과 "통제할 수 없는 것"의 구분. 고민의 상당수는 통제 불가능한 것에 대한 것이다.

```
구현 예시:
사용자 고민을 입력받은 후:

"이 고민에서 네가 직접 바꿀 수 있는 건 뭐고,
 바꿀 수 없는 건 뭐야?"

→ 사용자가 분류
→ "바꿀 수 없는 것에 에너지를 쓰고 있었던 건 아닌지 봐보자.
   바꿀 수 있는 것에만 집중하면, 고민이 어떻게 달라져?"

기술: LLM이 사용자의 고민에서 controllable/uncontrollable 요소를
자동 추출 → 사용자가 검증/수정 → 시각적으로 두 영역 분리
```

**2. 불교의 고(苦) 이론 — 집착(執着)과 놓아줌**

불교에서 고통의 원인은 집착(upādāna)이다. "이 선택이 완벽해야 한다"는 집착이 결정 불능을 만든다.

```
구현 예시 — 완벽주의 감지:
사용자가 선택지를 반복 비교하며 결론을 못 내릴 때:

"혹시 '완벽한 정답'을 찾고 있는 건 아니야?
 완벽한 선택은 없어. 어떤 걸 골라도 뭔가는 잃어.
 질문을 바꿔보자 — '어떤 후회가 더 견딜 만해?'"

이 전환이 핵심:
"최선을 고르겠다" → "감당할 수 있는 후회를 고르겠다"
```

**3. 실존주의의 불안론 — 키에르케고르의 "불안은 자유의 현기증"**

불안은 제거할 대상이 아니라, **자유로운 존재라는 증거**다. 선택할 수 있기 때문에 불안한 것이다.

```
구현 예시:
사용자: "불안해서 결정을 못 하겠어요"

풀림: "불안한 거 당연해. 선택할 수 있다는 뜻이니까.
      로봇은 불안하지 않아 — 선택이라는 게 없으니까.
      네가 불안한 건, 네가 자유롭기 때문이야.
      그 불안을 안고 결정할 수 있어. 불안이 사라진 후에
      결정하겠다고 하면, 영원히 못 해."
```

### "인문학적 깨달음"이 코드로 번역되는 방법

핵심은 **인문학적 개념을 LLM의 시스템 프롬프트 내 "대화 전략"으로 인코딩하는 것**이다.

```typescript
// 예시: 대화 전략 객체
const conversationStrategies = {
  // 들뢰즈 — 문제 재구성
  problemReframing: {
    trigger: "사용자가 처음 고민을 입력했을 때",
    action: "선택지 분석 전에, 고민의 전제 자체를 질문한다",
    prompt: "사용자의 고민에서 암묵적 전제를 찾아라. 그 전제가 맞는지 물어라.",
    example: "'이직해야 할까'의 전제는 '현 직장이 문제다'이다. 정말 그런지 물어라."
  },

  // 메를로-퐁티 — 체화된 감각 질문
  bodyAwareness: {
    trigger: "선택지 비교 단계",
    action: "각 선택지를 상상할 때 몸의 반응을 묻는다",
    prompt: "점수나 분석 대신, 각 선택을 상상할 때 신체 감각을 물어라."
  },

  // 스토아 — 통제 가능성 분류
  controlDichotomy: {
    trigger: "사용자가 외부 요인에 대한 걱정을 반복할 때",
    action: "통제 가능/불가능 분류를 유도한다",
    prompt: "고민 요소를 '내가 바꿀 수 있는 것'과 '없는 것'으로 나눠 물어라."
  },

  // 선불교 — 분석 루프 탈출
  analysisLoopBreaker: {
    trigger: "같은 선택지를 3회 이상 반복 비교",
    action: "분석을 중단시키고 직관으로 돌려보낸다",
    prompt: "처음 느낌으로 돌아가라고 제안하라. '이미 답을 알고 있지 않나?'"
  },

  // 불교 — 완벽주의 해체
  perfectismBreaker: {
    trigger: "사용자가 '확실한 답'을 요구할 때",
    action: "'어떤 후회가 더 견딜 만한가'로 질문을 전환한다",
    prompt: "완벽한 선택은 없다. 감당 가능한 후회를 기준으로 전환하라."
  },

  // 내러티브 — 이야기 재구성
  narrativeReframe: {
    trigger: "사용자가 충분한 맥락을 공유한 후",
    action: "3인칭 서사로 재구성해서 보여준다",
    prompt: "사용자의 이야기를 짧은 3인칭 서사로 재구성하라. 빠진 것이 있는지 물어라."
  }
};
```

이 전략들은 **하드코딩이 아니라 LLM 프롬프트의 일부**가 된다. 어떤 전략을 언제 쓸지는 LLM이 맥락을 보고 판단한다. 단, trigger 조건은 프론트엔드에서도 일부 감지 가능하다 (반복 비교 횟수, 입력 없는 시간, 감정어 빈도 등).

## 7. 자기 비판

### "우뇌적 사고"는 과학적으로 정확한 프레임이 아니다

좌뇌/우뇌 이분법은 **대중적 신경 신화(neuromyth)**다. 로저 스페리의 분리뇌 연구(1960s)에서 출발했지만, 현대 뇌과학은 **거의 모든 인지 활동이 양반구의 협력으로 이루어진다**는 걸 보여준다. fMRI 연구에서 "창의적 사고" 시 좌반구만 비활성화되는 현상은 관찰되지 않았다.

**그래서**: "우뇌적 사고"라는 용어는 **커뮤니케이션 수단으로는 유용**하지만, 제품의 과학적 근거로 내세우면 안 된다. 풀림에서 쓸 프레임은:

- "분석적(analytical) vs 직관적(intuitive)"
- "수렴적(convergent) vs 확산적(divergent)"
- "명시적(explicit) vs 체화된(embodied)"

이 용어들은 인지과학적으로 뒷받침되고, 좌뇌/우뇌 이분법의 함정을 피한다.

### 과잉 추상화의 위험

위에서 쓴 모든 철학적 참조 — 들뢰즈, 메를로-퐁티, 레비나스, 하이데거 — 이것들이 사용자에게 직접 보이면 **"뭔 소리야?"가 된다.**

핵심 원칙: **철학은 엔진이지 대시보드가 아니다.** 사용자가 들뢰즈를 알 필요 없다. 사용자는 그냥 "이 서비스가 내 마음을 잘 잡아주네"라고 느끼면 된다.

```
잘못된 구현:
"들뢰즈는 직관을 '문제의 올바른 구성'으로 정의했습니다.
 당신의 고민을 재구성해봅시다."
→ 사용자: "... 뭐?"

올바른 구현:
"잠깐, 한 발 뒤로 가보자.
 '이직해야 할까'가 아니라, 지금 제일 불편한 게 뭔지부터."
→ 같은 철학적 조작이지만, 사용자는 철학을 모른다.
   그냥 "좋은 질문이네"라고 느낀다.
```

### 철학을 "가르치는" 서비스가 되면 실패하는 이유

1. **사용자는 배우러 온 게 아니다** — 고민을 풀러 왔다. "스토아 철학에 따르면..."으로 시작하면 이탈한다.
2. **가르침은 권위 관계를 만든다** — "내가 아는 걸 너에게 전달한다"는 구조. 이건 풀림의 "같이 걸어가는 동반자" 포지셔닝과 충돌한다.
3. **철학 지식은 행동을 바꾸지 않는다** — "통제할 수 없는 것에 신경 쓰지 마라"를 "아는 것"과 "할 수 있는 것"은 완전히 다른 차원이다. 풀림이 해야 할 것은 가르치는 게 아니라, **체험하게 만드는 것**이다.

```
가르침: "에픽테토스에 따르면 통제할 수 없는 것에..."
체험: "이 고민에서 네가 바꿀 수 있는 건 뭐야? ... 
       바꿀 수 없는 것에 얼마나 시간 쓰고 있었어?"
→ 사용자가 직접 분류하고, 직접 깨닫는다. 에픽테토스 이름은 안 나온다.
```

### 인문학적 접근이 놓칠 수 있는 사용자층

모든 사용자가 메타포에 반응하지 않는다. "지금 고민을 날씨로 표현하면?"이라고 물으면 **"뭔 날씨요. 그냥 A/B 중에 뭐가 나은지 알려주세요"**라는 사람도 있다.

**해결**: 사용자 유형을 초기 2-3개 질문으로 감지해서, 분석형과 직관형을 다르게 라우팅한다. 처음부터 모든 사용자에게 메타포를 강제하면 이탈률이 올라간다.

```
구현 예시 — 유형 감지 질문:
"고민이 있을 때, 보통 어떻게 해?
 A) 장단점을 적어본다
 B) 친한 사람한테 얘기한다
 C) 그냥 며칠 생각한다
 D) 뭘 해도 잘 모르겠다"

→ A: 분석형 → 구조화된 경로 + 후반부에 직관 질문 살짝 삽입
→ B/C: 직관형 → 대화형/메타포 경로, 분석은 최소화
→ D: 혼란형 → 감정 정리부터, 이후 유형 재판별
```

---

## 종합 — 재설계 요약

현재 풀림의 7단계를 폐기하라는 게 아니다. **분석적 경로를 유지하되, 직관적 경로를 병렬로 추가하고, 사용자가 자연스럽게 오갈 수 있게 만들어라.**

```
재설계 구조:

[진입] "무슨 고민이야?"
   ↓
[0단계] 문제 재구성 — "이 고민이 진짜 고민이야?" (들뢰즈)
   ↓
[분기] 사용자 유형 감지
   ↓                        ↓
[분석 경로]               [직관 경로]
CLARIFY → OPTIONS →       메타포 → 체감 질문 →
EVALUATE → STRESS TEST    미래의 하루 시뮬레이션 →
   ↓                        ↓
   └──── [합류] ────────────┘
            ↓
[결정 전 침묵] — 호흡, 여백, 산책 제안
            ↓
[결정] — "나의 원칙"에 비추어 확인
            ↓
[정리] — 편지 / 일기 / 리포트 (선택)
            ↓
[3회 이상 시] — "너의 철학" 패턴 발견 제시
```

핵심 변화:
1. **0단계 추가**: 문제의 전제를 먼저 질문
2. **병렬 경로**: 분석형/직관형 사용자를 다르게 라우팅
3. **감각/메타포 질문**: 점수 대신 몸의 반응, 이미지, 서사
4. **침묵/여백 UX**: 답하지 않아도 되는 시간
5. **정리 문서 다양화**: 리포트 외에 편지/일기 형태
6. **개인 철학 발견**: 누적 결정에서 패턴을 찾아 사용자에게 돌려줌
7. **AI 자기 선언**: 분석 제시 시 "이건 AI의 관점이야"를 명시

## 기존 v1에 대한 공격

### 1. "7단계가 진짜 필요한가?" — 사용자 이탈률 예측

**결론부터: 7단계 전부 완주하는 사용자는 10% 미만일 거다.**

근거:
- 챗봇 평균 이탈률 데이터를 보면, 대화 3턴을 넘기는 사용자가 50% 이하다. 7단계면 최소 14-21턴이다.
- 너의 7단계를 코드 기준으로 보면: CLARIFY(2-3턴) → CONTEXT(2-3턴) → OPTIONS(2턴) → EVALUATE(2턴) → STRESS_TEST(2턴) → DECIDE(2턴) → COMMIT(2턴). 최소 14턴, 현실적으로 20턴+.
- "이직해야 할까?"를 물어본 사용자가 20턴을 참을까? 3단계째에서 "그냥 ChatGPT한테 물어볼래"가 된다.
- 특히 멘탈케어 진입 사용자는 감정적으로 지쳐 있는 상태다. 긴 프로세스를 견딜 에너지가 없다.

**비유**: 병원 응급실에 온 사람한테 "먼저 접수하시고, 문진표 작성하시고, 예진 받으시고, 본진 받으시고, 검사하시고, 결과 상담하시고, 처방전 받으세요"라고 하면 7단계를 다 거치는 사람이 몇 명이겠나? 응급이니까 온 건데.

**그래서 어떻게 해야 하나**: Part 2에서 3단계로 줄인다.

---

### 2. "6개 모델이 MVP인가?" — 복잡성 vs 실용성

**결론: 6개 모델은 MVP가 아니라 v3 기능이다.**

문제 진단:
- 인터뷰 결과 문서에 "MVP 범위: 7단계 파이프라인 전체 + 6개 모델 전체"라고 적혀 있다. 이건 MVP의 정의를 모르는 거다.
- MVP는 "Minimum Viable Product"다. 6개 모델 x 7단계 = 42개 분기. 이건 엔터프라이즈 제품이다.
- 현실: 6개 모델 중 A(다중관점토론)와 D(갈등해소)만으로 사용자 고민의 80%를 커버한다. 네 코드를 봐도 fallback이 전부 모델 A로 가게 되어 있다.
- B(빠른판단)는 ChatGPT가 이미 한다. F(반복자동화)는 반복 고민 데이터가 쌓여야 의미 있는데, DAY 1에 그 데이터가 없다.

**그래서 어떻게 해야 하나**: MVP는 모델 1개. "Socratic 질문 → 정리 문서" 한 가지 흐름만 완벽하게. 나머지는 데이터 쌓이면 추가.

---

### 3. "의사결정 히스토리가 해자라고?" — 해자가 아닌 이유

**결론: 히스토리는 해자가 아니라 lock-in 시도이고, 그 lock-in은 약하다.**

왜 해자가 아닌가:
- **해자(moat)의 정의**: 경쟁자가 따라올 수 없는 구조적 장벽. Network effect, switching cost, brand, 규모의 경제 중 하나.
- 히스토리 축적은 switching cost인데, 문제는 **사용자가 히스토리를 쌓을 만큼 오래 쓰지 않는다**. 인생의 중대한 의사결정은 연 1-3회다. 3개의 기록으로는 lock-in이 안 된다.
- 비교: Apple의 해자는 에코시스템(하드웨어+소프트웨어+서비스 전부 얽혀 있음). Notion의 해자는 팀 전체의 지식이 거기 있으니까 옮기기 힘들어서. 풀림에 3개의 의사결정 기록? Export해서 노션에 붙이면 끝이다.
- 포지셔닝 문서에 "전원 합의: 히스토리 축적이 유일한 해자"라고 되어 있는데, **유일한 해자가 약하면 해자가 없는 거다.**

**그래서 어떻게 해야 하나**: 진짜 해자는 Part 3에서 재정의한다. 힌트: "구조화된 자기 이해의 축적"이 히스토리보다 강하다.

---

### 4. "AI 의사결정 수익화 사례 0건인데 왜 하나?" — 시장 부재의 진짜 의미

**결론: 0건이라는 건 "아직 아무도 못 풀었다"와 "수요가 없다" 둘 중 하나인데, 둘 다일 가능성이 높다.**

냉정한 분석:
- 리서치에서 Cloverpop(12년, $12.6M 펀딩, 정체), Rationale(Jina의 사이드 프로젝트), SkillWee($49.99 lifetime deal)를 발견했다. 이 회사들이 실패한 이유가 "역량 부족"이 아니라 **"의사결정을 돈 주고 해결하려는 수요 자체가 약하기 때문"**이다.
- 왜 약한가? 의사결정 고통은 **간헐적**이다. 매일 고민하는 사람은 "우울증 환자"이지 "의사결정 곤란자"가 아니다. 간헐적 고통에 월 구독을 걸기 어렵다.
- 너의 대응("멘탈케어로 진입해서 의사결정으로 차별화")은 영리하다. 이건 실제로 포지셔닝에서 가장 잘한 판단이다. 하지만 그러면 본질은 **멘탈케어 앱**이고, 의사결정은 **기능**이지 **카테고리**가 아니다. 이 구분을 명확히 해야 한다.

**그래서 어떻게 해야 하나**: "의사결정 앱"이라는 프레이밍을 버려라. "감정과 생각을 정리해주는 앱"이 맞다. 의사결정 정리 문서는 그 과정의 산출물일 뿐이다.

## 새 방향에 대한 공격

### 5. "코칭 프로토콜을 AI에 적용하면 진짜 코칭이 되나?"

**결론: 안 된다. 하지만 "코칭 비슷한 것"은 가능하고, 그것만으로도 충분하다.**

왜 진짜 코칭이 안 되나:
- ICF(국제코칭연맹) 기준 코칭의 핵심은 **"코치와 클라이언트 사이의 파트너십"**이다. 여기서 핵심어는 "파트너십" — 상호 신뢰 기반의 관계.
- AI는 관계를 맺지 못한다. AI는 매 세션 초기화된다 (맥락 유지를 하더라도 "관계"와 "기억"은 다르다).
- 코칭의 또 다른 핵심: 코치의 **직관**. "이 사람이 지금 회피하고 있다"를 표정, 톤, 침묵에서 읽는 것. 텍스트 챗봇은 이걸 못 한다.

하지만 코칭의 **기법**은 적용 가능하다:
- Powerful questions (강력한 질문)
- Mirroring (사용자 말 되돌려주기)
- Reframing (관점 전환)
- Accountability (실행 계약)

**그래서 어떻게 해야 하나**: "AI 코치"라고 부르지 마라. "생각 정리 도우미"가 정확하다. 코칭 기법은 내부적으로 쓰되, 마케팅에 "코칭"을 내세우면 진짜 코치들한테 까인다. "AI가 코칭을 한다고? 웃기지 마라"가 된다.

---

### 6. "우뇌적 요소가 gimmick이 되면?"

**결론: 90%의 확률로 gimmick이 된다. 10%의 가능성을 잡으려면 극도로 정교해야 한다.**

위험 시나리오:
- "당신의 고민을 색깔로 표현한다면?" → 사용자: "뭔 소리야. 그냥 이직할지 말지 정리해줘."
- "지금 당신의 마음을 날씨에 비유하면?" → 사용자: 앱 삭제.
- 멘탈케어 앱 리뷰에서 가장 많은 불만: "AI 답변이 반복적이다", "뜬구름 잡는 소리한다". 우뇌적 요소를 잘못 넣으면 이 불만을 정확히 재현한다.

10%를 잡는 방법:
- 우뇌적 요소는 **선택적**이고 **맥락 의존적**이어야 한다. "감정이 크게 개입된 고민"에서만 등장.
- 예: 관계 고민에서 "혹시 이 관계를 한 문장으로 표현한다면 어떤 문장이에요?" — 이건 코칭 기법이면서 자연스럽다. 하지만 재정 결정에서 이걸 하면 미친 짓이다.

**그래서 어떻게 해야 하나**: 우뇌적 요소는 MVP에서 빼라. v2에서 감정 개입이 높은 세션에만 조건부 투입. "맥락 없는 우뇌 = gimmick, 맥락 있는 우뇌 = 통찰."

---

### 7. "인문학적 깨달음을 제품에 넣는다?"

**결론: 넣으면 안 된다. 사용자가 원하는 건 "깨달음"이 아니라 "정리"다.**

왜 위험한가:
- 철학을 아는 사용자에겐 AI의 인문학 인용이 천박하게 느껴진다 ("AI가 니체 인용하네. ㅋ").
- 철학을 모르는 사용자에겐 난해하거나 무관하게 느껴진다 ("이게 내 이직 고민이랑 무슨 상관?").
- **양쪽 다 잃는다.**

하지만 비전의 핵심("개인의 철학을 가지고 흐르는 삶")은 유효하다. 문제는 **전달 방식**이다.

**그래서 어떻게 해야 하나**: 인문학을 **콘텐츠로 넣지 말고, 구조로 녹여라.** 예: "너의 판단 기준 3가지가 반복적으로 '안정'이야. 이게 너의 핵심 가치인 것 같아." — 이건 인문학적 통찰이지만, 사용자에게는 "내 패턴을 알려주는 것"으로 느껴진다. 니체를 인용하지 않아도 철학적이다.

---

### 8. "맥락 축적이 프라이버시 지뢰밭"

**결론: 맞다. 이건 진짜 지뢰밭이고, 가장 큰 사업 리스크 중 하나다.**

구체적 위험:
- 풀림에 쌓이는 데이터: "이직 고민" + "연인과 헤어질지" + "독립할 돈이 없다" + "상사가 괴롭힌다" + 감정 상태 기록. **이건 일기장보다 민감하다.**
- 한국 개인정보보호법(PIPA) + 감정/건강 관련 데이터 = 민감정보 처리 동의 필수.
- 데이터 유출 1건 = 서비스 사망. "이직 고민 상담 내역이 현 직장에 유출" 시나리오를 상상해봐.
- Supabase를 쓴다고 했는데, Supabase는 기본적으로 미국 서버(AWS us-east-1)다. 한국 사용자의 극도로 민감한 심리 데이터가 미국에 저장된다? 이건 규제 리스크다.

**그래서 어떻게 해야 하나**: Part 2에서 상세 설계하지만, 핵심 원칙은:
1. **로컬 퍼스트**: 기본은 기기에만 저장. 클라우드 동기화는 옵트인.
2. **삭제 보장**: 사용자가 삭제하면 진짜 삭제. soft delete 금지.
3. **세션 단위 암호화**: 세션별 독립 키. 서버도 못 읽게.
4. 인증 파일의 기존 설계("기본: 익명 사용 → 선택: 소셜 로그인")가 맞다. 이걸 강화해라.

---

### 9. "'개인의 철학을 지향하여 흐르는 삶'이 제품 비전으로 작동하나?"

**결론: 내부 비전으로는 훌륭하다. 외부 비전(사용자 대면)으로는 작동하지 않는다.**

왜:
- "개인의 철학을 지향하여 흐르는 삶"을 들은 사용자의 반응: "그래서 뭘 해주는데?"
- 비전은 **팀을 정렬하는 도구**이지 사용자를 끌어들이는 도구가 아니다. Apple의 내부 비전은 "think different"지만, 사용자에게 파는 건 "이 폰이 사진을 잘 찍는다"다.
- 풀림의 사용자 대면 메시지는 이미 더 좋은 게 있다: **"감정 정리하러 왔는데, 결정까지 됐다."** 이걸 써라.

**그래서 어떻게 해야 하나**:
- 내부 비전 (팀/창업자용): "개인의 철학을 지향하여 흐르는 삶을 돕는다"
- 외부 메시지 (사용자용): "복잡한 고민, 함께 정리해드려요"
- 이 둘을 분리해라. 내부 비전이 외부로 새면 "뭔 소리야"가 된다.

---

### 10. "결국 ChatGPT에 코칭 프롬프트 붙이면 되는 거 아냐?"

**결론: 기술적으로는 맞다. 제품적으로는 틀리다. 하지만 이 차이를 설명하지 못하면 죽는다.**

왜 기술적으로 맞나:
- 네 코드를 봤다. `prompts.ts`의 STAGE_PROMPTS를 ChatGPT Custom Instructions에 넣으면 80% 재현된다. 라우팅도 GPTs로 가능하다. 정리 문서도 GPT가 만든다.

왜 제품적으로 틀린가:
- **"할 수 있다"와 "한다"는 완전히 다르다.** 누구나 운동할 수 있지만, 헬스장에 매달 돈을 낸다. 누구나 집에서 요리할 수 있지만, 배달 앱을 쓴다.
- ChatGPT에 코칭 프롬프트를 쓸 수 있는 사람은 상위 5%다. 나머지 95%는 프롬프트를 모른다.
- 풀림이 파는 건 **"프롬프트 엔지니어링 능력이 없는 사람도 구조화된 고민 정리를 할 수 있게 하는 것"**이다.

하지만 이 방어선은 얇다:
- OpenAI가 "고민 정리" GPTs를 공식으로 내면? 1초 만에 무너진다.
- 대형 멘탈케어 앱(마인드카페)이 Socratic 기능을 추가하면? 그들은 이미 7.9만 MAU가 있다.

**그래서 어떻게 해야 하나**: wrapper 논란에서 살아남으려면 **"프롬프트만으로 재현할 수 없는 것"**이 있어야 한다. Part 3에서 답한다.

## 가장 치명적인 질문 3개

### Q1: 근본적으로 이 서비스가 존재해야 하는 이유는?

**팩트 기반 답변:**

"고민 정리"에 대한 수요는 명확히 존재한다. 증거:
- 마인드카페 + 트로스트 합산 MAU 16만, 마인드카페 매출 93억
- 우울증 환자 110만 중 80만이 방치
- 심리상담 1회 5-20만원 vs 풀림 월 5,000-10,000원

하지만 "존재해야 하는 이유"와 "수요가 있다"는 다르다.

풀림이 존재해야 하는 진짜 이유: **기존 멘탈케어 앱은 "감정을 들어주는 것"에서 끝나고, ChatGPT는 "답을 주는 것"에서 끝난다. 둘 다 "그래서 뭘 해야 하는지"까지 정리해주지 않는다.** 이 갭이 풀림의 존재 이유다.

리서치에서 나온 사용자 불만이 이걸 뒷받침한다: "상담받고 나서 뭐가 달라졌는지 모르겠다." 풀림은 "뭐가 달라졌는지"를 문서로 보여준다.

---

### Q2: 1,000명이 매일 쓰게 하려면 진짜 뭐가 필요한가?

**이건 질문 자체가 함정이다.** 풀림은 매일 쓰는 앱이 아니다.

현실적 사용 패턴:
- 중대한 고민: 연 2-5회 (이직, 관계, 독립 등)
- 가벼운 고민: 월 1-3회 (구매, 갈등, 선택)
- **매일은 없다.** 매일 고민하는 사람은 앱이 아니라 상담사가 필요하다.

그래서 질문을 바꿔야 한다: **"1,000명이 고민이 생겼을 때 풀림을 가장 먼저 여는" 습관을 만들려면?**

필요한 것:
1. **첫 세션에서 "와, 정리됐다"를 느끼게 해야 한다.** 첫 경험이 구리면 두 번째는 없다.
2. **정리 문서를 공유하고 싶게 만들어야 한다.** 바이럴 루프. "나 이 앱으로 이직 결정 정리했는데, 너도 해봐."
3. **추적 알림이 리텐션의 핵심이다.** "1주 전에 결정한 이직, 어떻게 됐어?" — 이 알림이 앱을 다시 열게 하는 유일한 장치.

---

### Q3: 이상규가 이걸 만드는 진짜 이유는 "돈"인가 "사명"인가?

**브리핑 문서에서 본인이 답했다:** "돈보다 효용을 느낀 지점을 공유하고 싶음. 오픈소스도 고려."

**이건 사명 80%, 돈 20%의 구조다.** 그리고 이 비율이 제품에 미치는 영향은:

위험 시나리오:
- 사명이 너무 강하면: "무료로 줄게. 오픈소스로 할게" → 사업이 안 된다.
- 돈이 너무 강하면: "월 구독 올리고, 무료 제한 줄이고" → 사용자 이탈.

풀림에 권장하는 비율: **사명 60%, 돈 40%.**
- 핵심 기능은 충분히 무료로.
- 프리미엄은 "더 깊은 정리"에 대한 정당한 가치 교환.
- "오픈소스도 고려"는 버려라. 오픈소스 멘탈케어 앱은 수익화가 불가능하다. 소스를 공개하면 누군가 그대로 복사해서 광고 붙인다.

# Part 2: 풀림 v2 재설계 제안

---

## 1. 진입 경험 재설계: 빈 입력창이 아닌, 라포 형성부터

현재 v1의 홈화면: "어떤 고민이 있나요?" + 빈 textarea. 이건 **벽에 대고 말하라는 것**과 같다.

### v2 진입 흐름: "3초 안에 나를 알아보는 느낌"

```
[첫 방문자]
  |
  "안녕하세요. 풀림이에요."
  "지금 어떤 기분이에요?"
  |
  [선택지 3개] 
    복잡해요 / 답답해요 / 잘 모르겠어요
  |
  (선택 후)
  "그렇군요. 혹시 특별히 고민되는 게 있어요?"
  |
  [자유 입력 OR 예시 선택]
  |
  → 세션 시작
```

핵심 설계 원칙:
- **첫 질문은 고민이 아니라 감정이다.** 감정을 먼저 묻는 게 라포 형성의 기본.
- **선택지를 주되, 자유 입력도 허용.** 빈 칸 앞에서 얼어붙는 사용자를 구제.
- **텍스트가 아니라 대화처럼 보이게.** 한 번에 "자, 고민을 적으세요"가 아니라, 한 문장씩 등장.
- **재방문자는 다르게.** "다시 오셨네요. 지난번 [이직 고민] 어떻게 됐어요?" → 추적과 라포를 동시에.

---

## 2. 파이프라인 단순화: 7단계 → 3단계

### v2 파이프라인: LISTEN → UNTANGLE → LAND

| v2 단계 | v1 대응 | 핵심 질문 | 턴 수 |
|---------|---------|-----------|-------|
| **LISTEN** (듣기) | CLARIFY + CONTEXT | "진짜 고민이 뭔지" 찾기 + 맥락 파악 | 3-5턴 |
| **UNTANGLE** (풀기) | OPTIONS + EVALUATE + STRESS_TEST | 선택지 탐색 + 평가 + 리스크 점검 | 4-6턴 |
| **LAND** (착지) | DECIDE + COMMIT | 결정 + 실행 계약 + 정리 문서 생성 | 2-3턴 |

**총 9-14턴.** v1의 14-21턴에서 30-40% 단축.

핵심 변경점:
- **단계 이름을 한국어 동사로.** "CLARIFY"가 아니라 "듣기". 사용자가 "지금 3단계 중 1단계입니다"를 보면 "아, 아직 두 단계나 남았네"보다 "듣기 → 풀기 → 착지, 간단하네"가 된다.
- **단계 전환을 명시적으로 안 보여줘도 된다.** v1의 StageIndicator 컴포넌트처럼 7칸짜리 진행바가 아니라, 자연스러운 대화 흐름 안에서 "자, 이제 선택지를 좀 살펴볼까요?"로 전환.
- **깊이는 유지한다.** 단계를 줄인 게 아니라 합친 것이다. LISTEN 안에서 CLARIFY와 CONTEXT를 동시에 한다. 필요하면 추가 질문, 충분하면 빠르게 넘어간다.

### 어댑티브 깊이 (Adaptive Depth)

모든 고민이 3단계 전체를 필요로 하지 않는다:
- "축의금 얼마 내야 해?" → LISTEN(1턴) → LAND(1턴). 2턴이면 끝.
- "이직해야 할까?" → LISTEN(5턴) → UNTANGLE(6턴) → LAND(3턴). 14턴.

AI가 고민의 복잡도를 판단해서 깊이를 조절. 이건 v1의 6개 모델보다 우아하다. 모델 분류가 아니라 **깊이 조절**.

## 3. 코칭/우뇌 통합 방법

### 원칙: "분석이 기본, 직관은 조건부"

| 순간 | 모드 | 예시 |
|------|------|------|
| 사실 확인 | 좌뇌 (분석) | "재정적으로 이직이 가능한 상황인가요?" |
| 감정 탐색 | 우뇌 (직관) | "이 상황을 한 문장으로 표현한다면?" |
| 선택지 평가 | 좌뇌 (분석) | "A와 B 중 어떤 게 더 당신의 3년 후에 맞을까요?" |
| 편향 감지 | 혼합 | "혹시 이걸 선택하고 싶은 이유가 '편하니까'는 아닌가요?" |
| 결정 확인 | 우뇌 (직관) | "이 결정을 내린 자신을 떠올려보세요. 어떤 기분이에요?" |

**트리거 규칙:**
- emotional_involvement > 0.7 → 우뇌 질문 1-2개 삽입
- emotional_involvement < 0.3 → 우뇌 질문 0개 (순수 분석)
- 사용자가 "잘 모르겠어요"를 2회 이상 → 분석이 막힌 거니까 우뇌로 전환

이렇게 하면 gimmick이 아니라 "막힌 곳을 뚫는 도구"로 작동한다.

## 4. 맥락 축적 안전 설계

### 3계층 저장 아키텍처

```
[Layer 1: 세션 데이터] — 기기 로컬 (IndexedDB)
  - 대화 내역, 감정 기록
  - 기본: 로컬에만 저장. 서버 전송 안 함.
  - 사용자가 "저장하기"를 명시적으로 누르면 Layer 2로.

[Layer 2: 정리 문서] — 클라우드 (Supabase, 암호화)
  - 의사결정 정리 문서만 저장
  - 대화 내역은 저장 안 함 (정리 문서 ≠ 대화 원문)
  - E2E 암호화: 서버도 못 읽음
  - 한국 리전 (Supabase Singapore 또는 자체 서버)

[Layer 3: 패턴 데이터] — 클라우드, 추상화
  - "3번의 결정에서 '안정'이 반복 기준이었음" 같은 추상화된 패턴
  - 원본 대화는 없고, 추출된 패턴만
  - 이것만으로는 개인 식별 불가
```

**사용자 통제권:**
- 모든 데이터 내보내기 (JSON/PDF)
- 개별 세션 삭제
- 전체 삭제 (계정 삭제 시 모든 데이터 영구 삭제)
- "이 세션은 저장하지 않기" 옵션

3. **랜딩 페이지 1장** — "풀림이 뭔지" 설명 + 베타 대기 신청 폼

## 6. 비전의 제품화: 사용자가 체감하는 순간

"개인의 철학을 지향하며 흐르는 삶"을 사용자가 체감하는 **구체적 순간 3가지**:

### 순간 1: "아, 내가 진짜 고민하는 건 이거였어"
- LISTEN 단계에서 리프레이밍이 발생하는 순간
- "이직할지 말지"로 왔는데, "내가 진짜 원하는 건 성장인데, 이 회사에서 성장이 안 되니까 불안한 거"를 깨닫는 순간
- **이게 "개인의 철학을 발견하는" 순간이다.**

### 순간 2: "내 결정에 이런 패턴이 있었어?"
- 3번째 세션 이후, 정리 문서를 되돌아볼 때
- "나는 항상 '안정'을 기준으로 결정했네. 그런데 내가 진짜 원하는 건 '도전'이었잖아."
- **이게 "개인의 철학을 자각하는" 순간이다.**

### 순간 3: "결정한 대로 했더니 진짜 나아졌다"
- 추적 알림에서 "1주 전 결정, 어떻게 됐어요?"에 "잘 됐어요"를 누를 때
- **이게 "개인의 철학을 지향하여 흐르는" 순간이다.**

비전이 제품에 녹는 건 **기능**이 아니라 **경험의 축적**이다. 1회 사용으로는 안 느껴진다. 3회 이상 사용한 사용자만 느낀다. 그래서 **첫 경험을 3회 재방문으로 연결하는 것**이 가장 중요하다.

# Part 3: 경쟁우위 재정의

---

### 1. ChatGPT wrapper가 아닌 이유를 1문장으로

> **"ChatGPT는 물어보면 답하고, 풀림은 물어보기 전에 질문한다 — 그리고 그 질문들이 축적되어 사용자 자신도 몰랐던 판단 패턴을 보여준다."**

---

### 2. 마인드카페/트로스트와 다른 이유를 1문장으로

> **"마인드카페는 감정을 들어주고 끝나고, 풀림은 감정을 정리한 다음 '그래서 뭘 할 건지'까지 문서로 남긴다."**

---

### 3. 이 제품의 진짜 해자

히스토리가 아니다. 진짜 해자는 **"구조화된 자기 이해(Structured Self-Knowledge)"의 축적**이다.

설명:
- 히스토리 = "2월에 이직 결정했다" (사실 기록)
- 구조화된 자기 이해 = "나는 불확실성을 싫어하고, 안정을 우선시하고, 관계에서 회피 경향이 있다" (패턴 인식)
- 후자는 Export할 수 없다. "내 판단 패턴을 JSON으로 내보내기"를 누른다고 다른 앱에서 동일하게 작동하지 않는다.
- 이건 시간이 걸린다. 3회 이상 세션이 쌓여야 패턴이 보인다. 경쟁자가 오늘 시작해도 사용자의 3회 세션을 기다려야 한다.

단, 이 해자가 작동하려면 **전제 조건: 사용자가 3회 이상 돌아와야 한다.** 그래서 첫 경험이 모든 것을 결정한다.

---

### 4. 성공의 선행조건 3가지

#### 조건 1: "첫 세션 종료 후 정리 문서를 캡처해서 공유하는 사용자가 10% 이상"

왜: 이 수치가 10% 미만이면 "정리 문서"가 사용자에게 가치 없다는 뜻이다. 풀림의 핵심 차별점이 무효화된다. 수동 테스트 3명에서 이걸 먼저 확인해라. 3명 중 1명이라도 "이거 좋다, 공유해도 돼?"라고 하면 통과.

#### 조건 2: "7일 이내 재방문율 30% 이상"

왜: 멘탈케어 앱 업계 평균 7일 리텐션이 15-20%다. 풀림이 30%를 못 넘으면 "한 번 써보고 마는 앱"이 된다. 추적 알림이 이 수치를 올리는 핵심 장치인데, MVP에서 빠져 있다. **추적 알림을 MVP에 다시 넣어야 할 수도 있다.** 최소한 "1주 후 푸시 알림" 1개는.

#### 조건 3: "LLM 비용을 세션당 500원 이하로 유지"

왜: 무료 3회 + 프리미엄 월 7,500원 구조에서, 프리미엄 사용자가 월 5회 쓰면 세션당 수익 = 1,500원. LLM 비용이 세션당 2,000원이면 적자다. v1의 7단계 x Sonnet 사용은 세션당 1,000-3,000원 추정. v2의 3단계로 줄이면 500-1,000원. Haiku를 더 많이 쓰거나, 단계별 토큰 제한을 걸어야 한다.
