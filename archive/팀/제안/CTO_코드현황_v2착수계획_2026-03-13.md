## 1. v1 코드 현황 (Gemini 기반)

```

├── lib/
│   ├── types.ts              # 공통 타입 (ModelType, StageName, Session 등)
│   └── llm/
```

### 핵심 의존 관계

| 파일 | 역할 | Gemini 의존도 |
|------|------|--------------|
| `gemini.ts` | SDK 싱글턴 + 모델 2개 (Routing/Pipeline, 둘 다 gemini-2.5-flash) | **100%** — 교체 대상 |
| `router.ts` | `getRoutingModel()` → JSON 파싱 → RoutingResult 반환 | **직접 의존** — gemini.ts import |
| `prompts.ts` | 프롬프트 텍스트만. LLM 무관 | **0%** — 그대로 유지 |
| `chat/route.ts` | `getPipelineModel()` → SSE 스트리밍 | **직접 의존** — gemini.ts import |
| `route-concern/route.ts` | `routeConcern()` 호출 + 위기 감지 | **간접 의존** — router.ts 경유. 안전 레이어도 교체 대상 (섹션 2.5) |
| `types.ts` | 순수 타입 정의 | **0%** — 그대로 유지 |

### Gemini SDK 사용 패턴 (교체 시 매핑 필요)

| Gemini 패턴 | 사용 위치 | Claude 대응 |
|-------------|----------|-------------|
| `getGenerativeModel({ model })` | gemini.ts | `new Anthropic()` → `client.messages.create()` |
| `generateContent({ contents, systemInstruction })` | router.ts | `client.messages.create({ model, system, messages })` |
| `generateContentStream({ contents, systemInstruction })` | chat/route.ts | `client.messages.stream({ model, system, messages })` |
| `role: "model"` | chat/route.ts L36 | `role: "assistant"` |
| `role: "user"` (systemInstruction) | router.ts L16 | `system` 파라미터로 분리 |
| `result.response.text()` | router.ts L19 | `response.content[0].text` |
| `chunk.text()` (스트리밍) | chat/route.ts L49 | `stream.on('text', callback)` |

## 2. v2 착수 계획: Claude API 연결

### 전략: gemini.ts를 claude.ts로 교체 (병렬 공존)

gemini.ts를 삭제하지 않고, `claude.ts`를 새로 만든 뒤 router.ts와 chat/route.ts의 import만 전환한다. 프롬프트/타입/위기감지는 손 안 댄다.

### 작업 순서

#### Step 1: claude.ts 생성 (30분)

`src/lib/llm/claude.ts` — Anthropic SDK 싱글턴 + 모델 팩토리

```typescript
import Anthropic from "@anthropic-ai/sdk";

let client: Anthropic | null = null;

function getClient(): Anthropic {
  if (!client) {
    const apiKey = process.env.ANTHROPIC_API_KEY;
    if (!apiKey) throw new Error("ANTHROPIC_API_KEY is not set");
    client = new Anthropic({ apiKey });
  }
  return client;
}

// Routing: Haiku (저비용, 빠름)
export const ROUTING_MODEL = "claude-haiku-4-5-20241022";

// Pipeline: Sonnet (메인 LLM)
export const PIPELINE_MODEL = "claude-sonnet-4-20250514";

export { getClient };
```

#### Step 2: router.ts 수정 (30분)

- import를 `gemini.ts` → `claude.ts`로 변경
- `generateContent` → `client.messages.create` 매핑
- Gemini의 `systemInstruction` → Claude의 `system` 파라미터
- `role: "user"` → 그대로, `role: "model"` → 해당 없음 (라우터는 단발 호출)
- 응답 파싱: `result.response.text()` → `response.content[0].text`

#### Step 3: chat/route.ts 수정 (1시간)

- import를 `gemini.ts` → `claude.ts`로 변경
- 스트리밍 방식 교체:
  - Gemini: `generateContentStream` → `for await (chunk of stream)`
  - Claude: `client.messages.stream()` → `stream.on('text', delta => ...)`
- 메시지 형식 매핑:
  - Gemini: `{ role: "model", parts: [{ text }] }`
  - Claude: `{ role: "assistant", content: text }`
- `systemInstruction` → `system` 파라미터로 분리

#### Step 4: 환경변수 + 테스트 (30분)

- `.env.local`에 `ANTHROPIC_API_KEY` 추가
- `npm run dev` → 라우팅 API 호출 테스트
- 스트리밍 응답 확인
- 에러 핸들링 동작 확인

### 비용 영향

| 항목 | v1 (Gemini 2.5 Flash) | v2 (Claude) |
|------|----------------------|-------------|
| 라우팅 (1회/세션) | 무료 (Free Tier) | Haiku: ~$0.004 (입력 500토큰 + 출력 200토큰) |
| 파이프라인 (5-7회/세션) | 무료 (Free Tier) | Sonnet: ~$0.05-0.10/세션 (평균 6턴) |
| **세션당 총 비용** | **$0** | **~$0.05-0.10 (약 65-130원)** |
| **월 1,000세션** | **$0** | **$50-100 (약 6.5-13만원)** |

seed.yaml 기준 세션당 예산 500-2,000원 대비 충분히 범위 안. 프롬프트 캐싱 적용하면 추가 30-50% 절감 가능하지만, v2 첫 스프린트에서는 YAGNI — 나중에.

### 건드리지 않는 것 (명시)

- `prompts.ts` — 프롬프트 내용은 윤하 관할. API 교체와 무관
- `types.ts` — 순수 타입. LLM 비종속. 단, `CRISIS_KEYWORDS` 상수는 `src/lib/safety/crisis-keywords.ts`로 이관 후 제거
- 7단계 파이프라인 구조 — 스테이지 순서/전환 로직 변경 없음
- `@google/generative-ai` 패키지 — 당장 삭제 안 함. v2 안정화 후 제거

## 2.5. 안전 레이어 통합 계획 (최서영 명세 반영)

> 근거: 서영 명세 `Domain_안전레이어_코드화명세_2026-03-13.md`
> 핵심 갭: **chat API(`/api/chat`)에 위기 감지가 0%.** 세션 진행 중 위기 발언 → 아무 대응 없음.
> 원칙: API 교체(Step 1-3)와 안전 레이어 삽입을 **동시에** 진행한다. chat/route.ts를 어차피 스트리밍 교체로 다시 쓰기 때문에, 이때 안전 체크를 같이 넣는 게 가장 효율적.

### Step 0 (신규, Step 1 전에 실행): safety 모듈 생성 (20분)

`src/lib/safety/` 디렉토리 신설. 서영 명세 그대로 구현.

```
src/lib/safety/
├── crisis-keywords.ts    # TIER_A_KEYWORDS(45개), TIER_B_KEYWORDS(22개) 하드코딩
├── crisis-detector.ts    # detectCrisis(input) → { tier, matchedKeyword, response }
└── types.ts              # CrisisTier, CrisisDetectionResult, CrisisResponse, Hotline
```

핵심 함수: `detectCrisis(input: string): CrisisDetectionResult`
- 정규화: `input.replace(/\s+/g, "")` → 공백 삽입 우회 방어 ("죽 고 싶 다" → "죽고싶다")
- Tier A 먼저 체크 (상위 우선). 매칭 시 `shouldHalt: true` 반환
- Tier B 체크. 매칭 시 `shouldInjectGuard: true` 반환
- 미매칭: `{ tier: null }` 반환
- `matchedKeyword`는 내부 로깅용. 사용자에게 절대 노출 금지

기존 `src/lib/types.ts`의 `CRISIS_KEYWORDS` 상수 → `crisis-keywords.ts`로 이관. types.ts에서 해당 상수 제거.

### Step 2 수정 사항 추가: route-concern/route.ts 안전 레이어 교체

기존 계획(router.ts import 전환)에 추가:
- `route-concern/route.ts`에서 기존 `CRISIS_KEYWORDS` + `includes()` 로직 제거
- `detectCrisis()` import + Tier A/B 분기 적용
- Tier A → 즉시 crisis 응답 (`{ crisis: true, tier: "A", message, hotlines }`)
- Tier B → 라우팅 결과에 `safetyGuard` 플래그 추가 (`{ ...result, safetyGuard: { tier: "B", message, hotlines } }`)

### Step 3 수정 사항 추가: chat/route.ts 안전 체크 삽입 위치 (핵심)

chat/route.ts는 스트리밍 교체와 안전 체크를 동시에 구현한다. 삽입 위치는 **LLM 호출 직전, 메시지 파싱 직후**.

```
[요청 수신]
     │
     ▼
[1] req.json() → messages, stage, modelType 파싱
     │
     ▼
[2] ★ 안전 체크 삽입 지점 ★
     │  const lastUserMsg = messages.findLast(m => m.role === "user")
     │  const crisisResult = detectCrisis(lastUserMsg.content)
     │
     ├─ Tier A → LLM 호출 안 함. 즉시 SSE 위기 응답 스트림 반환
     │           data: {"text": "...", "crisis": true, "tier": "A", "hotlines": [...]}
     │           data: [DONE]
     │           (프론트엔드가 crisis 플래그 보고 CrisisAlert 모달 표시)
     │
     ├─ Tier B → systemPrompt 앞에 safetyGuardPrompt prepend
     │           + SSE 첫 이벤트로 safetyGuard 메타데이터 전송
     │           data: {"safetyGuard": {"tier": "B", "message": "...", "hotlines": [...]}}
     │           (프론트엔드가 SafetyBanner 표시)
     │           → 이후 정상 LLM 스트리밍 진행
     │
     └─ null → 정상 진행 (기존 로직 그대로)
     │
     ▼
[3] Claude API 스트리밍 호출 (client.messages.stream)
     │
     ▼
[4] SSE 전송 → 프론트엔드
```

#### Tier B safetyGuardPrompt (서영 명세 원문)

```
[안전 가드 — 활성]
사용자가 심리적으로 힘든 상태일 수 있습니다.
다음을 반드시 지켜주세요:
1. 절대 고통을 축소하거나 "다 괜찮아질 거예요" 같은 빈말 금지
2. 사용자의 감정을 먼저 인정 ("많이 힘드시죠", "그 마음 충분히 이해해요")
3. 응답 마지막에 자연스럽게 한 줄 삽입: "혼자 감당하기 어려우시면, 1393(자살예방상담전화)에서 24시간 이야기를 들어줍니다."
4. 질문은 가볍게, 깊이 파고들지 않기
5. "안 한다" 옵션을 항상 제시
```

이 프롬프트는 `buildSystemPrompt(stage, modelType)` 결과 앞에 prepend한다. 윤하의 기존 시스템 프롬프트를 덮어쓰지 않고, 앞에 안전 가드를 추가하는 방식.
