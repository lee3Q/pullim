# Solution Interview 스크립트 — 초안
> 작성: 박도현 (PM) | 2026-03-16
> 목적: Problem-Solution Fit 검증 + STAY 신호 검증 + 단일 앱 다고민 의향 검증
> 대상: Earlyvangelist (멘탈케어 앱 사용 경험자 or AI에게 고민 말해본 경험자)
> 진행자: 대표 (이상규) 직접. 박도현은 설계·분석 담당.
> 소요 시간: 30-40분

---

## 사전 준비

**진행자 주의사항:**
- 판단 금지. "맞아요" "좋네요" 같은 평가 반응 없애라.
- 침묵을 채우려 하지 마라. 상대가 말하기 전에 다음 질문 던지지 않는다.
- 기능 설명 금지. 제품을 팔려는 순간 인터뷰가 끝난다.
- 메모 또는 녹음 동의 먼저 받을 것.

**목표 변수 (이 인터뷰에서 확인하려는 것):**
1. 고민이 생겼을 때 실제로 어떻게 처리하는가 (현재 행동)
2. "풀어냈다" vs "해결됐다" 중 어느 쪽이 더 원하는 결과인가 (STAY 신호)
3. 하나의 앱에서 다른 종류의 고민도 다룰 의향이 있는가 (단일 앱 다고민 의향)
4. AI에게 감정/고민을 꺼내는 데 저항이 있는가 (신뢰 장벽)

---

## 섹션 0. 라포 형성 (3-5분)

> 목적: 긴장 풀기. 인터뷰어가 아니라 대화 상대로 인식시키기.

"제가 만들고 있는 게 있는데, 그걸 어떻게 쓸지 보기 전에 — 먼저 어떻게 살고 계신지 궁금해서요. 틀린 답이 없으니 편하게 말씀해주시면 됩니다."

- 요즘 어떻게 지내세요?
- 마지막으로 고민이 머릿속에 맴돌았던 게 언제였어요?

*(분위기 확인 후 다음 섹션으로)*

---

## 섹션 1. 과거 행동 파악 (8-10분)

> 목적: 현재 대안과 불만 확인. 기억이 아닌 행동 데이터.

**1-1.** 최근 6개월 안에 고민이 생겼을 때, 제일 먼저 뭘 했어요?
- *(친구에게 말함 → 계속)* 말하고 나서 어떻게 됐어요? 뭔가 바뀌었나요, 아니면 그냥 좀 나아졌나요?
- *(혼자 생각함 → 계속)* 얼마나 시간이 지났어요? 언제 멈췄어요?
- *(AI/앱 사용 → 계속)* 어떤 걸 쓰셨어요? 왜 그걸 선택했어요?

**1-2.** 그 고민이 어떻게 됐어요?
- 지금도 마음에 남아 있나요, 아니면 어느 순간 정리된 것 같나요?
- *(정리됐다고 하면)* 어떻게 정리됐어요? 결정을 내렸나요, 아니면 그냥 에너지가 빠진 건가요?

**1-3.** 혼자 고민할 때 — 가장 힘든 게 뭐였어요?
*(답 유도 금지. 상대 언어 그대로 기록)*

---

## 섹션 2. STAY 신호 검증 (8-10분)

> 목적: 사용자가 원하는 게 "해결"인지 "기다려주는 존재"인지 구분.
> ALTER EGO 리서치 핵심 발견: 번아웃 유저에게는 비조건부 대기가 해결보다 효과적.
> 단, STAY 수요가 실제로 있는지, 어느 맥락에서 발생하는지 확인 필요.

**2-1.** 고민을 말할 때 — 상대방이 뭔가 해결책을 제시해주길 바라나요, 아니면 그냥 들어주길 바라는 경우가 있나요?
- *(둘 다라고 하면)* 어느 쪽이 더 많아요? 어떤 상황일 때 그냥 들어주길 원하는 것 같아요?

**2-2.** 고민을 말했는데 상대방이 바로 해결책을 줬을 때 — 어떤 느낌이었어요?
*(경험 유도 질문. "좋았냐 나빴냐" 평가 묻지 말 것)*

**2-3.** 아무것도 안 해도 된다, 그냥 있어도 된다는 말을 들어본 적 있어요? 그때 어땠어요?
*(없다고 하면 skip)*

**2-4.** *(직접 시나리오 제시)*
"예를 들어서 — 앱을 켰는데, AI가 먼저 한 마디 건네고, 내가 말하고 싶을 때 말해도 되고 안 말해도 되는 공간이 있다면 — 어떨 것 같아요? 쓸 것 같아요, 아니면 어색할 것 같아요?"
- *(쓸 것 같다 → 계속)* 어떤 상황에서요?
- *(어색하다 → 계속)* 뭐가 어색해요?

> **기록 포인트**: 이 섹션에서 "그냥 들어줬으면" "판단 안 받고 싶다" "에너지가 없을 때" 같은 언어가 나오면 STAY 수요 확인. 3명 이상에서 비슷한 언어가 나오면 유의미.

---

## 섹션 3. 단일 앱 다고민 의향 검증 (6-8분)

> 목적: 풀림이 "의사결정 고민"만이 아니라 연애, 번아웃, 감정 정리 등 다른 종류의 고민도 다루는 공간이 되었을 때 — 사용자가 같은 앱에서 다 해결하려 할지, 아니면 기능별로 분리된 앱을 선호할지 확인.

**3-1.** 지금 쓰는 앱 — 하나를 주로 쓰는 편이에요, 아니면 고민 종류에 따라 다른 앱/사람을 쓰는 편이에요?
*(행동 확인. 아직 제품 설명 없음)*

**3-2.** 앱 하나에서 — 직장 고민도 하고, 연애 고민도 하고, 그냥 오늘 힘들었다는 것도 말할 수 있다면 — 괜찮을 것 같아요, 아니면 뭔가 섞이는 게 불편할 것 같아요?
- *(불편하다 → 계속)* 어떤 부분이 불편해요? 기록이 남는 게 불편한 건가요, 아니면 AI가 헷갈릴 것 같은 건가요?
- *(괜찮다 → 계속)* 그럼 지금까지 그런 앱이 없어서 못 쓴 건가요, 아니면 그런 앱이 있어도 굳이 안 쓸 것 같아요?

**3-3.** 하나의 앱이 내 고민 히스토리를 알고 있으면 — 다음에 고민 생길 때 도움이 될 것 같아요?
- *(도움이 된다 → 계속)* 어떤 면에서요?
- *(불편하다 → 계속)* 기억하는 게 불편한 이유가 뭐예요?

> **기록 포인트**: "다 넣고 싶다" "한 곳에서 다 보고 싶다" → 단일 앱 의향 확인. "섞이기 싫다" "각각 따로 쓰겠다" → 모드 분리 설계 필요 신호.

---

## 섹션 4. 현재 대안 평가 (4-5분)

> 목적: 경쟁 상황 파악. 사용자가 이미 해결하고 있다면 풀림의 포지션 재점검 필요.

**4-1.** 멘탈케어 앱 — 써본 적 있어요? (마인드카페, 트로스트, 마보 등)
- *(있다 → 계속)* 얼마나 썼어요? 지금도 쓰고 있어요?
- *(없다 → 계속)* 써볼 생각은 있었는데 안 써본 건가요, 아니면 필요 없어서인가요?

**4-2.** ChatGPT나 다른 AI한테 고민 말해본 적 있어요?
- *(있다 → 계속)* 어땠어요? 계속 쓰게 됐어요, 아니면 한두 번 하고 말았어요?
- *(없다 → 계속)* 왜요? 어색해서인가요, 아니면 AI가 도움이 안 될 것 같아서인가요?

**4-3.** 지금 고민 생기면 — 가장 편한 해소 방법이 뭐예요?
*(마지막 확인. 현재 대안의 강도 파악)*

---

## 섹션 5. 가상 시나리오 반응 (4-5분)

> 목적: 솔루션에 대한 첫 반응 확인. 기능 설명이 아닌 경험 묘사로 제시.
> 주의: 과도하게 팔지 마라. 반응을 보는 게 목적.

"제가 만들고 있는 게 이런 거거든요 — 고민이 생겼을 때 켜면, AI가 질문을 몇 가지 해서 내 생각이 정리되게 도와주고, 마지막에는 '내가 지금 이런 상태고, 이런 선택지가 있다'는 정리 문서가 나와요. 그리고 나중에 비슷한 고민이 생기면 전에 어떻게 정리했는지 다시 볼 수 있고요."

**5-1.** 어떤 생각이 들어요?
*(판단 유도 금지. 반응 그대로 받을 것)*

**5-2.** 이런 게 있었다면, 지난 고민 중에 써봤을 것 같은 게 있어요?
*(구체적 사례 연결 유도)*

**5-3.** 이걸 쓰게 될 것 같은 상황이 있어요? 반대로, 절대 안 쓸 것 같은 상황이 있어요?

**5-4.** 만약 이게 월 7,500원이라면 — 쓸 것 같아요?
*(WTP 직접 묻기. 이 단계에서 "쓸 것 같다"는 말을 믿지 마라. 행동 데이터가 아니다.)*
- *(쓸 것 같다 → 계속)* 지금 당장 결제하라고 하면요?
- *(안 쓸 것 같다 → 계속)* 얼마면 쓸 것 같아요?

---

## 섹션 6. 마무리 (2-3분)

**6-1.** 오늘 말씀해주신 것 중에 — 제가 놓친 게 있을 것 같아요. 더 하고 싶은 말 있어요?

**6-2.** 이 인터뷰 말고도, 나중에 제품 완성되면 먼저 써볼 의향 있어요?
*(Earlyvangelist 후보 파악)*

**6-3.** 주변에 고민이 많은 편인데 혼자 삭이는 친구 — 이런 거 보여주면 관심 가질 것 같은 사람 있어요?
*(네트워크 리퍼럴 가능성 확인)*

## 5명 인터뷰 후 분석 기준

| 검증 항목 | 확인 기준 | 결과 해석 |
|----------|----------|----------|
| STAY 수요 | 3명 이상에서 "들어주길 원한다" 언어 등장 | 번아웃 모드 개발 우선순위 높임 |
| 단일 앱 의향 | 3명 이상 "같은 앱에서 다 해도 된다" | 현재 단일 앱 방향 유지 |
| WTP 실제 의향 | "쓸 것 같다"는 말 말고, "지금 결제하면?" 질문에 긍정 2명 이상 | 7,500원 프라이싱 유효 |
| AI 신뢰 장벽 | 3명 이상에서 "AI한테 말하기 어색하다" | 온보딩 신뢰 설계 강화 필요 |
| 현재 대안 강도 | 기존 앱/친구 만족도가 높다고 3명 이상 | 포지셔닝 재검토 필요 |

## 주의사항 — 박도현의 경고

**이 스크립트는 도구다.** 대화 흐름에 따라 질문 순서는 바꿔도 된다. 하지만 목표 변수 4개(현재 행동, STAY 신호, 단일 앱 의향, AI 신뢰 장벽)는 반드시 건드려야 한다.

"쓸 것 같아요"는 데이터가 아니다. 행동 데이터는: 이미 돈을 낸 경험, 비슷한 앱을 실제로 쓴 경험, 지금 당장 쓰겠다는 의향. 나머지는 참고만.

STAY 신호 검증이 이번 인터뷰의 핵심이다. "해결해달라"는 사람과 "기다려달라"는 사람은 완전히 다른 제품을 원한다. 5명 중 몇 명이 어느 쪽인지 데이터로 확인해야 한다.
