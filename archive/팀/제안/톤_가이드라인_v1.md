# 풀림 기술 설명 톤 가이드라인 v1
> 확정: 2026-03-09 (3차 회의)
> 작성: 서윤하 + 최서영 크로스체크

## 원칙

### 1. 카피와 기술 설명은 역할이 다르다
- 카피: "답을 찾게 하는 AI. 같이 해나갑니다." — 감정, 여운, 한 줄
- 기술 설명: 풀림이 뭘 하는지 구체적으로 알려준다. 상세해도 된다
- 카피 톤을 기술 설명에 강제하지 않는다

### 2. "해준다" 금지. "된다/하게 된다" 사용
- 풀림의 철학: "AI가 해주는 것"이 아니라 "사용자가 스스로 발견하는 것"
- 주어만 바꾸면 된다

### 3. 과정을 숨기지 않는다
- 3단계 파이프라인을 사용자 언어로 설명 OK
- 단, 프레임워크 이름(Socratic, Reframing 등) 노출 금지

### 4. 톤 = "옆에 앉은 똑똑한 친구"
- 전문가 X, 선생님 X, 치료사 X
- 권위적이면 안 된다

## 위험 표현 (금지)

| 표현 | 위험 이유 |
|------|----------|
| "풀림이 생각을 **정리해드립니다**" | 서비스 주어 + 결과 보장 |
| "AI가 고민을 **해결해줍니다**" | 치료적 표현, 웰니스 경계 침범 |
| "당신 대신 **판단해드립니다**" | 의사결정 대리, 면책 붕괴 |
| "복잡한 상황을 **명쾌하게 정리**" | 결과 보장 뉘앙스 |
| "최적의 선택을 **찾아드립니다**" | 정답 제시, Socratic 원칙 위반 |

## 허용 표현 (사용 가능)

| 표현 | 안전한 이유 |
|------|-----------|
| "생각을 **정리하는 과정**을 함께합니다" | 과정 + 함께 = 서비스는 도구 |
| "질문을 통해 생각이 **정리되는** 경험" | 자동사, 사용자 내부 현상 |
| "흩어진 고민을 **구조화**하도록 돕습니다" | 보조 역할 명시 |
| "당신의 사고를 **시각화**합니다" | 기술 기능 설명, 판단 무관 |
| "정리된 결과는 **당신의 생각**입니다" | 결과 소유권 사용자 귀속 |

## 판별 기준
> 서비스가 주어이면서 결과를 보장하면 **위험**.
> 사용자가 주어이거나, 서비스가 "돕다/함께하다"면 **안전**.

## 3단계 파이프라인 사용자 설명

| 내부 용어 | 사용자 설명 |
|----------|-----------|
| 듣기 (Mirroring) | "먼저 당신의 이야기를 들어요" |
| 풀기 (Powerful Questions) | "맞는 질문으로 생각의 실타래를 풀어요" |
| 착지 (Action Design) | "정리된 생각을 글로 남기고, 첫 행동을 잡아요" |
