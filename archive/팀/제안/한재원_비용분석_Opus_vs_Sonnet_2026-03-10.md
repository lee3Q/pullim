## 0. 요약 (대표용)

비유로 말씀드리면, Opus는 **15만원짜리 과외 선생님**이고 Sonnet은 **3만원짜리 학원 강사**입니다.
과외 선생님이 더 섬세하지만, 우리가 짜놓은 3단계 파이프라인(듣기→풀기→착지)이 "교재"가 되면 학원 강사도 충분히 잘 가르칩니다.

**결론: 동아리 기간(3~7월)은 Sonnet 4.6 + 프롬프트 캐싱으로 간다. 세션당 197원 달성 가능.**
위기 감지만 별도 Haiku 콜로 처리. Opus는 불필요.

## 2. 세션당 비용 시뮬레이션

### 전제 조건 (손정원 테스트 기반 추정)

| 항목 | 수치 | 근거 |
|------|------|------|
| 총 턴 수 | 30턴 (테스터 발화 기준) | 손정원 실측 |
| 시스템 프롬프트 | ~2,000 tok | 3단계 파이프라인 + 코칭기법 + 안전규칙 |
| 사용자 입력 총량 | ~3,000 tok | 30턴 × 평균 100 tok/턴 |
| AI 응답 총량 | ~6,000 tok | 30턴 × 평균 200 tok/턴 (추정) |
| 라우팅 (Haiku) | 입력 500 tok + 출력 200 tok | 4축 분류 1회 |
| 정리 문서 생성 | 입력 4,000 tok + 출력 2,000 tok | 세션 요약 → 문서화 |
| **하이브리드 전환 후** | 총 턴 20턴 이하 (8턴 제한) | 확정 결정 반영 |

### 하이브리드 전환 후 토큰 추정 (20턴 세션)

| 구분 | Input tokens | Output tokens |

| 시스템 프롬프트 (캐시 가능) | 2,000 | — |
| 대화 (누적, 각 턴마다 전체 전송) | ~15,000 (추정, 누적 평균) | ~4,000 |

## 4. 품질 차이 예상 — 풀림 핵심 기능별

| 기능 | Sonnet 4.6 | Opus 4.6 | 차이 수준 | 근거 |
|------|:-:|:-:|:-:|------|
| **소크라틱 질문 생성** | A- | A | 미미 | 프롬프트가 질문 유형/깊이를 지정. 모델 차이보다 프롬프트 품질이 결정적 |
| **맥락 파악 (20턴 대화)** | B+ | A | 소~중 | Opus가 긴 대화의 미묘한 뉘앙스를 더 잘 잡음. 다만 20턴은 ~30K tok으로 양쪽 다 충분한 컨텍스트 |
| **위기 감지** | B+ | A- | 미미 | 키워드 기반 1차 필터 → Haiku로 충분. 2차 맥락 판단도 Sonnet으로 가능. 안전 마진은 프롬프트로 확보 |
| **정리 문서 생성** | A- | A | 미미 | 구조화된 output은 JSON 스키마 + 프롬프트로 강제. 모델 차이 최소 |
| **리프레이밍 깊이** | B+ | A | 소~중 | "의지→몸" 수준의 전환은 Sonnet도 가능. "아, 그건 생각 못했는데" 수준의 비직관적 전환에서 Opus가 약간 우위 |
| **톤 일관성** | A | A | 없음 | 시스템 프롬프트로 톤을 잡으면 양쪽 동일 |
| **중간 인사이트** | B+ | A- | 소 | 하이브리드에서 새로 추가되는 인사이트 삽입. Opus가 더 날카로울 수 있지만, 프롬프트에서 "뻔한 것 금지" 규칙으로 Sonnet도 충분 |

**핵심 판단**: 차이가 나는 곳은 "맥락 파악"과 "리프레이밍 깊이" 2가지. 나머지는 프롬프트 품질로 수렴.
그런데 이 2가지도 **3단계 파이프라인이 가이드**하기 때문에, 모델이 자유롭게 대화하는 것보다 차이가 줄어든다.

## 5. 하이브리드 모델 검토

"위기 감지만 Opus, 나머지 Sonnet" — 검토 결과: **불필요**.

| 하이브리드 옵션 | 판정 | 이유 |
|----------------|------|------|
| 위기 감지: Opus | 불필요 | 현재 설계는 키워드 필터(코드) + Haiku 2차 분류. 충분. Sonnet 3차 확인으로도 오버킬 |
| 리프레이밍: Opus | 검토 가능 | 풀기 단계에서 리프레이밍 quality가 차별점이라면 고려. 하지만 프롬프트 개선이 우선 |
| 정리 문서: Opus | 불필요 | 구조화된 output은 스키마로 강제. 모델 차이 미미 |
| 전체 Opus | 비현실적 | 세션당 426~771원. 유저 100명이면 월 17~31만원. 무료 유저 비용을 감당 못함 |

**만약 하이브리드를 한다면**: 풀기 단계의 "핵심 리프레이밍 1턴"만 Opus로 보내고 나머지 Sonnet.
- 추가 비용: 약 30~50원/세션 (input 3K + output 500 tok, Opus 가격)
- 세션당 총비용: 약 230~250원
- **현 단계에서는 과잉 최적화**. 프롬프트 개선 효과를 먼저 측정한 후 판단.

## 6. GPT 5.4와의 비교

대표님이 Perplexity 리서치에서 GPT 5.4 언급하셨는데, 정리하면:

| 비교 항목 | Claude Sonnet 4.6 | GPT 5.4 |
|-----------|:-:|:-:|
| Input 가격 | $3.00/1M | $2.50/1M |
| Output 가격 | $15.00/1M | $15.00/1M |
| 세션당 비용 (추정) | 198원 (캐싱) / 257원 | 238원 (캐싱 미적용) |
| 프롬프트 캐싱 | 지원 (90% 절감) | 지원 ($0.25/1M, 90% 절감) |
| 한국어 성능 | 강점 | 동등~약간 열세 (추정) |
| 코칭 톤 | 우리 프롬프트 최적화 완료 | 처음부터 재작업 필요 |
| 스트리밍 | SSE 지원 | SSE 지원 |
| **전환 비용** | 0 (현재 스택) | 높음 (프롬프트 전체 재작성, API 통합 재작업) |

**판단**: GPT 5.4가 input에서 $0.50/1M 싸지만, 프롬프트 캐싱 적용 시 차이 미미 (~40원/세션). 전환 비용(프롬프트 재작성 2주+) 대비 이점 없음. **지금 전환할 이유 없다.**

다만 **LLM-agnostic 아키텍처**는 유지해야 한다. 6개월 뒤 가격 판도가 바뀔 수 있음.

## 7. 권고안: 동아리 기간(3~7월) 모델 선택

### 확정 권고: **Sonnet 4.6 + 프롬프트 캐싱 + Haiku 라우팅**

| 구성 | 모델 | 역할 |
|------|------|------|
| 메인 대화 | **Sonnet 4.6** | 듣기→풀기→착지 전체 |
| 라우팅 | **Haiku 4.5** | 4축 분류 (1회/세션) |
| 정리 문서 | **Sonnet 4.6** | 세션 데이터 → 구조화 문서 |
| 위기 감지 | **코드(키워드)** + **Haiku** | 1차 키워드 → 2차 맥락 확인 |

| 지표 | 수치 |
|------|:-:|
| 세션당 비용 | **~198원** (목표 200원 달성) |
| 유저 100명 월간 | **~79,200원** |
| 유저 1명 연간 API | **~9,500원** |
| Tier 1 구독료 (7,500원/월) 대비 | **API 비용 2.6%** (추정, 월 4세션 기준) |

### 리스크와 대응

| 리스크 | 확률 | 대응 |
|--------|:-:|------|
| Sonnet 리프레이밍 품질 부족 | 중 | 프롬프트 개선 우선 → 2차 테스트 측정 → 부족하면 풀기 핵심 턴만 Opus 하이브리드 |
| 토큰 사용량 예상 초과 | 중 | 실측 후 조정. 풀기 8턴 제한이 이미 방어선 |
| 환율 변동 ($→₩) | 저 | 현재 1,380원 기준. 1,500원이 되어도 세션당 215원으로 목표 내 |
| Anthropic 가격 인상 | 저 | LLM-agnostic 아키텍처 유지. GPT 5.4가 대안으로 대기 |
