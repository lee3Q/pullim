대표님, 피드백 반영했습니다. 핵심 변경 3가지:

1. **"같이 해나갑니다" = 맥락 축적 시스템** — 슬라이드 22 아키텍처에 "데이터 파일 기반 연속성" 레이어를 명시적으로 추가했습니다. 요약이 아니라 원본 데이터를 파일로 관리해서, 사용자가 돌아왔을 때 "아, 이 사람이 나를 기억하고 있구나"를 기술적으로 구현하는 구조입니다. 칭찬, 진전 인식, 후속 문제 연결 — 이게 다 맥락 데이터가 있어야 가능합니다.

2. **기술력 증명 보강** — 슬라이드 23에 파일 수/코드 라인 수/모듈별 구현 목록을 구체적으로 넣었습니다. "19개"가 아니라 실제 코드베이스 기준 **22개 소스 파일, 1,642줄**입니다. 스크린샷은 API key 세팅 후 추가 예정으로 표기했습니다.

3. **Claude Opus 선택 근거** — 맥락 파악 성능이 가장 뛰어나서 Claude 기반으로 가는 것, 아키텍처 표에 반영했습니다.

## 슬라이드 22: 기술 아키텍처

### "답을 찾게 하는 AI. 결론은 같이 해나갑니다."

```
[사용자]  "이직해야 할까?"
   |
   v
[프론트엔드]  Next.js 15 + PWA (앱스토어 없이 모바일 앱 경험)
   |  실시간 스트리밍 대화
   v
[AI 엔진]  — 답을 찾게 한다
   |
   |---> [라우터] Haiku 4.5 (저비용 분류)
   |       4축 자동 분류
   |       가역성 / 정보충분성 / 감정개입 / 시간압박
   |
   |---> [코칭 엔진] Sonnet 4.6
   |       3단계 Socratic 파이프라인
   |       듣기 → 풀기 → 착지
   |
   v
[맥락 축적 엔진]  — 결론은 같이 해나간다
   |  세션 데이터를 요약이 아닌 데이터 파일로 관리
   |  → 이전 결정 기억 / 진전 인식 / 칭찬 / 후속 문제 연결
   |  → 일시적 코칭이 아닌, "돌아오면 알아보는" 연속적 관계
   |
   v
[산출물]  의사결정 정리 문서 자동 생성
   |  문제 / 맥락 / 선택지 / 평가 / 리스크 / 결정 / 첫 행동
   v
[저장] Supabase (암호화, 본인만 접근)
```

**핵심 기술 선택 근거**

| 선택 | 이유 |
|------|------|
| Next.js + PWA | 앱스토어 심사 없이 모바일 앱 경험 제공 |
| Claude API 기반 | 맥락 파악 성능이 가장 뛰어남 — 코칭에 필수인 "이 사람이 뭘 고민하는지" 정확히 이해 |
| 이중 모델 (Haiku + Sonnet) | 라우팅은 저비용 Haiku, 대화는 고품질 Sonnet — 비용 60% 절감 |
| 데이터 파일 기반 맥락 관리 | 요약 압축이 아닌 원본 보존 — 돌아온 사용자에게 유대감을 주는 연속성의 기반 |
| Supabase RLS | 사용자 데이터 완전 격리 (본인 데이터만 접근) |
| Vercel Edge | 자동 스케일링, 배포 5분 이내 |
