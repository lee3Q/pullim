## 의사결정 요약

### 안건 1: 산출물 이름 → "첫 걸음"
- **확정**: 사용자가 받는 산출물 = "첫 걸음"
- 코드 내부: `decision_record` 유지 (한재원)
- UI/알림: "첫 걸음이 도착했습니다"
- PPT: "의사결정 정리 문서(첫 걸음)" 병기 (심사위원 이해용)
- 사용자 시뮬: 3 페르소나 테스트, 7.5/9 (1위 동점)
- "정리 편지"는 위기 사용자 유서 연상 위험으로 메인 명칭에서 제거 (최서영)
- Tier B(위기) 세션에서는 산출물 미생성 (최서영)

### 안건 2: 제품 설명 톤 → 이원 구조 + 안전 가이드라인
- **확정**: 비전 슬라이드 = "같이 해나간다" 톤 / 기술 슬라이드 = 상세 설명 톤
- 카피와 기술 설명은 동일하게 안 가도 됨 (대표 방향)
- **금지**: 서비스가 주어 + 결과 보장 ("풀림이 정리해드립니다", "최적의 선택을 찾아드립니다")
- **허용**: 자동사 + 사용자 주체 ("생각이 정리됩니다", "내 답이 보입니다")
- 톤 가이드라인: 팀/제안/톤_가이드라인_v1.md 에 저장

### 안건 3: 가격 모델 → Tier 0/1 + 실행 환급
- **Tier 0 (무료)**: 0원/월, 월 3회 세션, 기본형 산출물
- **Tier 1 (프리미엄)**: 7,500원/월, 무제한, 풀버전 + 히스토리
- **실행 환급**: 첫 달 세션 3회 완주 시 2,500원 환급
- 환급 조건: 세션 완주 (결정 유무 무관). Tier B 자동 환급 (최서영 안전)
- 매출 구조: 결제=매출 인식, 환급=비용 처리 → 정부지원/투자 증빙 유리
- MVP 구현: PG 결제(토스페이먼츠 3일) + 수동 환급(카카오페이)
- 시장 근거: Noom 환급 모델(ARR $400M, 전환율 20%), 한국 멘탈케어앱 가격대 비교
- 검증 필요: 3/10 인터뷰에서 WTP 질문 추가

### 안건 4: 내부 엔진 용어 → "구체화 엔진(ClarifyEngine)"
- **확정**: 외부 PPT = "구체화 엔진" / 코드 = `ClarifyEngine` / 사용자 대면 = 용어 안 씀
- "코칭 엔진" 전 문서에서 삭제 (규제 리스크)
- "실행 엔진" 기각 (최서영 — 면책 리스크, 스코프 크립)
- 연결 스토리: 막연한 고민 → 구체화 → 첫 걸음
- seed.yaml: `DecisionEngine` → `ClarifyEngine` 변경 예정
