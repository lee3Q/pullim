# 에이전트 회의록 — v2 온보딩 개인화 설계
> 일시: 2026-03-12 | 26차 세션

## 안건
v2 온보딩 개인화 설계 — 분석 수위 사전 수집 방식 + 세션별 동적 조정 구조

## 배경
- v2 대표 직접 테스트 결과: 멀티 에이전트 토론이 싱글 LLM으론 나오기 어려운 인사이트 끌어냄
- 핵심 리스크: 일반 사용자는 세 전문가의 직접 분석에 불쾌감 → 이탈 가능
- 방향 결정: 실시간 저항 감지 어려움 → 온보딩 사전 수집이 해법

---

## 라운드 1 발언 요약

**서윤하 (AI Lead)**
- 온보딩 3항목 제안: A(분석 수위: direct/guided), B(결과물 형식), C(고민 영역 optional)
- 수집 순서: B → A → C
- 적용: system prompt injection (변수 주입 방식, 프롬프트 구조 건드리지 않음)
- 세션 축적: 자동 상향 조정 / 패턴 브리핑 / 사용자 주도 재설정 3시나리오
- 경고: guided 모드 프롬프트는 가설 수준, A/B 테스트 전 확정 불가

**한재원 (CTO)**
- 저장: Supabase `user_profiles` JSONB 단일 컬럼 (스키마 변경 유연)
- 주입: `buildPersonalizationBlock()` → system prompt 앞 블록 추가
- 세션 축적: `sessions` 테이블 tags + agent_summary 컬럼 추가
- MVP 공수: 3.5일 (온보딩 UI 포함)
- 온보딩 항목 확정은 서윤하/박도현 선행 필요

**박도현 (PM)**
- 긍정/부담 경계: "선택 1개 + 즉시 피드백" 구조. 질문 3개 이상 장벽
- "저항=정확성" 프레임: 외부 포지셔닝 불가 (샘플 1명, 진입 전환율 저하)
  - 활용 가능 범위: 신청서 슬라이드 내부, 투자자 설명 한정
- 테스트 설계: 1회차(온보딩 없이 파이프라인 검증) → 2회차(온보딩 추가) 분리

**최서영 (Domain/Ethics) — 부분 Veto 행사**
- Veto 대상: 위기 감지를 분석 수위 하위 속성으로 두는 설계
- 근거: 분석 수위 낮음 = 신호 희미 가능성 높음 → 감지까지 낮추면 역설
- 요구: 위기 감지 전처리 레이어 분리, 분석 수위 동적 조정과 무관하게 항상 작동
- 온보딩 자유 응답에도 위기 감지 필수, UI에 "가볍게 설정해도 위기 시 전문가 연결" 명시

## 라운드 2 (쟁점 해소)

**쟁점 1: 최서영 Veto → 조건부 해소**

한재원 답변:
- 구현 가능. `lib/crisis/detector.ts` 독립 모듈로 분리
- 파이프라인 구조: 사용자 입력 → [전처리 위기 감지 — ALWAYS ON] → [라우팅] → [분석 수위] → [파이프라인]
- Tier B: 즉각 개입 (파이프라인 중단), Tier A: 파이프라인 진행 + Tier A 플래그 주입
- 로컬 연산 (키워드/패턴 매칭), 비용 0원 추가

조건부 해소 — 서영 확인 필요 2건:
1. 맥락 기반 감지 범위: 칼/수면제 단독 키워드 포함 여부 (현재안: 오탐 높아 Tier A에만 보수적 포함)
2. Tier A 개입 타이밍: 세션 말미 vs 즉시

**쟁점 2: 온보딩 항목 수 → 합의**

서윤하 수정:
- 온보딩 1개로 축소 (B: 결과물 형식만)
- A(분석 수위): 온보딩 제거 → 첫 발화 자동 추론으로 대체
- C(고민 영역): 온보딩 제거 → 1단계 대화 자연 임베드
- 이유: 박도현 지적 수용 — 분석 수위는 발화 패턴에서 추론 가능, 물어볼 필요 없음
