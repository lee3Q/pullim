# 에이전트 회의록 — 하네스 차별화 적용 가능성
> 날짜: 2026-03-15 | 39차 세션

---

## 안건

하네스(Harness) 개념 — 풀림 차별화 적용 가능성
1. 기술적으로 어떻게 구현되는가?
2. MVP 범위인가 이후 단계인가?
3. "현재 AI 모델에는 없는 기능"을 차별화 메시지로 쓸 수 있는가?

추가 조건 (대표): "현재 어떤 AI 회사(OpenAI, Anthropic, Google)에서도 적용해놓지 않은 기능이어야 한다."

---

## 라운드 1 — 독립 발언 요약

### 한재원(CTO)
- OpenAI Memory/Anthropic Projects = 명시적 사실 저장. 우리 = 행동 시그널(회피 패턴) 기반 네거티브 앵커 자동 생성. 구조적으로 다름.
- MVP: 시그널 수집 스키마 설계. v2.5: 적용(네거티브 앵커 주입). 지금 설계 안 하면 나중에 마이그레이션 공수 발생.
- 서영에게: 안전 상수 목록 전달 요청. 서윤하에게: 네거티브 앵커 삽입 문장 형식 정의 요청.

### 서윤하(AI Lead)
- 초기 입장: 접근성 차별화 (Claude Code가 하는 걸 UX로 쉽게).
- 기술적으로 가능한 새로운 경험 4가지: 세션 간 상태 누적 주입, 병렬 다관점 토론, 산출물 구조화, 네거티브 앵커 개인화.
- 한계 인정: "Claude Code로 완전 대체 가능하다"는 문제에서 접근성 차별화는 요건 미충족.

### 박도현(PM)
- "어떤 AI 회사도 없다" 주장은 시장 메시지로 작동 안 함 (검증 불가, 하네스 용어 비사용자 친화적, 유지 불가능).
- 하네스 → 사용자 경험으로 번역 필요.
- 포지셔닝 문장 변경 보류 (인터뷰 20명 후 결정).
- WTP 연결 여부: 인터뷰 전 확정 불가. 인터뷰 가이드에 "ChatGPT와 차이" 질문 포함 필요.

### 최서영(Domain)
- 적합도 함수 자동 갱신 위험: 우울 성향 부정적 서사 학습 가능, 의존성 심화, 위기 감지 둔화.
- "어디에도 없는 기능" 주장 = 과잉 기대 → 규제 리스크 (Woebot FDA 사례).
- 안전 조건 3개 제시: 적합도 함수 안전 상수, 명시적 동의+투명성, 위기 편향 테스트.

## 라운드 2 — 쟁점 토론

### 쟁점 A: 기술 차별화 실재 여부

**한재원(CTO) 라운드 2:**
- MVP는 접근성 차별화, v2.5는 기술 차별화. 두 메시지 섞으면 안 됨.
- "어디에도 없는 기능" 주장은 v2.5 기능. MVP에서 쓰면 거짓말.
- Sprint 1 영향: session_events 테이블(행동 로그 필드) 지금 설계해야. 나중 마이그레이션 방지.

**서윤하(AI Lead) 라운드 2:**
- 접근성 차별화 **철회.** 대표 요건에 미충족.
- 새 제안: **침묵 적응 프롬프팅(Silence-Adaptive Prompting)**
  - 사용자가 말한 것이 아니라, 말하지 않은 것의 구조적 빈칸을 감지해 리프레이밍 질문 자동 설계.
  - 현재 Woebot/Wysa 포함 어떤 앱도 미구현.
  - 검증 조건: Woebot/Wysa 경쟁사 확인 필요.
- 다음 행동: Perplexity에서 "Woebot Wysa silence pattern unspoken intent detection" 확인 요청.

### 쟁점 B: Sprint 1 시그널 수집 포함 여부

**최서영(Domain) 라운드 2:**
- "수집만, 미반영" 상태도 동의 미확보 시 조건 2번 미충족.
- Sprint 1 허용 최소 조건 3가지:
  - A: 온보딩 동의 UI — 수집 항목 구체 명시
  - B: 수집 항목 목록 코드 전 문서화 (재원 작성)
  - C: 수집↔주입 경로 코드 레벨 분리 구조 보장
- 서윤하의 "상태 주입 Sprint 1 포함" → v1.5 별도 안건으로 분리 요청 (C 조건 보장 불가).
- 거부권 상태: **보류** (조건 A/B/C 충족 시 발동 안 함).

## 경쟁사 검증 결과 (대표 직접 확인)

**Woebot:** 명시적 발화 NLP + "concerning language recognition". 침묵/행동 패턴 기반 비명시적 의도 감지 공식 미구현.

**Wysa:** 120+ NLU 모델로 텍스트 분석. 위기 감지는 언어 패턴 + PHQ/GAD 설문 + 사용자 SOS 버튼. 침묵 패턴 기반 추론 공식 미구현.

**결론:** 두 앱 모두 "말한 것" 기반 분석. "말하지 않은 것의 빈칸 추론 → 질문 재설계"는 공개 제품 레벨에서 부재.

## 최종 결론

### 기술 차별화 2개 레이어 — 확정

**레이어 1: 행동 시그널 기반 네거티브 앵커 자동 갱신** (재원 설계)
- 범용 앱: 사용자가 말한 것(명시적 사실) 저장
- 풀림: 회피 패턴·재질문·중단 시그널 → 네거티브 앵커 자동 생성 → 다음 세션 시스템 프롬프트 주입

**레이어 2: 침묵 적응 프롬프팅 (Silence-Adaptive Prompting)** (서윤하 설계)
- 범용 앱: 사용자가 입력한 텍스트에만 반응
- 풀림: 대화 구조의 빈칸(말하지 않은 것) 감지 → 리프레이밍 질문 자동 설계

### 내부 포지셔닝 확정

> "현재 AI는 사용자가 말한 것에만 반응한다.
> 풀림은 말하지 않은 것과, 반복해서 회피하는 패턴까지 읽는다."

### 단계 분리

| 단계 | 내용 |
|------|------|
| MVP (Sprint 1) | 파이프라인 동작 + 시그널 수집 스키마 설계 (조건 A/B/C 충족 필수) |
| v2.5 | 네거티브 앵커 자동 주입 적용 시작 (10세션 이상 사용자) |
| v3 | 사용자 직접 하네스 편집 |
