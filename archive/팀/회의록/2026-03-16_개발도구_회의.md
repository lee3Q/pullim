# 개발 도구 회의 — MacBook Air M1 8GB 유지 여부
> 2026-03-16 | 참석: 박도현(PM), 한재원(CTO), 서윤하(AI Lead) | 진행: COS

## 안건
대표(이상규) 개발 도구 MacBook Air M1 8GB — 유지 vs 교체

## 결론 (전원 합의)
**유지. MVP 착수 시점에 재검토.**

---

## 라운드 1 — 팀원 발언

### 박도현 (PM) — 비용/리스크 관점
- **입장**: 유지
- **근거 1**: 현재 스택(Next.js + Claude API)에서 M1 8GB 초과 시나리오 없음. API 호출은 로컬 RAM 무관.
- **근거 2**: 예산 425만원 전액 배분 완료. 기기 교체 시 최소 135~179만원 추가. 예산 초과 또는 다른 항목 삭감 불가피.
- **근거 3**: 병목은 아직 가정. 검증되지 않은 문제에 자원 투입은 창업 초기 흔한 실수.
- **실행 제안**: 임계점 체크리스트 설정 (RAM 스왑 상시 8GB 초과 / 빌드가 Sprint 일정에 영향 / 개발 중단 3회 이상). 해당 시 팀 안건으로 올림.

### 한재원 (CTO) — 기술적 판단
- **입장**: 단기 유지 가능. MVP 착수 시 교체 권고.
- **기술 분석**:
  - 일반 개발 (VS Code + 브라우저 + dev server): 3.5~4.5GB — 문제 없음
  - 빌드 중 동시 실행: 피크 5.5~7GB — SSD 스왑 진입, 빌드 15~25% 느려짐
  - Claude API 호출: 네트워크 요청, RAM 수십 MB — 전혀 무관
  - 최악 (dev + build + 브라우저 풀로드): 버벅임 발생, 개발 의욕 타격 가능
- **핵심 회피 전략**: Vercel 자동빌드 사용 → 로컬 `next build` 실행 불필요. 병목 시나리오 대부분 사라짐.
- **교체 권고 시점**: MVP 착수 후 (멀티 에이전트 + Supabase + SSE 동시 개발)
- **권고 스펙**: MacBook Air M3 16GB (179만원, 1순위) 또는 M2 16GB (149만원, 2순위)
- **빌드 시간 참고**: M1 8GB → M3 16GB 기준 빌드 약 2배 빨라짐. HMR도 2~3배.

### 서윤하 (AI Lead) — AI 워크플로우 관점
- **입장**: 지금 충분. MVP 착수 전 재평가.
- **충분한 이유**: Claude Code는 가벼운 클라이언트. API 기반이라 추론 연산은 Anthropic 서버에서 발생. tmux/다중 탭도 문제 없음.
- **실제 병목 포인트**: 팀원 4명 병렬 소환 시 각 탭의 컨텍스트 + 스트리밍 버퍼 동시 메모리 적재. 현재 팀원 프롬프트가 길어서 체감 가능성 있음.
- **즉시 가능한 개선**: 에이전트 소환 중 Chrome 탭 최소화 습관. Activity Monitor 메모리 압박 확인.
- **추가 제안**: 팀원 프롬프트 경량화로 소환 시 메모리 부하 감소 가능 (별도 안건).

|------|------|

## 즉시 실행 (대표)

1. `Activity Monitor > Memory Pressure` 현재 상태 확인 (5분)
2. Vercel 자동빌드 활성화 → 로컬 `next build` 최소화
3. 에이전트 병렬 소환 중 Chrome 탭 닫기 습관
