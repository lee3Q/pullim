## 작업 목록

### 1층: API 라우트 생성 (의존: 없음)

#### 1-1. `/api/ultimate/listen/route.ts` — 경청 단계 ✅
- **읽기**: `src/app/api/chat/v2-listen/route.ts` (참고), `src/lib/llm/claude.ts`, `제품/현자_대사_시스템.md`
- **할 일**:
  - 사용자 고민 입력 → Claude Sonnet으로 공감 + 핵심 파악
  - 현자 톤 (고어체, "~일세", "~인가")
  - SSE 스트리밍 응답
  - 위기 감지(detectCrisis) 통합
  - 출력: 현자 대사 + 추천 구슬 3개 + listenSummary
- **산출물**: `src/app/api/ultimate/listen/route.ts`
- **핵심**: 기존 v2-listen을 참고하되, 현자 톤 + 구슬 추천 추가

#### 1-2. `/api/ultimate/analyze/route.ts` — 이종 모델 분석 ✅
- **읽기**: `src/app/api/analyze/route.ts` (참고), `src/lib/providers/*`, `제품/이종모델_오케스트레이션_설계.md`, `src/lib/types-ultimate.ts`
- **할 일**:
  - 선택된 구슬 3개 + 사용자 고민 + listenSummary 입력
  - 각 구슬에 서로 다른 모델 배정 (라운드 로빈: `session_id 해시 % 3`)
  - Claude, GPT, Gemini 각각 **독립 분석** (같은 프롬프트, 다른 모델)
  - 프롬프트: 구슬의 `analysisFocus`를 렌즈로 사용 (types-ultimate.ts의 CRYSTALS 참조)
  - 3개 분석 결과 + 불일치(Disagreement) 추출
  - 폴백: 모델 1개 실패 → 나머지 2개로 진행, 2개 실패 → 단일 모델 3관점
  - JSON 응답: `CrystalAnalysis[]` + `Disagreement[]`
- **산출물**: `src/app/api/ultimate/analyze/route.ts`
- **핵심**: 이종 모델 실제 호출. 프로바이더 팩토리(`src/lib/providers/index.ts`) 사용. 폴백 필수.

#### 1-3. `/api/ultimate/debate/route.ts` — 토론 ✅
- **읽기**: `src/app/api/debate/route.ts` (참고), `제품/끝판왕_파이프라인_설계_2026-03-19.md`
- **할 일**:
  - 3개 분석 결과의 불일치(Disagreement) 입력
  - 반론-수용 2라운드 (모델 교차: A의 분석을 B가 비평)
  - 합성: 핵심 갈림길 추출
  - Claude Sonnet 사용
  - JSON 응답: `DebateRound[]` + 합성 결과
- **산출물**: `src/app/api/ultimate/debate/route.ts`
- **핵심**: 모델 교차 수행 (자기합리화 방지)

#### 1-4. `/api/ultimate/conclude/route.ts` — 결론 ✅
- **읽기**: `src/lib/types-ultimate.ts` (ConclusionData), `제품/현자_대사_시스템.md`
- **할 일**:
  - 전체 세션 데이터 (listen + research + analysis + debate) 종합
  - 결론 문서 생성: 상황요약 + 선택지(리스크/보상) + 핵심 갈림길 + 사용자 성향
  - 시그니처: "자네는 이미 답을 알고 있지 않은가?"
  - 행동 약속 유도 (action + deadline)
  - Claude Sonnet 사용
  - JSON 응답: `ConclusionData`
- **산출물**: `src/app/api/ultimate/conclude/route.ts`
- **핵심**: 현자 톤 유지, 행동 약속까지 유도

1. 기존 코드 스타일/패턴 따를 것 (기존 API 라우트 참고)
