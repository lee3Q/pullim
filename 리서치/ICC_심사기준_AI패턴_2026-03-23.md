# ICC 심사 기준 + AI 작성 판별 패턴 리서치

> 날짜: 2026-03-23
> 소스: Claude 자체 웹검색 + Perplexity
> 용도: ICC 사업계획서 재작성 시 참조

## 1. ICC 입주 심사 배점 구조

센터마다 다르지만 공통 패턴:
- 사업성/시장성: 40~50% (최고 배점)
- 기술성: 30% 전후
- 창업자/팀 역량: 20~30%
- 기타/가점: 0~10%

실제 사례:
- 수성대: 경제성/실현가능성 50점, 창의성/기술수준 30점, 사업계획서 타당성 20점
- 건국대 글로컬: 사업성 40점, 기술성 30점, 창업자 역량 30점
- 60점 이상이 입주 기준인 곳이 많음

출처: 수성대 BI 사이트, 건국대 공고, 서울여대 운영규정

## 2. 심사위원 구성

- 학교 내부(산학협력단, 교수, 창업지원단) + 외부 전문가(기업인, VC, 변호사, 회계사, 멘토)
- 3~7인이 함께 서류/발표를 보고 각자 점수
- 최고/최저 점수 제외 후 평균으로 순위 결정

## 3. 탈락하는 사업계획서 특징

1. 요약문이 추상적 ("기술을 활용한 솔루션 개발")
2. 숫자만 있고 해석 없음 (표와 그래프만 나열)
3. 근거 없는 주장 ("경쟁사보다 기술이 우수하다" 비교 대상 없이)
4. 실제 성과/고객 반응 없음 (아이디어만)
5. 전문용어로만 설명 (비전문가 이해 불가)
6. 지원사업 목적과 미연결
7. 정보 나열식, 스토리텔링 없음
8. "AI가 써준 문장만 암기한 티" (심사역/멘토 반복 언급)

출처: brunch.co.kr/@0540973a0e9641d/109, eagler.blog

## 4. 합격하는 사업계획서 특징

1. "문제-해결-시장-수익" 한눈에 들어오는 구조
2. 숫자 기반 시장/재무 계획 + 출처
3. 창업자가 "이 일을 해야 할 이유" 드러남 (개인 경험)
4. 실행 계획/마일스톤 구체적 (월 단위 액션)
5. 형식/완성도/가독성 깔끔
6. 보수적 시나리오와 리스크 관리 전략 포함

## 5. 심사위원이 찾는 것

"완벽하게 성공한 기업"이 아니라 "완벽한 논리로 실패 확률을 줄여가는 독종 같은 예비 창업자"

3가지 핵심 질문:
- 누가, 어떤 문제를 해결하려 하는가?
- 진짜 고객이 존재하는가?
- 이 팀이 실제로 실행 가능한가?

## 6. AI 작성 판별 패턴

### 심사위원이 느끼는 "AI 티" 신호 (Perplexity 출처 다수)
1. 지나치게 매끈하고 일반론적인 문장
2. 업계 현실/규제/리스크 언급 없음
3. 수치/시장/BM 질문에 논리 설명 못하고 문장만 읊음
4. 팀 커리어와 문서 깊이 불일치
5. 공허한 유창함: 문법 완벽한데 읽고 나면 아무것도 기억 안 남는 글
6. 개인성 부재: 누가 써도 될 것 같은 내용
7. 과도한 완벽함: 오류/고민/불확실성이 전혀 없고 모든 것이 장밋빛

### AI 작성 vs 창업자 직접 작성 차이
- AI: 모든 섹션 균일하게 완성도 높음 / 창업자: 잘 아는 파트 상세, 모르는 파트 솔직하게 짧음
- AI: 일반적 시장 분석 / 창업자: 직접 인터뷰/조사한 구체적 인사이트
- AI: "이 문제는 중요합니다" / 창업자: "내가 직접 겪었고, 그때 이렇게 했다"
- AI: 리스크 없음 / 창업자: 실패 가능성과 대응 방안 솔직하게 제시

### 한국어 사업계획서 AI 패턴
- 번역투 ("~을 통해 혁신을 추구합니다")
- 첫째/둘째/셋째 기계적 적용
- "고객 중심의", "차별화된 가치를" 등 공허한 표현
- 정형화된 소결론 ("따라서 ~이 중요합니다")
- 균일한 단락 구조 (모든 단락 같은 길이, 같은 패턴)

### 절대 쓰면 안 되는 표현 (탈락 직행)
- "시장조사는 아직 진행 중"
- "지원금을 받으면 만들어보겠습니다"
- "AI, 블록체인 등 다양한 기술 활용 예정"
- "유튜브 바이럴로 홍보 예정"
- "비즈니스 모델은 추후 고민"
- 비교 대상 없이 "기술이 우수하다"

## 7. 판별 방식의 현실

- AI 탐지기(GPTZero 등)로 사업계획서를 걸러내는 제도화된 기준은 아직 없음
- 실제로는 발표/Q&A에서 "사람이 깊이 이해하고 쓴 글인지" 검증
- "AI로 써도 되지만, 자기 언어와 구체적 데이터로 재작성 안 하면 바로 티남" (심사위원/멘토 공통)
