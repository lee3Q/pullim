## 1. 스타트업 펀딩 스테이지 프레임워크

### 1-1. Pre-seed 단계 (현재 풀림의 위치)

| 항목 | 내용 |
|------|------|
| **목표** | Problem-Solution Fit 검증 |
| **핵심 질문** | "이 문제가 진짜 존재하는가? 사람들이 돈을 낼 만큼 아픈가?" |
| **투자 규모** | $50K~$500K (한국: 3,000만~2억원) |
| **투자자** | 엔젤, 액셀러레이터, 정부 지원금, 자비 |
| **핵심 지표** | 고객 인터뷰 수, Problem Validation, 초기 프로토타입 반응 |
| **팀 규모** | 1~3명 (창업자 + 핵심 1~2명) |
| **기간** | 3~6개월 |

**풀림 현재 상태 매핑:**
- ✅ 문제 정의 완료 ("상담 후 뭐가 달라졌는지 모르겠다")
- ✅ 경쟁 분석 완료 (한국에 Socratic→정리문서 서비스 없음)
- ✅ 시장 조사 완료 (TAM/SAM/SOM 산출)
- ✅ 프로토타입 개발 시작 (Next.js + Supabase + Claude)
- 🔄 수동 Socratic 테스트 진행 중 (3~5명 목표)
- ⏳ 유료 전환 의향 검증 미완

### 1-2. Seed 단계

| 항목 | 내용 |
|------|------|
| **목표** | Product-Market Fit (PMF) 달성 |
| **핵심 질문** | "이 제품을 가져가면 실망할 사용자가 40% 이상인가?" (Sean Ellis 테스트) |
| **투자 규모** | $500K~$2M (한국: 2억~10억원) |
| **투자자** | 시드 전문 VC, 액셀러레이터 데모데이, 정부 사업 |
| **핵심 지표** | MAU, Retention (D7/D30), NPS, 유료 전환율, ARPU |
| **팀 규모** | 3~8명 |
| **기간** | 6~18개월 |

**풀림이 Seed로 가려면:**
- MVP 출시 + 베타 테스트 20명+ 완료
- NPS 40 이상 달성
- 유료 전환율 5% 이상 확인
- D30 Retention 20% 이상
- 월 활성 사용자 1,000명+

### 1-3. Series A

| 항목 | 내용 |
|------|------|
| **목표** | Scalable Growth Model 확보 |
| **핵심 질문** | "성장 채널이 반복 가능하고 예측 가능한가?" |
| **투자 규모** | $2M~$15M (한국: 10억~50억원) |
| **투자자** | 시리즈A 전문 VC (한국: 소프트뱅크벤처스, 캡스톤파트너스, DSC 등) |
| **핵심 지표** | MRR $100K+, MoM Growth 15%+, LTV/CAC > 3, Payback < 12개월 |
| **팀 규모** | 10~30명 |

**풀림 Series A 조건:**
- MRR 1,000만원+ (유료 사용자 1,300명+)
- 검증된 고객 획득 채널 2개+ (SEO + 커뮤니티 or B2B EAP)
- B2B 파일럿 1건+ 성사
- 기술적 해자(Moat): 의사결정 히스토리 데이터 축적

## 2. 핵심 창업 방법론

### 2-1. Lean Startup (Eric Ries)

**Build-Measure-Learn 사이클:**
```
아이디어 → [BUILD] MVP → [MEASURE] 데이터 → [LEARN] 인사이트
    ↑                                                    |
    └────────────── 피벗 or 유지 ──────────────────────────┘
```

**핵심 원칙:**
1. **Validated Learning**: 가설을 세우고, 실험으로 검증. 감이 아니라 데이터로 결정
2. **MVP (Minimum Viable Product)**: 학습에 필요한 최소 기능만 구현
3. **피벗**: 핵심 가설이 틀렸으면 방향 전환. 비전은 유지하되 전략 변경

**풀림 적용:**
| 가설 | MVP 실험 | 측정 지표 | 피벗 기준 |
|------|---------|----------|----------|
| Socratic 질문이 자유대화보다 효과적 | A/B 비교 테스트 (ChatGPT vs 구조화) | 만족도, 명확도 자가평가 | 차이 없으면 → 방식 변경 |
| 정리 문서가 결정에 도움됨 | 수동 테스트 후 설문 | 유용성 평가 (1-10) | 평균 6 미만 → 포맷 재설계 |
| 월 7,500원 지불 의향 있음 | 베타 후 결제 페이지 노출 | 전환율 | 3% 미만 → 가격/가치 재설계 |
| 추적 알림이 재방문 유도 | v1.1에서 ON/OFF 비교 | D30 Retention 차이 | 유의미한 차이 없으면 → 제거 |

### 2-2. Customer Development (Steve Blank)

**4단계 프레임워크:**
```
[1] Customer Discovery → [2] Customer Validation → [3] Customer Creation → [4] Company Building
        (문제 존재?)            (솔루션 구매?)            (수요 창출)           (조직 확장)
```

**각 단계별 풀림 적용:**

| 단계 | 핵심 활동 | 풀림 현황 |
|------|----------|----------|
| **Customer Discovery** | 20명+ 인터뷰, 문제 가설 검증, 얼리어답터 발굴 | ✅ 부분 완료 (에이전트 리서치 + 시장 데이터) / 🔄 실제 사용자 인터뷰 필요 |
| **Customer Validation** | MVP로 "돈 낼 의향" 검증, 판매 프로세스 반복 | ⏳ MVP 개발 중 |
| **Customer Creation** | 마케팅 채널 확보, 유료 고객 획득 | ⏳ 계획 단계 (SEO, 커뮤니티, B2B) |
| **Company Building** | 조직 확장, 프로세스 정비 | ⏳ AI 창업팀 시스템으로 선행 |

**Steve Blank의 핵심 교훈:**
- "Get out of the building" — 빌딩 밖으로 나가서 고객을 만나라
- 비즈니스 모델은 가설이다. 실행 계획이 아니다
- 스타트업 ≠ 작은 대기업. 탐색(Search) 모드에서 실행(Execute) 모드로 전환하는 것

## 3. AI SaaS 특화 전략

### 3-1. AI SaaS의 구조적 특징

| 특징 | 전통 SaaS | AI SaaS |
|------|----------|---------|
| **비용 구조** | 고정(서버) 중심 | 변동(API 콜) 중심 — 매출↑ 비용↑ |
| **마진** | 70-80% 그로스 마진 | 50-65% (LLM 비용 반영) |
| **Moat** | 네트워크 효과, 전환 비용 | 데이터 플라이휠, 프롬프트 자산, 파인튜닝 |
| **PMF 속도** | 느림 (기능 개발) | 빠름 (프롬프트로 빠른 프로토타이핑) |
| **차별화 난이도** | 기능 차별화 가능 | "GPT wrapper" 리스크 — 기능만으론 방어 불가 |

### 3-2. AI SaaS 핵심 전략: "GPT Wrapper"를 넘어서

**1단계: 프롬프트 자산화 (현재)**
- Socratic 질문 세트를 도메인별로 정밀 설계
- 4축 라우팅 로직 (가역성/정보충분도/감정관여도/시간압박)이 핵심 IP
- 이것만으로는 방어 불가 — 경쟁자가 복제 가능

**2단계: 데이터 플라이휠 구축 (Seed)**
```
사용자 세션 → 의사결정 히스토리 축적 → 패턴 분석 정확도 향상
    ↑                                           |
    └──── 개인화된 질문 → 사용자 만족도 상승 ──────┘
```
- 시간이 갈수록 개인화 품질 향상 = 전환 비용 상승 = Moat
- 익명화된 집합 데이터로 "한국인 의사결정 패턴 DB" 구축 가능성

**3단계: 파인튜닝/독자 모델 (Series A)**
- 축적된 Socratic 대화 데이터로 도메인 특화 모델 파인튜닝
- LLM 비용 절감 (대형 모델 → 소형 파인튜닝 모델 전환)
- 벤더 의존도 감소 (Claude 단일 의존 → 멀티 LLM)

### 3-3. AI SaaS 가격 전략

| 전략 | 설명 | 풀림 적용 |
|------|------|----------|
| **Usage-based** | API 콜 수 기반 과금 | 세션 횟수 제한 (무료 3회/월) |
| **Outcome-based** | 결과물 기반 과금 | 정리 문서 생성 시 과금 가능성 |
| **Tiered Subscription** | 기능 단계별 구독 | Free → Premium → Business |
| **Freemium + Upsell** | 무료로 유입, 가치 체험 후 전환 | ✅ 채택 — 3회 무료 → 프리미엄 |

**AI SaaS 유닛 이코노믹스 관리:**
- COGS(매출원가)에 LLM API 비용 포함 필수
- 세션당 비용 최적화: Haiku(라우팅, 저비용) + Sonnet(Socratic, 고비용) 분리
- 프롬프트 캐싱, 컨텍스트 윈도우 최적화로 토큰 절약
- 목표: 그로스 마진 60% 이상 유지

### 3-4. Product-Led Growth (PLG) 전략

**PLG가 풀림에 적합한 이유:**
1. 의사결정 정리 문서 = 자연스러운 바이럴 루프 (공유 가능한 산출물)
2. 무료 3회 체험 = 가치를 먼저 경험
3. 셀프서브 온보딩 = 영업팀 불필요 (B2C)

**풀림 PLG 플라이휠:**
```
고민 입력 (진입) → Socratic 질문 체험 → 정리 문서 생성 (WOW 모먼트)
                                                |
                                    문서 공유 (바이럴) → 새 사용자 유입
                                                |
                            히스토리 축적 → 개인화 → 프리미엄 전환
```

**핵심 PLG 지표:**
| 지표 | 정의 | 목표 |
|------|------|------|
| Time to Value | 가입 → 첫 정리 문서 생성까지 시간 | < 15분 |
| Activation Rate | 가입자 중 첫 세션 완료 비율 | > 60% |
| Viral Coefficient | 1명이 데려오는 신규 사용자 수 | > 0.3 |
| Free→Paid Conversion | 무료 → 유료 전환율 | > 5% |
| Net Revenue Retention | 기존 유료 고객의 매출 유지/확장 | > 100% |

## 4. 추가 창업 프레임워크

### 4-1. Jobs-to-be-Done (JTBD) — Clayton Christensen

**고객이 "고용"하는 Job:**
```
상황(When): 중요한 결정 앞에서 혼자 반추할 때
원하는 결과(I want to): 내 상황을 객관적으로 정리하고
기대하는 성과(So that): 확신을 가지고 결정하고 행동으로 옮기고 싶다
```

**경쟁 "고용" 대안:**
| 대안 | 한계 |
|------|------|
| 혼자 고민 | 반추만 반복, 진전 없음 |
| 지인 상담 | "잘 생각해봐" — 구조 없음 |
| ChatGPT | 장단점 나열 — 결론 없음 |
| 전문 상담 | 비용(5~20만), 대기 시간, 접근성 |
| 마인드카페/트로스트 | 감정 케어 — "뭐가 달라졌는지 모르겠다" |

**풀림의 Job 해결:**
- 구조화된 질문으로 혼자 반추 → 체계적 분석으로 전환
- 정리 문서라는 산출물 = "달라진 것"의 증거
- 추적 알림 = 결정 → 행동으로의 다리

### 4-2. 피터 틸의 7가지 질문 (Zero to One)

| 질문 | 풀림 답변 | 강도 |
|------|----------|------|
| **기술 질문**: 점진적 개선이 아닌 돌파구인가? | Socratic+라우팅+정리문서 조합은 기존에 없는 접근 | 🟡 중간 |
| **타이밍 질문**: 지금 시작하기에 맞는가? | LLM 성숙, 멘탈케어 수요 급증, 정부 지원 확대 | 🟢 강함 |
| **독점 질문**: 작은 시장에서 큰 점유율로 시작하는가? | 한국 진로고민 20-30대 → 독점 가능한 니치 | 🟢 강함 |
| **사람 질문**: 맞는 팀인가? | 창업자 실사용 1년, AI 에이전트 팀 시스템 | 🟡 중간 |
| **유통 질문**: 배달 방법이 있는가? | PLG(정리문서 바이럴) + SEO + 커뮤니티 | 🟡 중간 |
| **지속성 질문**: 10-20년 후에도 방어 가능한가? | 데이터 플라이휠 + 히스토리 Moat | 🟡 잠재적 |
| **비밀 질문**: 남들이 모르는 기회를 봤는가? | "답 대신 질문"이 더 효과적이라는 실사용 인사이트 | 🟢 강함 |

### 4-3. Crossing the Chasm (Geoffrey Moore)

**기술 수용 주기상 풀림의 위치:**
```
혁신가(2.5%) → 얼리어답터(13.5%) → [캐즘] → 초기다수(34%) → 후기다수 → 낙오자
                    ↑ 현재 타겟
```

**캐즘 돌파 전략:**
1. **볼링핀 전략**: 진로/이직 고민 20-30대 → 이 세그먼트에서 압도적 1위 → 인접 확장
2. **Whole Product**: MVP만으론 안 됨. 정리문서 + 추적 + 히스토리 = 완전한 제품
3. **포지셔닝**: "멘탈케어 앱" 카테고리로 진입, 제품 내에서 "의사결정 코치"로 전환

### 4-4. Pirate Metrics — AARRR (Dave McClure)

| 단계 | 지표 | 풀림 적용 | 초기 목표 |
|------|------|----------|----------|
| **Acquisition** | 방문자 수 | SEO + 커뮤니티 유입 | 월 5,000 방문 |
| **Activation** | 첫 세션 완료 | 고민 입력 → 정리문서 생성 | 60% |
| **Retention** | D7/D30 재방문 | 추적 알림 + 새 고민 | D30 > 20% |
| **Revenue** | 유료 전환 | Free→Premium 전환 | 5% |
| **Referral** | 추천/공유 | 정리문서 링크 공유 | Viral K > 0.3 |

## 6. 풀림 단계별 실행 로드맵 (방법론 통합)

### Phase 0: 현재 ~ 2026년 3월 (Pre-seed 초기)
- **방법론**: Customer Discovery + Lean Startup
- **핵심**: 수동 Socratic 테스트 5명, 창업동아리 신청
- **산출물**: 테스트 결과, 신청서, 프로토타입

### Phase 1: 2026년 4~5월 (Pre-seed 후기)
- **방법론**: Build-Measure-Learn 첫 사이클
- **핵심**: MVP 출시, 베타 테스트 20명, 핵심 가설 검증
- **산출물**: 웹앱 MVP, 사용자 피드백, NPS 측정
- **지원사업**: 창업동아리 활동, 예비창업패키지 지원

### Phase 2: 2026년 6~8월 (Seed 준비)
- **방법론**: Customer Validation + AARRR 최적화
- **핵심**: 유료 전환 테스트, 성장 채널 실험, B2B 파일럿 탐색
- **산출물**: 유료 사용자 100명+, 유닛 이코노믹스 검증
- **지원사업**: 초기창업패키지 or TIPS 지원

### Phase 3: 2026년 9월~ (Seed)
- **방법론**: PLG 플라이휠 + 데이터 플라이휠
- **핵심**: MAU 1,000명+, 유료 1,000명 목표, 패턴 분석 기능
- **산출물**: PMF 달성 증거, Seed 투자 유치
