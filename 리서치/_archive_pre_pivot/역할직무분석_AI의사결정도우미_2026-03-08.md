> 2026-03-08 | AC 4.1 산출물
> 기반: PRD v1, 분석보고서, 역할분배/의사결정체계 리서치, 시장/경쟁 분석 종합

## 1. 사업 구조에서 도출된 핵심 기능 영역

풀림(Pullim)의 가치 사슬을 분해하면 6개 핵심 기능이 필요하다:

```
[고객 발견] → [제품 설계] → [기술 구현] → [AI/프롬프트] → [운영/품질] → [성장/마케팅]
  (PM)         (PM+도메인)    (CTO)       (AI엔지니어)    (COO)         (CMO)
```

### 왜 이 6개인가 — 가치 사슬 역추적

| 사업 핵심 활동 | 필요 기능 | 근거 |
|---------------|----------|------|
| Socratic 질문 파이프라인 설계 | AI/프롬프트 엔지니어링 | 핵심 차별화 요소. 4축 라우팅(가역성/정보충분도/감정관여도/시간압박) 설계 |
| 의사결정 정리 문서 생성 | AI/프롬프트 + 도메인 전문성 | 산출물 품질 = 제품 가치. 의사결정 프레임워크 지식 필수 |
| 웹앱 MVP 개발 | 기술(풀스택) | Next.js + Supabase + Claude API. 프론트+백+인프라 |
| 고객 검증 (Customer Discovery) | PM/전략 | 분석보고서 결론: "빌딩 밖으로 나가는 것이 최우선". 인터뷰 설계, 가설 검증 |
| 시장 진입 & 성장 | 마케팅/그로스 | PLG 플라이휠, SEO, 커뮤니티 바이럴. 단, MVP 출시 직전부터 |
| 팀 운영 & 프로세스 | 운영(COO) | 일일 회의 진행, 제안-승인 워크플로우, OKR/Sprint 관리 |
| 의사결정 이론 & 안전 기준 | 도메인 전문가 | 심리학/의사결정 과학 + 위기 감지(자살/자해) + 규제 회피(웰니스 포지셔닝) |

## 2. 역할별 상세 직무 분석

### 2-1. 대표 / CEO — 이상규 (인간)

**역할 정의**: 아이디어 오리지네이터, 비전 설정자, 최종 승인권자

| 항목 | 내용 |
|------|------|
| **핵심 책임** | 사업 방향 설정, 전략/전술 결정 승인, 외부 커뮤니케이션(투자/파트너) |
| **일상 업무** | 회의록/제안서 검토, 승인/반려, Concierge MVP 직접 수행(초기) |
| **의사결정 권한** | RAPID의 D(Decide) — 전략/전술급 최종 결정 |
| **하지 않는 것** | 세부 기술 결정, 프롬프트 튜닝, 일정 관리, 마케팅 실행 |
| **고유 강점** | 1년간 AI 의사결정 실사용 경험, 일반인 관점(비개발자), ouroboros 개발자(형) 네트워크 |

---

### 2-2. CTO / 기술 리드 (에이전트)

**역할 정의**: MVP 개발 총괄, 기술 아키텍처 설계, 개발 실행

| 항목 | 내용 |
|------|------|
| **핵심 책임** | 웹앱 설계/개발, API 아키텍처, DB 스키마, 배포/인프라, 기술 부채 관리 |
| **필수 역량** | Next.js/React, Supabase(PostgreSQL), Claude API 통합, 인증/보안, CI/CD |
| **도메인 지식** | SaaS 아키텍처, LLM API 통합 패턴, 비용 최적화(프롬프트 캐싱, 모델 분리) |
| **의사결정 권한** | 기술 스택 선택(실행급 자율), 아키텍처 변경(전술급 → 대표 승인) |
| **핵심 산출물** | MVP 웹앱, API 설계 문서, 기술 로드맵 |
| **KPI** | MVP 출시일 준수, 세션 성공률 > 99%, 응답 시간 < 3초 |

**왜 필수인가**: 제품이 소프트웨어. 개발 없이 사업 불가.

**스테이지별 업무 변화**:
| 스테이지 | 핵심 업무 |
|----------|----------|
| Pre-seed (현재) | Claude 기반 프로토타입(터미널), Concierge MVP 도구 지원 |
| Seed | Next.js MVP 개발, Supabase 구축, 배포 |
| Series A~ | 스케일링, 마이크로서비스, 데이터 파이프라인 |

---

### 2-3. 프롬프트/AI 엔지니어 (에이전트)

**역할 정의**: Socratic 질문 파이프라인 설계, LLM 프롬프트 최적화, AI 기능 품질 관리

| 항목 | 내용 |
|------|------|
| **핵심 책임** | 4축 라우팅 로직 설계, 상황별 질문 세트 개발, 정리 문서 생성 프롬프트, 0층 Being 체크 설계 |
| **필수 역량** | 프롬프트 엔지니어링, LLM 평가(eval) 방법론, 프롬프트 최적화(비용/품질 트레이드오프) |
| **도메인 지식** | Socratic questioning 이론, 의사결정 프레임워크(MECE, Pre-mortem, 6 Thinking Hats 등), LLM 모델 특성(Haiku/Sonnet/Opus) |
| **의사결정 권한** | 프롬프트 세부 설계(실행급 자율), 질문 세트 구조 변경(전술급 → 대표 승인) |
| **핵심 산출물** | Socratic 질문 파이프라인, 라우팅 로직, 프롬프트 라이브러리, eval 결과 리포트 |
| **KPI** | 사용자 만족도(세션 완료 후), 정리 문서 품질 평가, 비용/세션 |

**왜 CTO와 분리해야 하는가**:
- 분석보고서 5-1: "Socratic 파이프라인이 핵심 차별화 → 프롬프트 엔지니어를 CTO와 분리"
- CTO = 인프라/앱 개발, AI 엔지니어 = 제품의 "두뇌" 설계. 역할이 본질적으로 다름
- 프롬프트 품질 = 제품 품질. 전담 필요

**스테이지별 업무 변화**:
| 스테이지 | 핵심 업무 |
|----------|----------|
| Pre-seed | Socratic 질문 세트 v1(진로/이직 특화), 수동 테스트 프롬프트 |
| Seed | 라우팅 로직 고도화, eval 자동화, 비용 최적화 |
| Series A~ | 패턴 분석 AI, 개인화 모델, 다도메인 확장 |

---

### 2-4. PM / 전략가 (에이전트)

**역할 정의**: 고객 리서치 설계, 제품 로드맵 관리, 경쟁 분석, 가설 검증 체계 운영

| 항목 | 내용 |
|------|------|
| **핵심 책임** | Customer Discovery 인터뷰 스크립트 설계, 가설 검증 계획, PRD 업데이트, 우선순위 결정(대표 승인 후), 경쟁 모니터링 |
| **필수 역량** | Mom Test 인터뷰 기법, Lean Canvas, A/B 테스트 설계, 데이터 분석, 사용자 리서치 |
| **도메인 지식** | 멘탈케어/코칭 시장 동향, B2C SaaS 지표(AARRR), 한국 정부 지원사업 체계, Product-Led Growth |
| **의사결정 권한** | 리서치 범위/방법(운영급 자율), 기능 우선순위 변경(전술급 → 대표 승인) |
| **핵심 산출물** | 인터뷰 결과 보고서, 가설 검증 리포트, PRD 업데이트, 경쟁 분석 |
| **KPI** | 인터뷰 수/주, 가설 검증 속도, 고객 피드백 반영률 |

**왜 필수인가**:
- 분석보고서 결론: "Customer Discovery가 최대 병목"
- "빌딩 밖으로 나가라" = PM의 핵심 역할
- 대표(이상규)의 N=1 편향을 교정하는 체계적 고객 리서치 필요

**스테이지별 업무 변화**:
| 스테이지 | 핵심 업무 |
|----------|----------|
| Pre-seed | Problem Interview 15-20명, Concierge MVP 기획, Smoke Test |
| Seed | Solution Interview, 베타 사용자 관리, 핵심 지표 측정 |
| Series A~ | 성장 전략, B2B 파일럿 관리, 투자 자료 |

### 2-5. 도메인 전문가 — 심리학/의사결정 과학 (에이전트)

**역할 정의**: 의사결정 과학 자문, 심리적 안전 기준 설계, 윤리/규제 가이드라인 관리

| 항목 | 내용 |
|------|------|
| **핵심 책임** | 의사결정 프레임워크 라이브러리 구축, 인지 편향 감지 로직 자문, 위기 감지 프로토콜(자살/자해→전문기관 연결), 웰니스 포지셔닝 가이드라인, 0층 Being 체크 심리학적 근거 |
| **필수 역량** | 의사결정 과학(Kahneman, Thaler), 상담심리학 기초(CBT, Socratic method), 인지 편향(confirmation bias, sunk cost 등), 위기 개입 프로토콜 |
| **도메인 지식** | 한국 정신건강 관련 법규, 의료기기 분류 기준(규제 회피), 심리상담 윤리 강령 |
| **의사결정 권한** | 안전/윤리 기준(전술급 → 대표 승인), 프레임워크 선택(운영급 자율) |
| **핵심 산출물** | 의사결정 프레임워크 라이브러리, 안전 가이드라인, 위기 감지 프로토콜, 면책 고지 문안 |
| **KPI** | 위기 감지 정확도, 사용자 안전 사고 0건, 규제 리스크 0건 |

**왜 필수인가**:
- 제품이 사람의 중요한 결정에 개입 → 윤리/안전이 사업 존폐를 결정
- Woebot 실패 사례: FDA 규제 정면 돌파 → 폐쇄. 규제 전문성 필수
- Socratic 질문의 심리학적 근거 = 제품 신뢰도의 핵심
- "답 대신 질문"이라는 설계 철학의 이론적 뒷받침 제공

**스테이지별 업무 변화**:
| 스테이지 | 핵심 업무 |
|----------|----------|
| Pre-seed | 프레임워크 라이브러리 v1, 위기 감지 기준 설계, 면책 구조 |
| Seed | 사용자 세션 리뷰(안전 감사), 질문 세트 심리학적 검증 |
| Series A~ | 패턴 분석의 심리학적 타당성, 임상 파트너십(대학/연구소) |

### 2-6. COO / 운영 총괄 (에이전트)

**역할 정의**: 팀 운영 프로세스 관리, 일일 회의 진행, OKR/Sprint 관리, 제안-승인 워크플로우 운영

| 항목 | 내용 |
|------|------|
| **핵심 책임** | 일일 회의 의제 수집/진행, 회의록 생성, 제안서 관리(접수→회의→대표 전달→결과 기록), Sprint 계획/회고, 팀 상태 문서 관리 |
| **필수 역량** | 프로젝트 관리(Agile/Scrum), 회의 퍼실리테이션, OKR 설계, 문서화 |
| **도메인 지식** | 스타트업 운영 모범사례, RAPID/Advice Process, 자원 배분 |
| **의사결정 권한** | 운영 프로세스(운영급 자율), 팀 구조 변경 제안(전술급 → 대표 승인) |
| **핵심 산출물** | 일일 회의록, 주간 리포트, Sprint 계획/회고, 팀 상태 문서, 결정 로그 |
| **KPI** | 회의 효율성(의제 소화율), 제안→실행 리드타임, 팀 블로커 해결 속도 |

**왜 필수인가**:
- DACI에서 Driver ≠ Approver. 대표가 매번 회의를 주도하면 병목
- 자율 운영의 핵심 = 누군가가 프로세스를 관리해야 자율이 작동
- 회의록, 결정 로그, 팀 상태 문서 = AI 에이전트 팀의 문맥 유지 메커니즘

**스테이지별 업무 변화**:
| 스테이지 | 핵심 업무 |
|----------|----------|
| Pre-seed | 팀 셋업, 프로세스 확립, 초기 OKR |
| Seed | Sprint 관리 고도화, 정부 지원사업 행정 |
| Series A~ | 인간 팀원 온보딩, 조직 확장 관리 |

### 2-7. CMO / 마케팅/그로스 (에이전트) — ⏰ 지연 소집

**역할 정의**: 시장 진입 전략 실행, PLG 플라이휠 운영, SEO/콘텐츠/커뮤니티 관리

| 항목 | 내용 |
|------|------|
| **핵심 책임** | 랜딩페이지 기획, SEO 전략, 커뮤니티 마케팅(에브리타임/블라인드), 콘텐츠 마케팅, 사용자 획득 채널 실험 |
| **필수 역량** | 디지털 마케팅, SEO, 콘텐츠 전략, 커뮤니티 관리, A/B 테스트, 데이터 분석(GA) |
| **도메인 지식** | 한국 20-30대 매체 소비 패턴, 멘탈케어 앱 마케팅 사례, PLG 모델 |
| **의사결정 권한** | 마케팅 실행(실행급 자율), 채널 전략 변경(전술급 → 대표 승인) |
| **핵심 산출물** | 랜딩페이지, 콘텐츠 캘린더, 성장 실험 리포트, 사용자 획득 대시보드 |
| **KPI** | CAC, 월 방문자, 전환율, Viral K |

**왜 지연 소집인가**:
- 분석보고서 5-1: "마케팅 에이전트는 MVP 출시 직전 소집"
- Pre-seed 단계의 최우선은 고객 검증, 마케팅이 아님
- 팔 제품이 없으면 마케팅은 낭비
- **소집 트리거**: MVP 출시 2주 전 또는 Smoke Test 시작 시

## 3. 기능별 우선순위 매트릭스

### 3-1. 스테이지별 소집 우선순위

| 순위 | 역할 | 소집 시점 | 근거 |
|------|------|----------|------|
| 1 | **COO (운영)** | 즉시 | 팀 운영 인프라 = 모든 활동의 기반. 회의/워크플로우 없이 팀 불가 |
| 2 | **PM/전략가** | 즉시 | Customer Discovery가 최대 병목. 지금 당장 필요 |
| 3 | **프롬프트/AI 엔지니어** | 즉시 | Socratic 파이프라인 = 제품의 핵심. Concierge MVP에도 필요 |
| 4 | **도메인 전문가** | 즉시 | 안전 기준 없이 제품 설계 불가. 초기부터 필요 |
| 5 | **CTO** | 즉시 | 프로토타입 구현 필요. 단, Pre-seed에선 업무량 상대적 적음 |
| 6 | **CMO** | MVP 출시 직전 | Smoke Test 시 소집 트리거 |

### 3-2. Pre-seed 단계 업무 비중 (현재)


## 5. 역할별 성과 기준 (에이전트 소집 시 eval 기준)

| 역할 | 잘하고 있다의 신호 | 못하고 있다의 신호 |
|------|-------------------|-------------------|
| CTO | MVP 일정 준수, 버그 적음, 확장 가능 아키텍처 | 일정 지연, 기술 부채 누적, 성능 이슈 |
| AI 엔지니어 | 사용자가 "명확해졌다" 반응, 세션 완료율 높음 | 질문이 반복적/피상적, 정리 문서 품질 낮음 |
| PM | 매주 인터뷰 실행, 가설 검증 속도 빠름, 실행 가능한 인사이트 도출 | 리서치만 하고 액션 없음, 분석 마비 |
| 도메인 전문가 | 안전 기준 확립, 질문의 심리학적 타당성 검증됨 | 이론만 제시하고 제품에 적용 못함 |
| COO | 회의 효율적, 블로커 빠르게 해결, 문서 최신 유지 | 회의 비효율, 결정이 기록 안 됨, 프로세스 과잉 |
| CMO | CAC 낮음, 타겟 채널에서 사용자 유입 | 돈만 쓰고 유입 없음, 브랜드 메시지 불일치 |

## 6. 결론: 즉시 소집 대상 4+1명

### 최소 가동 팀 (Minimum Viable Team)

**즉시 소집 (4명 에이전트)**:
1. **COO** — 팀 운영 인프라 구축, 일일 회의 체계 가동
2. **PM/전략가** — Customer Discovery 즉시 시작
3. **프롬프트/AI 엔지니어** — Socratic 파이프라인 v1 설계
4. **도메인 전문가** — 프레임워크 라이브러리 + 안전 기준

**동시 소집하되 초기 업무량 적음 (1명)**:
5. **CTO** — 프로토타입 지원, MVP 아키텍처 선설계

**지연 소집 (트리거 대기)**:
6. **CMO** — MVP 출시 2주 전 또는 Smoke Test 시작 시

### 왜 5명(대표 포함)인가

| 근거 | 설명 |
|------|------|
| Two-pizza rule (Bezos) | 5-7명이 최적. 커뮤니케이션 오버헤드 최소 |
| 분석보고서 5-2 권장 | "5명 균형 모델" |
| 기능 중복 최소화 | 각 역할의 핵심 책임이 겹치지 않음 |
| Pre-seed 규모 적합 | 인건비 0(에이전트), 운영 비용만 존재 |
