## 1. 현재 단계 진단

### 위치: Customer Discovery 초입 — "문제가 진짜 있는가?"를 아직 증명 못 했다

Steve Blank의 Customer Development 4단계 중 1단계(Customer Discovery)에 있다. 이 단계의 목적은 단 하나: **"내가 풀려는 문제가 진짜 존재하고, 사람들이 돈을 낼 의향이 있는지"를 검증하는 것.**

| 항목 | 현재 상태 | 판정 |
|------|-----------|------|
| 아이디어 | PRD v1, seed.yaml, 인터뷰 결과 — 구체화 완료 | OK |
| 포지셔닝 | 멘탈케어 + 의사결정 하이브리드 확정 (에이전트 4:1 투표) | OK |
| 시장 리서치 | 한국/글로벌 경쟁 분석, 시장 규모, 정부 정책 | OK |
| 기술 스택 | Next.js 15 + Supabase + Vercel + Claude API 확정 | OK |
| **고객 검증** | **인터뷰 0건 실시** (3건 계획만) | **미달** |
| **MVP** | **미착수** | **미달** |
| **수익** | **0원** | **미달** |
| **팀** | 대표 1인 (에이전트 미소집) | **미달** |
| 마감 | 창업동아리 신청 3/11 (D-3) | 긴급 |

### Customer Discovery에서 지금 해야 하는 것

Blank는 명확하게 말한다: **"Get out of the building."** 사무실에서 제품 만들지 말고, 고객에게 나가서 물어봐라.

구체적으로:
1. **Problem Interview** (5-10명): "고민 앞에서 뭐가 가장 힘드냐", "AI한테 고민 상담 해본 적 있냐", "결과물(정리 문서)이 나오면 쓸 것 같냐"
2. **Solution Interview** (5명): 수동 Socratic interview를 직접 해주고, 정리 문서를 만들어주고, "이거 돈 내고 쓸래?"를 물어본다
3. **Earlyvangelist 식별**: 문제를 인지하고, 해결책을 찾고 있고, 돈을 쓸 의향이 있는 사람 3명을 찾는다

**지금은 제품을 만드는 단계가 아니다.** Wizard of Oz MVP(수동 Socratic 인터뷰)로 가설 검증이 먼저다.

## 2. 리서치 결과 종합 의견

### 강점: 리서치 품질이 Pre-seed 수준을 넘는다

3건의 리서치(창업 방법론, 팀 구성 모범사례, 에이전트 조직설계)가 체계적으로 수행됐다. 특히:

- **6대 창업 방법론** (Lean Startup, Customer Dev, YC, Zero to One, Design Thinking, JTBD) 분석이 사업에 정확하게 매핑됨
- **경쟁사 분석**이 한국+글로벌을 모두 커버하고, 성공/실패 패턴까지 도출
- **Founder-Market Fit**이 강력: 이상규가 1년간 AI 의사결정을 실사용한 경험
- **포지셔닝 의사결정**이 구조화됨 (5인 에이전트 2라운드 투표 + 데이터 기반)

### 약점: 리서치는 훌륭한데, 실행은 0이다

- 리서치 문서 10개+, 코드 0줄, 인터뷰 0건
- Paul Graham: "만드는 것 빼고 다 했다"는 최악의 상태
- 지금 시점에서 리서치 추가는 가치가 없다. **실행만 남았다**

### 핵심 발견: 이 사업의 진짜 리스크와 기회

| 구분 | 내용 |
|------|------|
| **기회 1** | 한국에 Socratic + 정리문서 서비스 없음 — 빈 자리 확인됨 |
| **기회 2** | 정부 예산 240억(AI 심리케어) + 3.4조(창업지원) — 돈이 흐르는 방향과 일치 |
| **기회 3** | "감정 정리하러 왔는데, 결정까지 됐다" — 포지셔닝 메시지가 명확하고 차별적 |
| **리스크 1** | AI 의사결정 순수 카테고리 글로벌 수익화 사례 0건 — 시장이 없을 수 있음 |
| **리스크 2** | Woebot 폐쇄($129M 펀딩) — 규제 정면 돌파의 결말 |
| **리스크 3** | 한국 멘탈케어 앱 MAU 합산 16만 — 시장 천장이 낮을 가능성 |

## 3. 시작 팀원 제안

### 핵심 판단: 5명은 과잉이다. 4명으로 시작하라.

기존 team/agents/에 5명(CTO, Prompt/AI, PM, Domain Expert, COO) + 확장 후보 2명(CMO, CFO)이 설계되어 있다. 컨설턴트 관점에서 재검토한 결과:

**COO(정하린)는 이 단계에서 불필요하다.**

| 근거 | 설명 |
|------|------|
| YC 모델 | 가장 성공한 팀은 2-3명. Pre-seed에서 운영 전담은 과잉 |
| 현재 팀 규모 | 에이전트 4명 + 대표 = 회의 참여자 5명. 퍼실리테이터가 별도로 필요한 규모가 아님 |
| 업무량 | Customer Discovery에서 회의 체계/Sprint/OKR을 돌릴 일이 없음 |
| 비용 | 에이전트 1명 = 회의당 토큰 비용 20-25% 증가 |
| 타이밍 | MVP 개발 착수 시 소집해도 늦지 않음 |

COO의 핵심 기능(회의록, 의사결정 기록)은 PM이 겸임하거나, 세션 시작/종료 프로토콜에 내장한다.

### 최종 제안: 4명 + 대표

| 우선순위 | 역할 | 이름 | 왜 지금 필요한가 | 비고 |
|---------|------|------|----------------|------|
| **1 (필수)** | CTO / Tech Lead | 한재원 | MVP = 소프트웨어. 빌더 없으면 사업 없음. 비개발자 대표에게 기술을 번역해주는 유일한 사람 | 기존 설계 유지 |
| **2 (필수)** | Prompt & AI Lead | 서윤하 | 이 사업에서 프롬프트 = 제품. Socratic 질문 품질이 곧 사용자 경험. CTO와 분리 필수 (전문성이 다르다) | 기존 설계 유지 |
| **3 (필수)** | PM & Strategy Lead | 박도현 | Customer Discovery의 핵심 파트너. 인터뷰 설계/분석, 경쟁 모니터링, "안 만들어야 할 기능" 필터링. 전략+마케팅 겸임 (이 단계에서 분리 불필요) | 기존 설계에 운영(회의록/기록) 겸임 추가 |
| **4 (필수)** | Domain Expert + Ethics/Safety | 최서영 | 멘탈케어 포지셔닝 = 안전이 생존 조건. Replika, Noom, 마인드카페 모두 도메인 전문가 초기 합류. Ethics/Safety를 별도로 두기엔 이르지만, 겸임은 필수 | 기존 설계에 Ethics/Safety 명시적 겸임 |
| — | COO (정하린) | 정하린 | **보류.** MVP 개발 착수 시 소집. 현재는 PM이 운영 겸임 | 프롬프트는 보관 |
| — | CMO (정하은) | 정하은 | **보류.** MVP 출시 2주 전 소집 | 프롬프트는 보관 |
| — | CFO (정하준) | 정하준 | **보류.** 시드 펀딩 준비 시 소집 | 프롬프트는 보관 |

### Ethics/Safety 판단

별도 팀원으로 두지 않고, 도메인 전문가(최서영)가 겸임한다.

**근거:**
- Pre-seed에서 Ethics/Safety만 전담할 일이 아직 많지 않다
- 도메인 전문가의 핵심 전문성(임상심리학, CBT, 위기 개입)이 Ethics/Safety와 85% 중첩
- 최서영의 판단 기준 제1원칙이 이미 "Do No Harm" (기존 프롬프트에 설계됨)
- 안전 관련 거부권(Veto)을 이미 보유 중
- **단, MVP 출시 전에 Ethics 전담 검토 세션을 반드시 실시** (면책 고지, 위기 감지 키워드, 전문기관 연결 프로토콜)

## 4. Phase 1에서 즉시 해야 할 3가지

### 1. 수동 Socratic Interview 5명 실시 (이번 주 내)

| 항목 | 내용 |
|------|------|
| **방법** | 카카오톡 또는 대면. 대표가 직접 Socratic 질문을 던지고, 수동으로 정리 문서를 만들어준다 |
| **대상** | 20-30대, 최근 6개월 내 중요한 결정(이직/관계/독립 등)을 고민한 경험이 있는 사람 |
| **검증 가설** | (1) 구조화된 질문이 자유 대화보다 명확도를 높이는가 (2) 정리 문서가 실제로 도움이 되는가 (3) 돈을 낼 의향이 있는가 |
| **에이전트 지원** | 서윤하(AI Lead)가 질문 세트 초안 설계, 박도현(PM)이 인터뷰 프로토콜 설계 |
| **산출물** | 인터뷰 결과 기록 5건 + 가설 검증 결과 요약 |

### 2. 창업동아리 신청서 완성 (3/11, D-3)

| 항목 | 내용 |
|------|------|
| **방법** | 기존 PPT 초안 + PRD + 리서치 기반. 에이전트 팀이 신청서 구조 리뷰 |
| **에이전트 지원** | 박도현(PM)이 신청서 구조/스토리라인 검토, 최서영(Domain)이 사회적 명분 근거 검증 |
| **핵심 메시지** | Founder-Market Fit(1년 AI 의사결정 실사용) + 한국 시장 빈 자리 + 정부 예산 방향 일치 |

### 3. Lean Canvas 1장 작성 (이번 주 내)

| 항목 | 내용 |
|------|------|
| **방법** | Ash Maurya의 Running Lean 형식. 9개 블록을 1페이지로 |
| **에이전트 지원** | 박도현(PM)이 초안 작성, 팀 전체 리뷰, 대표 승인 |
| **목적** | 사업 전체를 한 장으로 보는 도구. 인터뷰 결과에 따라 반복 업데이트 |

## 5. 리스크와 대응

### 5-1. 사업 리스크

| 리스크 | 심각도 | 발생 가능성 | 대응 전략 |
|--------|--------|------------|-----------|
| **AI 의사결정 시장 부재** | 높음 | 중간 | 멘탈케어로 진입, 의사결정 정리는 "보너스 가치". 시장이 없으면 멘탈케어 방향으로 피벗 |
| **Woebot 시나리오 (규제)** | 높음 | 낮음 | 웰니스/코칭 포지셔닝 유지, 진단/치료 표현 금지, 면책 고지 필수, 위기 감지→전문기관 연결 |
| **"ChatGPT면 되는데"** | 중간 | 높음 | 구조화(라우팅+Socratic)+정리문서+추적이 ChatGPT와 다르다는 것을 체험으로 증명. 마케팅보다 제품 차별화 |
| **LLM 비용 폭발** | 중간 | 중간 | Haiku(라우팅)+Sonnet(질문) 모델 분리, 프롬프트 캐싱, 세션당 비용 상한선 설정 |
| **MAU 천장 (한국 16만)** | 중간 | 높음 | B2B EAP(기업 직원 복지) 파이프라인 조기 탐색, 해외 진출(영어) 장기 계획 |
| **대기업 진입 (네이버/카카오)** | 중간 | 중간 | 의사결정 히스토리 데이터 선점이 유일한 해자. 빠르게 유저 확보 |

### 5-2. 팀 리스크

| 리스크 | 심각도 | 대응 전략 |
|--------|--------|-----------|
| **에이전트 품질 편차** | 높음 | 헤드헌팅급 프롬프트 설계 (완료), 정기 리뷰 |
| **세션 간 맥락 유실** | 높음 | 파일 기반 상태 관리 (team_state.yaml + dashboard.md + 회의록) |

| **토큰 비용 폭발** | 중간 | 4명으로 팀 최소화, 일일 회의 15분 타임박싱, Sonnet 모델 사용 |
| **에코 챔버 (동일 결론)** | 중간 | 도메인 전문가(서영)의 안전 우선 관점 + PM(도현)의 "No" 역할이 균형추 |

### 5-3. 대표 리스크

| 리스크 | 심각도 | 대응 전략 |
|--------|--------|-----------|
| **고객 인터뷰 미실시** | 높음 | Customer Discovery에서 인터뷰는 위임 불가. 대표가 직접 해야 한다 (Steve Blank) |
| **리서치 중독/분석 루프** | 중간 | 리서치는 종료. 추가 리서치는 인터뷰 결과 나온 후에만. 이 보고서가 리서치의 마지막 |
| **비개발자 기술 판단 오류** | 중간 | CTO(한재원)가 비유와 수치로 번역. 대표는 기술 결정 위임 + 비용 판단에만 관여 |
