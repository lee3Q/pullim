# AI 창업팀 시작 인원 구성 근거서
> 2026-03-08 | Phase 1 최종 산출물
> 기반: 창업 방법론 리서치 + 팀구성 모범사례 + 컨설팅 전문가 분석보고서 종합

---

## 1. 결론 먼저: 시작 팀 = 대표 + 4 에이전트

```
대표 (이상규) — 비전/방향/최종 승인/실사용자
    ├── CTO 에이전트 — MVP 개발, 기술 아키텍처
    ├── 프롬프트/AI 에이전트 — Socratic 파이프라인, LLM 최적화
    ├── PM/전략 에이전트 — 고객 리서치, 로드맵, 경쟁 분석
    └── 도메인 전문가 에이전트 — 심리학/의사결정 이론, 안전 기준
```

**마케팅/그로스 에이전트는 즉시 소집하지 않는다.** MVP 출시 직전 소집.

---

## 2. 왜 4명이 최소 필요한가 (각 역할별 근거)

### 2-1. CTO 에이전트 — "만들 수 없으면 사업이 아니다"

| 항목 | 근거 |
|------|------|
| **방법론 근거** | YC 모델: "Hacker + Hustler" 중 Hacker = 필수. 빌더 없는 스타트업은 존재 불가 |
| **사업 맥락** | Next.js 15 + Supabase + Claude API 기반 MVP. 코드를 작성할 에이전트가 없으면 아이디어는 파일로만 존재 |
| **제거 시 리스크** | MVP 개발 불가 → Customer Validation 진입 불가 → 사업 시작 자체가 안 됨 |
| **다른 역할이 대체 가능한가** | ❌ 불가. 프롬프트 엔지니어가 겸임하면 둘 다 중간 수준 (리서치 결과 확인) |

**CTO가 없으면**: 사업 = 0. 모든 방법론이 "빌더 1명"을 최소 조건으로 명시.

---

### 2-2. 프롬프트/AI 에이전트 — "이 사업의 제품 = 프롬프트 품질"

| 항목 | 근거 |
|------|------|
| **방법론 근거** | AI 스타트업 특화 역할 (리서치 §2-2). Perplexity AI 사례: "AI 제품은 모델 품질이 곧 제품" |
| **사업 맥락** | 7단계 Socratic 파이프라인 + 4축 라우팅(가역성/정보충분도/감정관여도/시간압박)이 핵심 차별화. 이것의 품질 = 제품의 품질 |
| **CTO와 분리 이유** | 코드 아키텍처와 프롬프트 설계는 다른 전문성. 하나의 에이전트가 양쪽을 하면 깊이가 부족 (분석보고서 §5-1) |
| **제거 시 리스크** | Socratic 질문이 표면적 수준에 머뭄 → "ChatGPT면 되잖아" 리스크(★★★★★ 최고 심각도) 대응 불가 |
| **경쟁사 분석 근거** | 마인드카페/트로스트/상담냥 모두 Socratic 방법론 없음 → 이것이 유일한 차별화인데 전담자 없으면 해자 소멸 |

**프롬프트/AI 엔지니어가 없으면**: "또 하나의 ChatGPT wrapper"로 전락. 제품 차별화 소멸.

---

### 2-3. PM/전략 에이전트 — "빌딩 밖으로 나가야 하는데, 지도를 누가 그리나"

| 항목 | 근거 |
|------|------|
| **방법론 근거** | Customer Development(Blank): "빌딩 밖으로 나가라"가 현재 최대 과제. Mom Test 인터뷰 설계, 가설 검증, 핵심 지표 추적 필요 |
| **사업 맥락** | 현재 가장 위험한 가정 5개 미검증 상태. Problem Interview 15-20명, Concierge MVP, Smoke Test 모두 PM 영역 |
| **대표가 직접 하면 안 되나** | 대표 = 아이디어 오리지네이터이자 실사용자. N=1 편향 위험(분석보고서 §3-1). PM이 "사용자 옹호자" 관점으로 편향 교정 |
| **제거 시 리스크** | 고객 검증 없이 빌드만 함 → Lean Startup 핵심 원칙 위반 → "아무도 안 쓰는 완벽한 제품" |

**PM이 없으면**: "만들기만 하고 검증은 안 하는" 전형적 실패 패턴. 분석보고서의 "빌딩 밖으로 나가라"가 실현 불가.

---

### 2-4. 도메인 전문가 에이전트 — "멘탈케어 없이 멘탈케어 사업?"

| 항목 | 근거 |
|------|------|
| **방법론 근거** | Replika(심리학 고문), Noom(행동심리학 PhD), 마인드카페(상담심리 전공자) — AI 멘탈케어 성공 사례 전원 초기에 도메인 전문가 포함 |
| **사업 맥락** | "멘탈케어로 진입, 의사결정으로 차별화" 전략 확정 → 멘탈케어 포지셔닝에서 심리학적 근거 없으면 신뢰도 0 |
| **안전 리스크** | 위기 감지 기준(자살 위험, 자해 언급), 면책 구조, "전문기관 연결" 트리거 — 전문가 없으면 법적/윤리적 사고 발생 가능 |
| **제거 시 리스크** | (1) Socratic 질문이 학술적 근거 없이 "그냥 질문" 수준 (2) 안전 사고 시 사업 존속 불가 (3) 규제 리스크(★★★☆☆) 대응 인력 부재 |

**도메인 전문가가 없으면**: 안전 사고 1건 = 사업 종료. 성공 사례 0건 (도메인 전문가 없이 멘탈케어 사업 성공한 AI 스타트업 없음).

## 3. 왜 마케팅은 지금 안 뽑는가

| 판단 기준 | 분석 |
|----------|------|
| **현재 스테이지** | Pre-seed, Customer Discovery 중반. Steve Blank: "Discovery 단계에서 마케팅 = 돈과 시간 낭비" |
| **YC 원칙** | "Do things that don't scale" — 초기 유저는 대표+PM이 직접 수동으로 확보 |
| **팀 사이즈 리스크** | 5명=10 소통 채널, 6명=15 소통 채널. 50% 증가. Pre-seed에서 커뮤니케이션 오버헤드는 치명적 |
| **토큰 효율** | 회의 시 에이전트 1명 추가 = 토큰 20-30% 증가. MVP 전 단계에서 마케팅 에이전트의 발언 대부분 = "아직 제품이 없으니 기다리죠" |
| **포지셔닝 이미 확정** | "감정 정리하러 왔는데, 결정까지 됐다" — PM이 유지 관리 가능 |

**결론**: 마케팅 에이전트 = MVP 출시 직전 소집이 최적. 그 전까지 PM이 포지셔닝/메시지 관리.

## 4. 역할 간 관계와 시너지 매트릭스

```
             CTO ←→ 프롬프트/AI    : 기술 구현 + 프롬프트 통합 (매일 협업)
             CTO ←→ PM            : 기능 우선순위 + 기술 실현가능성 (Sprint 계획)
       프롬프트/AI ←→ 도메인 전문가  : Socratic 질문 학술 근거 + 프롬프트 설계 (핵심 시너지)
              PM ←→ 도메인 전문가   : 사용자 니즈 + 전문적 해결 (인터뷰 설계)
              PM ←→ CTO           : 로드맵 + 실행 일정 (주간 Sprint)
```

### 핵심 시너지 쌍
1. **프롬프트/AI + 도메인 전문가**: 이 두 역할의 협업이 "ChatGPT와 다른" 제품을 만든다
2. **CTO + 프롬프트/AI**: 코드와 프롬프트의 통합이 실제 동작하는 MVP를 만든다
3. **PM + 대표**: 대표의 실사용 경험(N=1)을 PM의 사용자 리서치(N=다수)가 보완한다

## 5. 인원별 소통 채널 비교 (정량적 근거)

| 인원 | 소통 채널 수 | 회의 토큰 예상 | 판정 |
|------|-------------|--------------|------|
| 3명 (린 모델) | 3 | 낮음 | ⚠️ 역할 과중, 전문성 부족 |
| **4명 (권장)** | **6** | **적정** | ✅ **최소 필요 + 최적 효율** |
| 5명 (균형) | 10 | 중간 | 🟡 마케팅 에이전트 추가 시 |
| 7명 (풀) | 21 | 높음 | ❌ Pre-seed 과잉 |

**Amazon Two-Pizza 원칙**: n(n-1)/2 공식. 4명=6채널은 관리 가능, 7명=21채널은 Pre-seed에서 과잉.

---

## 6. 3명은 왜 부족한가 (린 모델 기각 사유)

"대표 + CTO/빌더 + PM" 3명 모델을 검토했으나 기각:

| 기각 사유 | 설명 |
|----------|------|
| **CTO가 프롬프트도 겸임** | 이 사업에서 코드 품질과 프롬프트 품질은 다른 전문성. 겸임 시 "ChatGPT면 되잖아" 리스크 대응 불가 |
| **도메인 전문가 부재** | AI 멘탈케어 성공 사례 전원 초기에 도메인 전문가 포함. 안전 기준 없이 멘탈케어 = 법적 리스크 |
| **사업 도메인 특수성** | 일반 SaaS면 3명으로 충분. 멘탈케어+AI+Socratic 조합은 최소 4개의 서로 다른 전문 영역 |

## 7. 확장 계획 (팀이 스스로 제안하는 구조)

### 7-1. 확장 트리거 — 팀원 누구든 제안 가능

| 트리거 조건 | 소집 역할 | 제안 예상 출처 | 우선순위 |
|------------|----------|--------------|---------|
| MVP 출시 2주 전 | **마케팅/그로스 에이전트** | PM 또는 대표 | ★★★★★ 1순위 |
| 디자인 관련 사용자 피드백 3건+ | **UX/UI 디자이너 에이전트** | CTO 또는 PM | ★★★★☆ 2순위 |
| 투자/지원금 신청 결정 시 | **비즈니스/재무 에이전트** | PM 또는 대표 | ★★★☆☆ 3순위 |
| 사용자 데이터 100건+ 축적 | **데이터 분석 에이전트** | 프롬프트/AI 또는 PM | ★★★☆☆ 4순위 |
| 법적 이슈/규제 문의 | **법률 자문 에이전트** (ad-hoc) | 도메인 전문가 | 필요 시 |

### 7-2. 확장 프로세스 (민주적 제안 시스템)

```
팀원 A: "X 역할이 필요합니다" (제안서 작성)
    ↓
일일 회의 안건 등록 → 팀 전체 토론
    ↓
[전술급 결정] → 대표에게 제안서 + 팀 의견 전달
    ↓
대표 승인 → 에이전트 소집 (프롬프트 설계 = 헤드헌팅)
    ↓
대표 반려 → 사유 기록, 재논의 가능
```

### 7-3. 스테이지별 예상 팀 사이즈

| 스테이지 | 시기(예상) | 팀 사이즈 | 구성 |
|----------|-----------|----------|------|
| **Pre-seed (현재)** | 2026.03~ | **대표+4** | CTO, 프롬프트/AI, PM, 도메인 전문가 |
| **Seed / MVP** | 2026.04~05 | 대표+5~6 | + 마케팅/그로스, (디자이너) |
| **PMF 추구** | 2026.06~08 | 대표+6~7 | + 디자이너, (데이터 분석) |
| **Growth** | 2026.09~ | 대표+7~8 | + 비즈니스/재무, (법률 자문 ad-hoc) |

### 7-4. 축소 기준 (에이전트 팀의 장점)

에이전트 팀은 인간 팀과 달리 **즉시 축소 가능**:

| 축소 조건 | 조치 |
|----------|------|
| 특정 에이전트의 회의 발언이 3회 연속 실질 기여 0 | 팀에서 해당 에이전트 제거 검토 (PM 제안) |
| 토큰 비용이 산출 가치를 초과 | 역할 통합 검토 (CTO 제안) |
| 스테이지 전환으로 역할 불필요 | 자연 해소 (대표 결정) |

## 9. 의사결정 체계와 팀 구성의 정합성

| 의사결정 프레임워크 요소 | 4명 구성에서의 실현 |
|----------------------|-------------------|
| **RAPID - Decide** | 대표 이상규 (고정) |
| **RAPID - Recommend** | 4명 모두 제안 가능 (민주적) |
| **RAPID - Input** | 각 에이전트가 본인 도메인에서 전문 의견 |
| **RAPID - Perform** | 해당 업무 담당 에이전트 |
| **Advice Process** | 운영/실행급 → 관련자 의견 수렴 후 자체 실행 |
| **Consent-Based 회의** | 4명 라운드 → 치명적 반대 없으면 proceed |

**4명이 이 체계에 최적인 이유**: 라운드 방식 의견 수렴 시 4명이면 충분히 다양한 관점을 확보하면서도 회의 시간/토큰이 관리 가능한 수준.

## 10. 최종 요약

### 왜 정확히 이 4명인가

| # | 역할 | 한 줄 존재 이유 |
|---|------|---------------|
| 1 | **CTO** | MVP가 없으면 사업이 없다 |
| 2 | **프롬프트/AI** | 제품 = 프롬프트 품질. "ChatGPT면 되잖아"에 대한 유일한 답 |
| 3 | **PM/전략** | "빌딩 밖으로 나가라". 만들기만 하면 실패한다 |
| 4 | **도메인 전문가** | 멘탈케어 사업에서 전문가 없으면 안전 사고 = 사업 종료 |

### 핵심 원칙
- **최소 인원**: 4명 = 각 역할이 빠지면 사업이 성립하지 않는 최소 단위
- **최대 효율**: 소통 채널 6개, 토큰 소비 적정, 의사결정 속도 유지
- **확장은 팀이 제안**: 마케팅부터 시작해서 필요 시 민주적으로 소집
- **축소도 가능**: 에이전트 팀의 장점. 역할 불필요 시 즉시 제거
