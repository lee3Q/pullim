## 1. Mac Studio M4 Max — 가격/성능

### 한국 Apple Store 가격 (2025 기본 모델)

| 구성 | CPU/GPU | 메모리 | 저장장치 | 한국가격(원) |
|------|---------|--------|----------|-------------|
| 기본형 | 14코어/32코어 | 36GB | 512GB | **3,290,000** |
| 상위형 | 16코어/40코어 | 64GB | 1TB | **4,040,000** |

**CTO(주문제작) 메모리 업그레이드 추정:**
- 96GB: 약 470~530만원 (기본형+메모리 업그레이드)
- 128GB: 약 550~630만원 (16코어/40코어 기반 CTO)

> 참고: Apple은 36GB→48GB→64GB→96GB→128GB 옵션 제공. CTO 가격은 한국 Apple Store에서 직접 확인 필요 (동적 로딩 방식)

### 메모리 대역폭

| 칩 | 대역폭 |
|----|--------|
| M4 Max (32코어 GPU) | **410 GB/s** |
| M4 Max (40코어 GPU) | **546 GB/s** |

### LLM 추론 벤치마크 (M4 Max, llama.cpp 기준)

| 모델 크기 | 양자화 | tok/s (생성) | 비고 |
|-----------|--------|-------------|------|
| 7B (LLaMA 2) | Q4_0 | **~83 tok/s** | 40코어 GPU |
| 7B (LLaMA 2) | Q8_0 | **~54 tok/s** | 40코어 GPU |
| 7B (LLaMA 2) | Q4_0 | **~70 tok/s** | 32코어 GPU |
| 8B (Q4_K_M) | Q4_K_M | **~96-100 tok/s** | MLX 백엔드 추정 |
| 13B | Q4_K_M | **~50-60 tok/s** | 추정치 |
| 30B (Nemotron 등) | Q4_K_M | **~30-45 tok/s** | MLX 기준 |
| 70B (LLaMA 3.3) | Q4_K_M | **~7-12 tok/s** | 128GB 필수, 메모리 대역폭 병목 |

> MLX는 llama.cpp 대비 **20~30% 빠름** (Apple Silicon 최적화). 모델이 클수록 차이가 커짐.

## 2. Mac Studio M3 Ultra

### 핵심 사실: M4 Ultra는 2025년 기준 출시 안 됨

Apple은 2025년 Mac Studio에서 **M4 Max + M3 Ultra** 조합으로 출시.
M4 Ultra는 발표되지 않았으며, "모든 세대에서 Ultra를 내지는 않겠다"는 Apple 입장.

### 한국 Apple Store 가격

| 구성 | CPU/GPU | 메모리 | 한국가격(원) |
|------|---------|--------|-------------|
| M3 Ultra 기본 | 28코어/60코어 | 192GB | **6,590,000** |
| M3 Ultra 상위 | 32코어/80코어 | 192GB | **8,840,000** |

- 메모리: 최대 **512GB** CTO 가능 (LPDDR5-6400)
- 메모리 대역폭: **819 GB/s**

### M4 Max 대비 LLM 성능

| 항목 | M4 Max (40코어) | M3 Ultra (28/60코어) |
|------|-----------------|---------------------|
| 메모리 대역폭 | 546 GB/s | 819 GB/s (1.5x) |
| 최대 메모리 | 128GB | 512GB |
| 8B 모델 tok/s | ~81 tok/s | ~84 tok/s |
| 멀티모델/대형 모델 | 70B 한계 | 200B+ 가능 |
| 가격(기본) | 404만원 | 659만원 |

**핵심:** M3 Ultra는 메모리 용량(512GB)과 대역폭(819GB/s)에서 압도적이지만, 단일 모델 추론 속도는 M4 Max와 비슷하거나 약간 빠른 수준. **큰 모델을 돌릴 수 있느냐의 차이**가 핵심.

| TDP | 450W | 575W |

| 32B (Qwen 2.5) | Q6_K | ~39 | ~52 | +32% |
| 70B (LLaMA 3.3) | Q4_K_M | ~28 | ~37 | +30% |

| **소음** | 팬 소음 | 저소음 |
| **개발 편의성** | CUDA 생태계 풍부 | macOS 통합, MLX |
| **확장성** | 멀티 GPU 가능 | 단일 SoC |

### MacBook Air M1 8GB에서 가능한 것

- **추천 모델**: Phi-3 Mini (3.8B), Gemma 2B, TinyLlama 1.1B
- **한계 모델**: LLaMA 2 7B Q4 (가능하나 ~5-8 tok/s로 느림)
- **불가능**: 13B 이상
- **서빙 도구**: Ollama가 가장 쉬움 (자동 양자화, 메모리 관리)
- **주의**: 스왑 사용 시 극심한 속도 저하. 7B도 긴 컨텍스트에서 스왑 발생

## 5. 로컬 LLM 서빙 도구 비교 (2026년 기준)

### 종합 비교표

| 도구 | 설치 난이도 | Apple Silicon | NVIDIA GPU | OpenAI API 호환 | 스트리밍(SSE) | GUI | 핵심 장점 |
|------|-----------|-------------|------------|----------------|-------------|-----|----------|
| **Ollama** | 매우 쉬움 | 네이티브 | 지원 | **호환** | **지원** | CLI | 원커맨드 설치, "Docker for LLMs" |
| **llama.cpp** | 중간 | Metal 지원 | CUDA 지원 | server 모드 호환 | **지원** | CLI | 최고 성능, 세밀한 제어 |
| **MLX** | 쉬움 | **최적화** | 미지원 | 커뮤니티 래퍼 | **지원** | CLI/Python | Apple Silicon 최고 성능 (20-30%↑) |
| **vLLM** | 어려움 | 미지원 | **최적화** | **호환** | **지원** | 없음 | 프로덕션 처리량 최고 (19x Ollama) |
| **LM Studio** | 매우 쉬움 | 지원 | Vulkan/CUDA | **호환** | **지원** | **GUI** | 초보자 친화, 모델 허브 |
| **Jan.ai** | 매우 쉬움 | 지원 | CUDA/Vulkan | **호환** | **지원** | **GUI** | 오프라인 ChatGPT, 확장 시스템 |

### 도구별 상세

#### Ollama
- **장점**: `brew install ollama` 후 `ollama run llama3` 한 줄이면 끝. 자동 양자화, 모델 관리, OpenAI API 호환 (`/v1/chat/completions`). Apple Silicon Metal 네이티브.
- **단점**: 내부적으로 llama.cpp 래핑이라 순수 llama.cpp/MLX 대비 20-40% 느림. 프로덕션 동시성 약함.
- **Apple Silicon 성능**: ~20-40 tok/s (8B 모델, M4 Max 기준)
- **SSE 스트리밍**: 지원 (`stream: true`)
- **추천 용도**: 개발/프로토타이핑, API 서버 빠르게 띄우기

#### llama.cpp
- **장점**: 최고의 커스터마이징. GGUF 양자화 표준. Metal(Mac)/CUDA(NVIDIA) 모두 지원. `llama-server`로 OpenAI 호환 API 제공.
- **단점**: 빌드 필요 (brew로도 가능: `brew install llama.cpp`). 모델 관리 수동.
- **MLX 백엔드**: 별도 프로젝트 (mlx-lm). llama.cpp는 Metal 백엔드 사용.
- **SSE 스트리밍**: 지원
- **추천 용도**: 성능 극대화, 벤치마킹, 커스텀 파이프라인

#### MLX (Apple 공식)
- **2026년 상태**: WWDC 2025에서 대대적 발표. `mlx-lm` 패키지로 LLM 추론/파인튜닝 모두 지원. M5 칩에서 4x TTFT 개선 발표.
- **장점**: Apple Silicon 전용 최적화 → llama.cpp 대비 **21-87% 높은 처리량**. 양자화 내장. Swift 앱 통합 가능.
- **단점**: Apple Silicon 전용 (NVIDIA 불가). 생태계 아직 성장 중.
- **성능**: 8B 모델 기준 ~230 tok/s (M4 Max, MLX 직접 실행)
- **SSE 스트리밍**: `mlx_lm.server`로 지원
- **추천 용도**: Mac에서 최고 성능이 필요할 때

#### vLLM
- **장점**: PagedAttention으로 GPU 메모리 효율 극대화. 동시 사용자 100명+ 처리. Ollama 대비 **19x 처리량**.
- **단점**: NVIDIA GPU 전용 (Mac 미지원). Python/CUDA 환경 필요. 설정 복잡.
- **SSE 스트리밍**: 지원 (OpenAI 호환 API)
- **추천 용도**: GPU 서버에서 프로덕션 서빙

#### LM Studio
- **장점**: GUI로 모델 검색/다운로드/실행 원클릭. 내장 채팅 UI. Vulkan 오프로드로 저사양 하드웨어에서도 Ollama보다 나은 성능.
- **단점**: 상업 라이선스 별도. CLI 자동화 제한적.
- **SSE 스트리밍**: 지원 (OpenAI 호환 API 내장)
- **추천 용도**: 비개발자, GUI 선호, 빠른 모델 테스트

#### Jan.ai
- **장점**: 오프라인 ChatGPT 대체. 모델 허브 + 채팅 UI + API 서버 통합. 확장(Extensions) 시스템. 대화 기록 완전 로컬.
- **단점**: tool calling 미지원 (2026 기준). 에이전트 워크플로우 제한적. 상대적으로 신생.
- **SSE 스트리밍**: 지원
- **추천 용도**: 프라이버시 중시 개인 사용, ChatGPT 대체

### 마이그레이션 전략 (추천)

```
프로토타이핑 → Ollama (간편)
    ↓ 성능 필요 시
Mac 최적화 → MLX (최고 속도)
    ↓ 프로덕션 서빙 시
GPU 서버 → vLLM (대규모 처리량)
```
