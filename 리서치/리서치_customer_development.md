## 1. Steve Blank Customer Development 4단계

Steve Blank의 Customer Development 모델은 "The Four Steps to the Epiphany" (2005)에서 체계화되었다.
핵심 전제: **스타트업은 대기업의 축소판이 아니다. 스타트업은 "반복 가능하고 확장 가능한 비즈니스 모델을 탐색하는 임시 조직"이다.**

### 1단계: Customer Discovery (고객 발견)

**목적**: "우리가 풀려는 문제가 진짜 고객의 문제인가?" 검증

**핵심 활동**:
| 단계 | 활동 | 산출물 |
|------|------|--------|
| 가설 수립 | Business Model Canvas 9블록 작성 | 초기 가설 문서 |
| 고객 인터뷰 | 최소 50-100명 대면/비대면 인터뷰 | 인터뷰 노트 |
| 문제 검증 | "이 문제를 실제로 겪는가?" 확인 | 문제-고객 적합성 판단 |
| 솔루션 검증 | Lo-fi 프로토타입으로 반응 테스트 | 솔루션 가설 수정 |

**핵심 원칙**:
- **Get Out of the Building**: 사무실에서 가설만 세우지 말고 고객을 직접 만나라
- **문제부터**: 솔루션이 아니라 문제가 존재하는지부터 확인
- **판매가 아닌 학습**: 인터뷰의 목적은 팔기가 아니라 배우기
- **Pivot or Proceed**: 가설이 틀리면 피벗, 맞으면 다음 단계

**Blank의 인터뷰 프레임워크**:
1. "이 문제에 대해 말해주세요" (개방형)
2. "지금 어떻게 해결하고 있나요?" (현재 대안)
3. "가장 힘든 점은 뭐에요?" (페인 포인트)
4. "이걸 해결해주는 서비스가 있다면 돈 내실 건가요?" (WTP 탐색)

---

### 2단계: Customer Validation (고객 검증)

**목적**: "이 솔루션에 돈을 낼 고객이 실제로 존재하는가?" 검증

**핵심 활동**:
| 단계 | 활동 | 산출물 |
|------|------|--------|
| MVP 구축 | 최소 기능 제품 개발 | 작동하는 프로토타입 |
| 초기 판매 | Earlyvangelists에게 실제 판매 시도 | 매출/전환율 데이터 |
| 판매 로드맵 | 재현 가능한 판매 프로세스 설계 | Sales Playbook |
| 비즈니스 모델 검증 | 유닛 이코노믹스 확인 | CAC, LTV, Payback 데이터 |

**핵심 개념 — Earlyvangelists (초기 전도사)**:
Steve Blank가 정의한 이상적 초기 고객의 5가지 특성:
1. 문제를 **인지**하고 있다
2. 이미 **해결책을 찾아다닌** 적이 있다
3. 자체적으로 **임시 해결책**을 만들어 쓰고 있다
4. 예산 확보 **의지/권한**이 있다
5. 불완전한 솔루션이라도 **즉시 도입**할 의향이 있다

**Pivot 기준**:
- 고객이 안 사면 → Customer Discovery로 돌아감
- 판매 프로세스가 재현 불가 → 재설계
- 유닛 이코노믹스가 안 맞으면 → 가격/비용 구조 변경

---

### 3단계: Customer Creation (고객 창출)

**목적**: 검증된 비즈니스 모델을 기반으로 수요를 대규모로 창출

**핵심 활동**:
| 활동 | 설명 |
|------|------|
| 시장 유형 판단 | 기존 시장 / 재분류 시장 / 신규 시장 중 어디인지 결정 |
| 포지셔닝 확정 | 시장 유형에 맞는 메시징/브랜딩 |
| 마케팅 실행 | 유료 채널 + 오가닉 성장 전략 |
| 스케일 준비 | 마케팅 비용 대비 고객 확보 효율 최적화 |

**Blank의 시장 유형 4가지**:
| 유형 | 특징 | 전략 |
|------|------|------|
| 기존 시장 | 경쟁자 존재, 고객이 카테고리를 앎 | 더 나은 제품으로 경쟁 |
| 재분류 시장 (니치) | 기존 시장의 세그먼트를 새로 정의 | 특정 니즈에 초집중 |
| 재분류 시장 (저가) | 기존 시장을 저가로 파괴 | 비용 혁신 |
| 신규 시장 | 카테고리 자체가 없음 | 교육 + 에반젤리즘 필요 |

---

### 4단계: Company Building (조직 구축)

**목적**: 탐색 조직 → 실행 조직으로 전환

**핵심 활동**:
| 활동 | 설명 |
|------|------|
| 조직 구조화 | 기능별 팀 구성 (마케팅, 엔지니어링, CS 등) |
| 프로세스 수립 | 반복 가능한 운영 체계 |
| 문화 정립 | 미션/비전/가치 공식화 |
| 스케일링 | 채용, 인프라, 파트너십 확장 |

## 2. 고객 검증 프로세스 (심화)

### 2-1. Mom Test (Rob Fitzpatrick, 2013)

고객 인터뷰의 바이블. 핵심: **엄마에게 물어도 거짓말 안 할 질문만 해라.**

**3가지 규칙**:
1. **그들의 삶에 대해 물어라** (당신의 아이디어에 대해 묻지 마라)
2. **구체적 과거 행동을 물어라** (미래 의향을 묻지 마라)
3. **적게 말하고 많이 들어라**

**좋은 질문 vs 나쁜 질문**:
| ❌ 나쁜 질문 | ✅ 좋은 질문 |
|-------------|-------------|
| "이런 앱 나오면 쓸 건가요?" | "마지막으로 중요한 결정을 못 해서 힘들었던 때는?" |
| "월 5,000원 내실 건가요?" | "지금 고민 상담에 돈 쓰고 있는 게 있나요?" |
| "AI가 질문을 던져주면 좋을까요?" | "고민할 때 주로 어떻게 하세요?" |
| "의사결정 정리 문서 필요하지 않나요?" | "고민 끝나고 나서 결론이 뭐였는지 기록한 적 있어요?" |

### 2-2. Lean Validation Board

| 항목 | 설명 |
|------|------|
| Customer Hypothesis | 타겟 고객은 누구인가 |
| Problem Hypothesis | 그들의 핵심 문제는 무엇인가 |
| Solution Hypothesis | 우리 솔루션이 어떻게 해결하는가 |
| Riskiest Assumption | 가장 위험한 가정은 무엇인가 |
| Experiment | 이 가정을 어떻게 테스트할 것인가 |
| Minimum Success Criteria | 성공 판단 기준은 무엇인가 |
| Result | 결과는? → Pivot or Proceed |

### 2-3. 검증 단계별 필요 표본 수

| 단계 | 표본 수 | 목적 |
|------|---------|------|
| Problem Interview | 15-30명 | 문제 존재 확인 |
| Solution Interview | 15-30명 | 솔루션 반응 확인 |
| MVP Test | 50-100명 | 사용 의향 확인 |
| Pricing Test | 30-50명 | WTP 확인 |
| 초기 판매 | 10-50명 | 실제 결제 확인 |

## 3. AI 의사결정 도우미 사업에의 적용점 분석

### 3-1. 현재 진행 상태 — Customer Development 프레임워크 매핑

```
[1단계] Customer Discovery
  ├─ ✅ 가설 수립: PRD v1 작성 완료 (2026-03-06)
  ├─ ✅ 시장 리서치: 경쟁사/시장규모/정부정책 분석 완료
  ├─ ✅ 문제 정의: "어떤 상황에 어떤 의사결정 방법을 쓸지 모른다"
  ├─ ✅ 포지셔닝 확정: 멘탈케어 + 의사결정 하이브리드 (C)
  ├─ ⚠️ 고객 인터뷰: 아직 체계적 실행 안 됨 (PRD에 "주변 5명" 수준)
  ├─ ⚠️ Earlyvangelists 식별: 미진행
  └─ ❌ Problem-Solution Fit 검증: 미완료

[2단계] Customer Validation — 아직 미진입
[3단계] Customer Creation — 미진입
[4단계] Company Building — 미진입
```

**현재 위치**: Customer Discovery 중반. 가설은 정교하나, 고객 직접 접촉이 부족.

### 3-2. Earlyvangelists 프로파일 — AI 의사결정 도우미

Steve Blank의 5가지 기준을 우리 사업에 매핑:

| Earlyvangelist 기준 | 우리 사업에서의 구체적 인물상 |
|---------------------|------------------------------|
| 1. 문제 인지 | "나 결정을 잘 못 해", "맨날 고민만 하다 시간 다 감" 자각하는 사람 |
| 2. 해결책 탐색 경험 | ChatGPT에 고민 상담해본 적 있음, 심리상담 앱 설치해본 적 있음 |
| 3. 자체 해결책 사용 중 | 친구에게 장단점 정리해달라고 함, 노트에 pros/cons 적어봄, Reddit/블라인드에 고민 게시 |
| 4. 예산 의지 | 마인드카페/트로스트 유료 전환 경험 또는 심리상담 비용(5-20만원) 이미 지불 |
| 5. 불완전해도 도입 의향 | "좀 불편해도 되니까 써볼래" — 베타 테스터 의향 |

**1순위 Earlyvangelist 세그먼트**:
- 20-30대, 진로/이직 고민 중
- ChatGPT로 고민 상담해봤으나 만족 못 함 ("장단점만 나열해줘서 여전히 모르겠음")
- 심리상담 1-2회 경험 있으나 비용/시간 부담으로 지속 불가
- **찾을 수 있는 곳**: 블라인드 이직 게시판, 에브리타임 진로 고민 글, 커리어리, 잡플래닛 리뷰어

### 3-3. 가장 위험한 가정 (Riskiest Assumptions)

Customer Development에서 가장 중요한 것은 **가장 위험한 가정부터 테스트**하는 것.

| 순위 | 가정 | 위험도 | 테스트 방법 |
|------|------|--------|-------------|
| 1 | **"사람들이 AI에게 중요한 고민을 말할 의향이 있다"** | 🔴 최고 | 랜딩페이지 + "무료 체험" CTA 클릭률 |
| 2 | **"구조화된 질문이 자유 대화보다 나은 결과를 준다"** | 🔴 높음 | A/B 테스트: ChatGPT vs Socratic 세션 → 만족도 비교 |
| 3 | **"의사결정 정리 문서에 가치를 느낀다"** | 🟡 중간 | 수동 테스트 후 NPS 측정 |
| 4 | **"월 5,000-10,000원 지불 의향이 있다"** | 🟡 중간 | Van Westendorp 가격 민감도 조사 |
| 5 | **"한 번 쓰고 끝이 아니라 반복 사용한다"** | 🟡 중간 | 베타 14일 리텐션율 측정 |

### 3-4. Customer Discovery 실행 계획 (즉시 가동용)

**Phase A: Problem Interview (1-2주)**
```
목표: 15-20명 인터뷰
채널: 지인 네트워크, 에브리타임/블라인드 DM, SNS 모집
소요: 인터뷰 1건 = 20-30분

질문 스크립트 (Mom Test 기반):
1. "최근 중요한 결정을 내려야 했던 적이 있나요? 어떤 건이었나요?"
2. "그 고민을 하면서 가장 힘들었던 점은요?"
3. "그때 어떻게 결정했어요? 누구랑 상의했어요?"
4. "ChatGPT나 AI한테 고민 상담해본 적 있어요? 어땠어요?"
5. "고민이 정리가 안 될 때, 돈 주고라도 해결하고 싶었던 적 있어요?"
6. "심리상담이나 코칭 서비스 써본 적 있어요? 왜 계속/안 계속 했어요?"
```

**Phase B: Solution Interview (2-3주)**
```
목표: 15명에게 프로토타입 시연
방법: Claude 기반 Socratic 세션 직접 시연 → 반응 관찰
핵심 관찰 포인트:
- 질문에 어떻게 반응하는가 (불편? 신기? 도움?)
- 정리 문서를 받았을 때 반응 ("오 이거 좋다" vs "굳이?")
- 끝나고 "한 번 더 하고 싶다"고 하는가
```

**Phase C: Smoke Test (3-4주)**
```
목표: 100명 랜딩페이지 유입 → 전환율 측정
방법:
- 랜딩페이지: "고민을 넣으면 질문으로 정리해주는 AI"
- CTA: "무료 체험 신청" (이메일 수집)
- 목표 전환율: 10% 이상이면 수요 존재 판단
채널: 에브리타임/블라인드 커뮤니티 포스팅, 인스타 스토리
```

### 3-5. 시장 유형 판단 — Blank 프레임워크 적용

| 시장 유형 | 우리 사업 해당 여부 |
|-----------|-------------------|
| 기존 시장 (멘탈케어 앱) | **부분 해당** — 마인드카페/트로스트 존재. 고객이 카테고리를 인지 |
| 재분류 시장 (니치) | **가장 유력** — 멘탈케어 시장 내 "의사결정 정리" 서브카테고리 신설 |
| 신규 시장 (AI 의사결정) | **위험** — "AI 의사결정" 순수 카테고리는 글로벌 수익화 사례 0건 |

**결론**: **재분류 시장 전략**이 최적.
- 멘탈케어라는 기존 시장에 진입하되
- "Socratic 질문 → 의사결정 정리 문서"라는 새로운 니치를 개척
- 포지셔닝 의사결정 기록(2026-03-07)의 결론과 일치

### 3-6. Customer Development vs 현재 팀의 갭

| 항목 | Blank 권장 | 현재 상태 | 갭 |
|------|-----------|-----------|-----|
| 고객 인터뷰 수 | 50-100명 | ~5명 (비체계적) | 🔴 심각 |
| Earlyvangelist 식별 | 명확한 프로파일 | 미정의 | 🔴 |
| Problem-Solution Fit | 데이터 기반 판단 | 직관 기반 | 🟡 |
| MVP | 최소 기능 작동 | 기술 설계 완료, 미구현 | 🟡 |
| 판매 프로세스 | 재현 가능한 플레이북 | 없음 | ⬜ (아직 단계 아님) |
| 유닛 이코노믹스 | 실 데이터 기반 | 추정치만 있음 | ⬜ (아직 단계 아님) |

## 4. 핵심 인사이트 & 즉시 실행 권고

### 인사이트 1: "빌딩 밖으로 나가라"가 최우선
- 현재 가장 큰 리스크는 기술이나 시장이 아니라 **고객 접촉 부족**
- PRD/리서치/기술 설계는 충분. 이제 고객 15명 이상 인터뷰가 급선무

### 인사이트 2: 창업자 자신이 Earlyvangelist #1
- 이상규 대표가 1년간 AI 의사결정을 실제 사용한 경험 = Earlyvangelist 5가지 조건 모두 충족
- 그러나 **N=1 편향** 위험. 자신과 다른 사용자를 반드시 만나야 함

### 인사이트 3: "의사결정"을 팔지 마라, "멘탈케어"로 진입하라
- 포지셔닝 의사결정(2026-03-07)에서 확정된 사항
- Customer Development 관점에서도 정확: 고객이 인지하는 카테고리(멘탈케어)로 진입 → 내부에서 차별화(의사결정 정리 문서) 경험하게

### 인사이트 4: Smoke Test를 MVP 전에 실행 가능
- 랜딩페이지 + CTA만으로도 수요 검증 가능
- MVP 개발 2-3개월 투자 전에 1주일 Smoke Test로 방향 확인

### 인사이트 5: B2B EAP는 Customer Validation 단계의 킬러
- Wysa/BetterUp 성공 패턴: B2B 수익이 핵심
- 기업 EAP 담당자 3명만 인터뷰해도 B2B 가능성 판단 가능
- 단, 현재 단계(Discovery)에서는 B2C 검증이 먼저
