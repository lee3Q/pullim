## 1. Lean Startup 핵심 원칙 (Eric Ries, 2011)

### 5대 원칙

| # | 원칙 | 설명 | 우리 사업 적용 |
|---|------|------|---------------|
| 1 | **Entrepreneurs are Everywhere** | 스타트업은 차고에만 있지 않음. 불확실성 속에서 새 제품/서비스를 만드는 모든 조직 | 1인 대표 + AI 에이전트 팀도 스타트업 조직 |
| 2 | **Entrepreneurship is Management** | 스타트업에도 체계적 경영이 필요 | 일일 회의 + 제안-승인 워크플로우 |
| 3 | **Validated Learning** | 고객에게서 배운 것만 진짜 학습 | 가설 → 실험 → 데이터 → 의사결정 |
| 4 | **Build-Measure-Learn** | 아이디어→제품→데이터의 피드백 루프 | MVP → 사용자 반응 측정 → 방향 조정 |
| 5 | **Innovation Accounting** | 진전을 측정하는 새로운 방법 필요 | 허영 지표(PV) 대신 행동 지표(세션 완료율) |

## 2. Build-Measure-Learn 루프

### 루프 구조

```
    IDEAS (가설)
       │
       ▼
    BUILD (최소 제품 구축)
       │
       ▼
    PRODUCT (MVP)
       │
       ▼
    MEASURE (핵심 지표 측정)
       │
       ▼
    DATA (학습 데이터)
       │
       ▼
    LEARN (검증된 학습)
       │
       ▼
    IDEAS (다음 가설) ← 루프 반복
```

### 핵심 포인트
- **역방향으로 계획**: Learn부터 → 무엇을 배워야 하는지 먼저 정의 → 측정 방법 설계 → 최소한의 빌드
- **속도가 경쟁력**: 루프를 빠르게 도는 팀이 이김. 완벽한 제품이 아니라 빠른 학습이 목표
- **배치 사이즈 축소**: 한 번에 많이 만들지 말고, 작게 만들어 빨리 검증

### 우리 사업 적용

| 단계 | 행동 | 기간 |
|------|------|------|
| **LEARN 목표** | "구조화된 Socratic 질문이 자유대화보다 의사결정 명확도를 높이는가?" | - |
| **MEASURE 설계** | 명확도 자기평가(1-10), 세션 완료율, 정리문서 공유율 | - |
| **BUILD** | Claude 기반 터미널 프로토타입 (진로/이직 특화 5개 질문) | 1주 |
| **PRODUCT** | 10명 베타 테스트 | 2주 |
| **DATA** | 완료율, 만족도, "도움됐다" 응답률 | - |
| **LEARN** | 가설 검증 → 유지/피벗/수정 결정 | - |

## 3. MVP (Minimum Viable Product)

### MVP의 정의
> "새 제품에 대해 최대한의 검증된 학습을 가능하게 하는 최소한의 노력" — Eric Ries

### MVP는 제품이 아닌 실험이다
- **목적**: 완성품이 아니라 학습 도구
- **기준**: "이 MVP로 우리의 핵심 가설을 검증할 수 있는가?"
- **함정**: 과도한 기능, 완벽주의, "이건 너무 부끄럽다"

### MVP 유형과 적용

| MVP 유형 | 설명 | 우리 사업 적합도 |
|----------|------|-----------------|
| **Concierge MVP** | 자동화 없이 수동으로 서비스 제공 | ★★★★★ 가장 적합. 이상규가 직접 Socratic 질문 |
| **Wizard of Oz MVP** | 겉은 자동, 뒤는 수동 | ★★★★☆ Claude 프롬프트로 반자동화 가능 |
| **Landing Page MVP** | 랜딩페이지로 수요 측정 | ★★★☆☆ 사전등록으로 관심도 확인 |
| **Explainer Video** | 영상으로 컨셉 설명 후 반응 측정 | ★★☆☆☆ 이 서비스는 체험해봐야 이해됨 |
| **Single Feature MVP** | 핵심 기능 하나만 구현 | ★★★★☆ Socratic 질문 + 정리문서 하나만 |
| **Piecemeal MVP** | 기존 도구 조합으로 구현 | ★★★★★ Claude API + Supabase + Vercel |

### 우리의 MVP 전략 (3단계)

**MVP 0 — Concierge (이미 시작됨)**
- 이상규가 직접 3명에게 수동 Socratic 질문
- 도구: 종이+펜, 카카오톡
- 검증: "구조화된 질문이 도움이 되는가?"

**MVP 1 — Wizard of Oz**
- Claude 프롬프트 기반 터미널 챗봇
- 이상규가 프롬프트 조율하며 실시간 개입
- 검증: "AI가 해도 효과가 유지되는가?"

**MVP 2 — Single Feature + Piecemeal**
- Next.js + Claude API 웹앱
- 자동 라우팅 + Socratic 질문 + 정리문서
- 검증: "낯선 사용자가 혼자 쓸 수 있는가? 돈을 내는가?"

## 4. Validated Learning (검증된 학습)

### 허영 지표 vs 행동 지표

| 허영 지표 (쓸모없음) | 행동 지표 (진짜) |
|---------------------|-----------------|
| 방문자 수 (PV) | **세션 완료율** (끝까지 하는 비율) |
| 다운로드 수 | **활성 사용자 비율** (DAU/MAU) |
| SNS 좋아요 | **정리문서 공유율** (가치를 느낀 증거) |
| 가입자 수 | **재사용률** (7일 내 재방문) |
| 총 매출 | **코호트별 리텐션** (시간에 따른 잔존) |

### 우리의 핵심 지표 (One Metric That Matters)

**초기 단계: 세션 완료율**
- 왜: Socratic 질문을 끝까지 답하는지 = 가치 제공의 가장 직접적 증거
- 목표: 70% 이상 (시작한 사람 중 정리문서까지 도달)

**성장 단계: 7일 재사용률**
- 왜: 한 번 쓰고 마는 건 바이럴 불가. 반복 사용 = 진짜 가치
- 목표: 30% 이상

## 5. Pivot (방향 전환) 기준

### Pivot의 정의
> "전략의 근본적 변경을 가설 검증에 기반하여 실행하는 것" — 포기가 아니라 학습에 의한 전환

### Pivot 유형 (Eric Ries의 10가지)

| Pivot 유형 | 설명 | 우리 시나리오 |
|-----------|------|-------------|
| **Zoom-in Pivot** | 하나의 기능이 전체 제품이 됨 | 정리문서만 따로 제품화 |
| **Zoom-out Pivot** | 전체 제품이 하나의 기능이 됨 | 멘탈케어 종합 앱의 한 기능으로 흡수 |
| **Customer Segment Pivot** | 다른 고객 세그먼트로 전환 | B2C → B2B (기업 EAP) |
| **Customer Need Pivot** | 같은 고객, 다른 문제 | 의사결정 → 감정 정리 → 습관 코칭 |
| **Platform Pivot** | 앱 → 플랫폼 | 단일 앱 → 의사결정 프레임워크 마켓플레이스 |
| **Business Architecture Pivot** | B2C ↔ B2B | 개인 구독 → 기업 계약 (Wysa 사례) |
| **Value Capture Pivot** | 수익 모델 변경 | 구독 → 세션당 과금 or 기업 라이센스 |
| **Engine of Growth Pivot** | 성장 엔진 변경 | 바이럴 → 유료 광고 → SEO |
| **Channel Pivot** | 유통 채널 변경 | 웹앱 → 카카오 미니앱 → 네이버 커넥트 |
| **Technology Pivot** | 기술 변경 | Claude → GPT → 자체 모델 |

### Pivot 판단 기준 (데이터 기반)

```
┌─────────────────────────────────────────────┐
│ PIVOT 신호 (2개 이상이면 심각하게 검토)       │
├─────────────────────────────────────────────┤
│ □ 세션 완료율 < 40% (3주 연속)               │
│ □ 7일 재사용률 < 10%                         │
│ □ NPS < 20                                   │
│ □ "돈 낼 의향" 설문 < 15%                    │
│ □ 3개월간 유료 전환 0건                       │
│ □ 사용자 인터뷰에서 "필요없다" 반복           │
│ □ B-M-L 루프 5회 돌았는데 핵심 지표 개선 없음 │
└─────────────────────────────────────────────┘
```

### Pivot vs Persevere 판단 프레임워크

| 상황 | 판단 | 행동 |
|------|------|------|
| 지표는 낮지만, 사용한 사람은 열광 | **Persevere** | 더 많은 사람에게 도달하는 방법 찾기 |
| 많이 쓰지만, 아무도 돈 안 냄 | **Value Capture Pivot** | 수익 모델 실험 |
| 진로 고민은 쓰는데, 관계 고민은 안 씀 | **Zoom-in Pivot** | 진로 특화로 좁히기 |
| 개인은 안 쓰는데, 기업 HR이 관심 | **Customer Segment Pivot** | B2B로 전환 |
| 세션 중간에 다 이탈 | **기능 개선** (아직 Pivot 아님) | 질문 순서/톤 조정 |
| 아무 지표도 안 움직임 | **Pivot 필요** | 전면 재검토 |

## 6. Innovation Accounting (혁신 회계)

### 3단계 프로세스

**1단계: 기준선 확립 (Baseline)**
- MVP 출시 → 현재 상태의 실제 지표 확보
- "세션 완료율이 45%다" = 이것이 기준선

**2단계: 엔진 튜닝 (Tuning)**
- 가설 기반으로 개선 실험 → 기준선에서 이상(Ideal) 방향으로 이동
- "질문 톤을 바꿨더니 완료율 55%로 올랐다"

**3단계: Pivot or Persevere**
- 튜닝으로 충분히 개선되고 있는가?
- 개선 속도가 이상에 수렴하는가, 정체하는가?

### 코호트 분석 (우리 제품 적용)

| 코호트 | 측정 | 목표 |
|--------|------|------|
| Week 1 가입자 | 세션 시작률 | > 80% |
| Week 1 가입자 | 세션 완료율 | > 60% |
| Week 1 가입자 | 7일 재사용 | > 20% |
| Week 1 가입자 | 30일 잔존 | > 10% |
| 유료 전환 | 무료→유료 | > 3% |

## 7. 추가 Lean 원칙: 우리에게 특히 중요한 것들

### 7-1. Genchi Gembutsu (현장에 가라)
- **원칙**: 데이터만 보지 말고 실제 사용자를 관찰하라
- **적용**: 이상규 본인이 직접 사용자와 Socratic 세션 진행. 화면 녹화. 어디서 막히는지 관찰.

### 7-2. Small Batch (작은 배치)
- **원칙**: 한 번에 10개 기능 만들지 말고, 1개 만들어 검증
- **적용**: MVP에 7단계 파이프라인 전부 넣지 말 것. CLARIFY + EVALUATE + DECIDE 3단계만 먼저.

### 7-3. Five Whys (5 Whys)
- **원칙**: 문제 발생 시 "왜?"를 5번 반복하여 근본 원인 도달
- **적용**: "세션 완료율이 낮다" → 왜? → "질문이 어렵다" → 왜? → "전문 용어가 많다" → 왜?... → 근본 원인 해결

### 7-4. Leap of Faith Assumptions (믿음의 도약 가정)
두 가지 핵심 가정을 반드시 검증해야 한다:

| 가정 | 내용 | 우리 사업 | 검증 방법 |
|------|------|-----------|-----------|
| **Value Hypothesis** | 고객이 가치를 느끼는가? | "Socratic 질문 + 정리문서가 자유 대화보다 의사결정에 도움이 된다" | Concierge MVP → 사용자 피드백 |
| **Growth Hypothesis** | 어떻게 성장하는가? | "만족한 사용자가 정리문서를 공유하여 바이럴이 발생한다" | 정리문서 공유 링크 클릭률 |

## 8. 성장 엔진 (Engine of Growth)

### 3가지 성장 엔진

| 엔진 | 메커니즘 | 핵심 지표 | 우리 적합도 |
|------|---------|-----------|------------|
| **Sticky (점착)** | 높은 리텐션 | 이탈률 < 신규 유입률 | ★★★★☆ 히스토리 축적 = lock-in |
| **Viral (바이럴)** | 사용자가 사용자를 데려옴 | Viral Coefficient > 1 | ★★★★★ 정리문서 공유 = 자연 바이럴 |
| **Paid (유료)** | LTV > CAC | LTV/CAC > 3 | ★★★☆☆ 초기에는 유료 광고 비효율 |

### 우리의 성장 전략
1. **1차**: Viral — 정리문서 공유 링크에 서비스 소개 삽입
2. **2차**: Sticky — 의사결정 히스토리 + 패턴 분석으로 이탈 방지
3. **3차**: Paid — PMF 확인 후 키워드 광고 (심리상담앱, 멘탈케어앱)

## 9. Lean Startup을 우리 사업에 적용한 실행 로드맵

| 주차 | B-M-L 단계 | 행동 | 판단 기준 |
|------|-----------|------|-----------|
| W1 | Build | Concierge MVP (수동 Socratic 3명) | - |
| W2 | Measure | 만족도, "결정에 도움됐나" | 3명 중 2명 이상 긍정 |
| W2 | Learn | Value Hypothesis 검증 | 통과 → W3, 실패 → 질문 세트 재설계 |
| W3-4 | Build | Claude 기반 프로토타입 | - |
| W5-6 | Measure | 세션 완료율, 재사용률 (10-20명) | 완료율 > 60%, 재사용 > 20% |
| W6 | Learn | Growth Hypothesis 초기 검증 | 통과 → W7, 실패 → Pivot 검토 |
| W7-8 | Build | 웹 MVP (Next.js + Claude API) | - |
| W9-12 | Measure | 코호트 분석, NPS, 유료 전환 | NPS > 30, 유료 전환 > 3% |
| W12 | Learn | PMF 판단 | Pivot or Scale |

## 10. 기존 자료와의 연결

### PRD v1 (3/6)과의 정합성
- PRD의 "검증해야 할 가설 4가지"는 Lean의 Leap of Faith Assumptions와 정확히 일치
- PRD의 MVP 정의는 적절하나, **Concierge MVP(수동 테스트)를 MVP 0로 추가해야 함**

### 리서치 종합 (3/7)과의 시사점
- "AI 의사결정 순수 카테고리 돈 번 사례 = 0건" → **Value Hypothesis가 미검증 상태**
- 멘탈케어 하이브리드 포지셔닝은 Customer Segment Pivot의 사전 적용
- Woebot 실패(FDA 규제) → 웰니스 포지셔닝은 Lean의 "규제 리스크 최소화" 원칙과 합치

### 포지셔닝 의사결정 (3/7)과의 시사점
- "감정 정리하러 왔는데, 결정까지 됐다" = **Zoom-out Pivot 가능성** 미리 설계한 것
- B2B EAP 수익 모델 = Business Architecture Pivot 옵션 확보

## 11. 핵심 요약: 팀이 기억해야 할 10가지

1. **MVP는 제품이 아니라 실험이다** — 완벽하지 않아도 배울 수 있으면 된다
2. **역방향 계획** — "무엇을 배울 것인가?"부터 시작
3. **속도 > 완성도** — B-M-L 루프를 빠르게 도는 것이 경쟁력
4. **허영 지표에 속지 마라** — PV, 다운로드 수는 의미없음. 완료율, 재사용률이 진짜
5. **Concierge부터 시작** — 코딩 전에 수동으로 검증
6. **Pivot은 실패가 아니라 학습** — 데이터가 말해주면 방향을 바꿔라
7. **한 번에 하나만 테스트** — 변수를 통제해야 뭐가 효과인지 안다
8. **현장에 가라** — 대시보드만 보지 말고, 사용자가 쓰는 걸 직접 봐라
9. **Five Whys** — 문제의 표면이 아니라 근본 원인을 파라
10. **Pivot 기준을 사전에 정해라** — 감정적 판단이 아닌 데이터 기반 판단
