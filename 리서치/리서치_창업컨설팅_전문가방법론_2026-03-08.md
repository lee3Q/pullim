## 1. 핵심 창업 방법론 6대 프레임워크

### 1-1. 린 스타트업 (Lean Startup) — Eric Ries

**핵심 원리:**
- **Build-Measure-Learn** 반복 루프: 가설 → 최소 제품(MVP) → 측정 → 학습 → 피벗 or 지속
- **Validated Learning**: 추측이 아닌 실험으로 검증된 학습만 인정
- **MVP (Minimum Viable Product)**: 가설 검증에 필요한 최소 기능만 구현
- **피벗 (Pivot)**: 핵심 가설이 틀렸으면 방향 전환, 전체 포기가 아님
- **Innovation Accounting**: 전통 재무지표 대신 학습 속도/전환율/활성화율 추적

**AI 의사결정 도우미 적용:**
- MVP = Socratic 질문 5-7개 + 정리 문서 생성 (이미 PRD에 반영됨 ✓)
- 측정 지표: "정리 문서 도움 됐나" 만족도, 재방문율, 세션 완료율
- 피벗 시나리오: Socratic이 사용자에게 어렵다면 → 더 가이드된 선택지 방식으로 전환

**대표 저서:** 《The Lean Startup》(2011), 《The Startup Way》(2017)

---

### 1-2. 고객 개발 (Customer Development) — Steve Blank

**핵심 원리:**
- **4단계 모델**: Customer Discovery → Customer Validation → Customer Creation → Company Building
- **"Get out of the building"**: 사무실에서 제품 만들지 말고, 고객에게 나가서 물어봐라
- **비즈니스 모델 캔버스**: 9개 블록으로 사업 모델 전체를 한 장에 시각화
- **Problem-Solution Fit → Product-Market Fit**: 문제가 진짜 존재하는지 먼저 검증
- **Earlyvangelists**: 문제를 알고, 해결책을 찾고 있고, 돈을 쓸 의향이 있는 초기 고객

**AI 의사결정 도우미 적용:**
- Customer Discovery: "고민 상담에 AI를 쓸 의향이 있는가?" → 주변 5명 테스트 (이미 계획 ✓)
- Earlyvangelist 프로필: 멘탈케어 앱 이미 사용 중인 20-30대, 심리상담 경험자
- 비즈니스 모델 캔버스 작성 필요 (팀 빌딩 후 첫 과제로 적합)

**대표 저서:** 《The Four Steps to the Epiphany》(2005), 《The Startup Owner's Manual》(2012)

### 1-3. Y Combinator 방법론 — Paul Graham, Sam Altman 등

**핵심 원칙 (YC Motto: "Make something people want"):**
- **Do Things That Don't Scale**: 초기엔 자동화 하지 마라. 직접 고객 만나고 수동으로 해라
- **Talk to Users**: 사용자와 대화가 모든 것의 시작
- **Launch Early, Iterate**: 완벽한 제품 대신 빨리 출시하고 반복
- **Default Alive vs Default Dead**: 현재 성장률+비용으로 생존 가능한가? 매주 점검
- **Weekly Growth Rate**: 주간 5-7% 성장이 좋은 스타트업의 기준
- **Founder-Market Fit**: 창업자가 이 문제를 풀기에 가장 적합한 사람인가?

**Paul Graham 핵심 에세이들:**
- "Do Things That Don't Scale" (2013) — 초기 성장의 핵심
- "How to Get Startup Ideas" (2012) — 아이디어는 관찰에서
- "Startup = Growth" (2012) — 성장이 스타트업을 정의
- "Be Good" (2008) — 사용자에게 좋으면 사업도 된다
- "The 18 Mistakes That Kill Startups" (2006)

**Sam Altman (전 YC 대표) 핵심 강의:**
- "How to Start a Startup" (Stanford CS183B, 2014) — 20강 무료 공개
- 핵심: 아이디어 → 제품 → 팀 → 실행 순서

**AI 의사결정 도우미 적용:**
- Founder-Market Fit ✓: 이상규 = 1년간 AI 의사결정 실사용자, 비개발자 관점 보유
- Do Things That Don't Scale: 초기엔 수동 Socratic 인터뷰 직접 수행 (이미 계획 ✓)
- Default Alive 점검: LLM API 비용 vs 수익 매주 체크 필요

### 1-4. 제로 투 원 (Zero to One) — Peter Thiel

**핵심 원리:**
- **0 to 1 vs 1 to N**: 기존 것 복제(1→N)가 아니라 새로운 것 창조(0→1)
- **독점(Monopoly)**: 경쟁은 패배자의 게임. 작은 시장에서 독점 → 확장
- **비밀(Secret)**: "대부분의 사람이 동의하지 않는, 당신만 아는 중요한 진실"
- **Last Mover Advantage**: 먼저 진입이 아니라 마지막까지 살아남는 게 중요
- **7가지 질문 (Thiel's 7 Questions)**:
  1. 기술: 점진적 개선이 아닌 획기적 기술인가?
  2. 타이밍: 지금이 맞는 타이밍인가?
  3. 독점: 작은 시장에서 큰 점유율로 시작하는가?
  4. 사람: 맞는 팀인가?
  5. 유통: 만드는 것뿐 아니라 팔 방법이 있는가?
  6. 지속성: 10-20년 후에도 방어 가능한가?
  7. 비밀: 남들이 못 보는 기회를 발견했는가?

**AI 의사결정 도우미 적용:**
- 비밀: "AI 의사결정 도구는 아무도 돈 벌지 못했다. 하지만 멘탈케어 + 의사결정 정리 문서 결합은 아무도 안 했다."
- 독점 시작점: 한국 멘탈케어 앱 시장 (MAU 16만, 아직 초기) + Socratic 방법론 차별화
- 지속성: 의사결정 히스토리 축적 = 네트워크 효과 없이도 개인 데이터 lock-in
- Thiel 7 질문 점검은 팀 빌딩 후 전략 회의 아젠다로 적합

**대표 저서:** 《Zero to One》(2014)

### 1-5. 디자인 씽킹 (Design Thinking) — IDEO / Stanford d.school

**핵심 원리 (5단계):**
1. **Empathize (공감)**: 사용자 관찰, 인터뷰, 감정 이해
2. **Define (정의)**: 핵심 문제를 한 문장으로 정의 (Point of View)
3. **Ideate (아이디어)**: 제약 없이 브레인스토밍, 다양한 해결책
4. **Prototype (프로토타입)**: 빠르고 저렴하게 만들어 보기
5. **Test (테스트)**: 사용자에게 보여주고 피드백 받기

**특징:**
- 인간 중심(Human-Centered Design)
- 실패를 학습으로 재정의
- 비선형: 5단계를 순서대로가 아니라 반복적으로

**AI 의사결정 도우미 적용:**
- Empathize: "고민 앞에서 고통받는 사용자"의 실제 감정을 이해 (이상규 본인 경험 ✓)
- Define: "좋은 의사결정 방법은 있지만 일반인이 어떤 걸 쓸지 모른다" (PRD에 정의됨 ✓)
- Prototype: Claude 기반 터미널 프로토타입 → 빠른 검증 (옵션 B 계획 ✓)

### 1-6. Jobs-to-be-Done (JTBD) — Clayton Christensen / Tony Ulwick

**핵심 원리:**
- 사람들은 제품을 사는 게 아니라 **"할 일(Job)"을 해결하기 위해 "고용(Hire)"**한다
- "밀크쉐이크는 왜 팔리는가?" → 통근 중 지루함 해소 + 점심까지 배 안 고프게
- **기능적 Job + 감정적 Job + 사회적 Job** 세 가지 차원
- 경쟁 = 같은 카테고리가 아니라 같은 Job을 해결하는 모든 대안

**AI 의사결정 도우미의 JTBD:**
- 기능적: "내 고민을 정리해서 결정할 수 있게 해줘"
- 감정적: "이 불안에서 벗어나고 싶어" / "누군가 들어줬으면"
- 사회적: "현명한 결정을 내리는 사람이고 싶어"
- 현재 대안(경쟁): 친구에게 물어보기, 혼자 반추, ChatGPT 자유대화, 유료 심리상담
- 이 분석은 팀 CXO/마케팅 에이전트의 초기 과제로 적합

## 5. 핵심 인사이트 — 팀 설계에 반영할 점

### 인사이트 1: "리서치 → 실행" 전환 속도가 핵심
- 린 스타트업 + YC 모두 강조: **빨리 만들어서 빨리 보여줘라**
- 팀 에이전트는 리서치만 하는 게 아니라 실행 계획까지 출력해야 함
- → 에이전트 프롬프트에 "분석 결과는 반드시 실행 가능한 다음 행동 1-3개로 마무리" 규칙 삽입

### 인사이트 2: Customer Development는 대표가 직접 해야 한다
- Steve Blank: 초기 고객 인터뷰는 위임하면 안 됨. 창업자가 직접.
- → 대표(이상규)의 역할에 "고객 인터뷰 직접 수행"을 필수로 포함
- → 에이전트 팀은 인터뷰 질문 설계/분석 지원

### 인사이트 3: "비밀(Secret)"이 이 사업의 핵심 방어선
- Thiel의 비밀: "멘탈케어에 온 사람에게 의사결정 정리 문서를 주면 만족도가 폭발한다"
- 이건 아직 검증 안 됨 → MVP에서 반드시 측정
- → 팀 OKR에 이 가설 검증을 Q1 핵심 목표로 설정

### 인사이트 4: 한국 생태계 활용 전략이 필요
- 정부 예산 3.4조(창업) + 240억(AI 심리케어)이 있음
- TIPS, 창업동아리, 예비창업패키지 등 순차 공략
- → 팀에 "정부 지원사업 전문가" 역할 or 정기 리서치 태스크 필요

### 인사이트 5: 실패 패턴을 피하는 게 성공보다 중요
- Woebot ($129M 펀딩 → 폐쇄): 규제 정면 돌파 실패
- Pi ($1.5B → MS acqui-hire): 수익 모델 없음
- Character.AI (28M MAU → 낮은 ARPU): B2C only + 무료 의존
- → **우리의 원칙**: 웰니스 포지셔닝(규제 회피), 초기부터 유료 모델 설계, B2B 파이프라인 조기 탐색
