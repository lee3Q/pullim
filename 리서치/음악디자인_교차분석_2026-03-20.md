## 1. 도트 아트 — 양쪽 일치

| 항목 | Gemini | Perplexity | 결론 |
|------|--------|-----------|------|
| **추천 도구** | FLUX.1 Schnell + ControlNet + LoRA | Stable Diffusion + 픽셀 LoRA + Aseprite 플러그인 | **Stable Diffusion/FLUX 생태계가 정답** |
| **Aseprite 연동** | PixelLab.ai, Sprite AI 등 특화 도구 | PixelAI(무료), PixelForgeAI(MIT) | **Aseprite + AI 플러그인 = 하이브리드 워크플로우** |
| **일관성 유지** | ControlNet Canny + 앵커 이미지 + LoRA | 모델+LoRA+프롬프트+시드 고정 | **구조적 제어가 핵심** (프롬프트만으론 부족) |
| **Midjourney** | 언급 없음 | 컨셉/배경용은 좋지만 스프라이트 파이프라인엔 부적합 | **우리 용도엔 비추** |
| **DALL-E 3** | 언급 없음 | Aseprite 연동 있고 라이선스 깔끔 | **보조 도구로 가능** |
| **라이선스** | FLUX.1 Dev 상업 금지 ⚠️, Schnell은 Apache 2.0 OK | SD 1.5/SDXL CreativeML OK, SD3 소규모 무료 | **FLUX.1 Schnell 또는 SD 1.5/SDXL이 안전** |

### 불일치/보완 지점
- Gemini는 **FLUX.1 생태계**를 중심으로 설명 (2026년 최신 트렌드)
- Perplexity는 **Stable Diffusion + Aseprite 실무 스택** 중심 (더 실용적)
- **결론**: 둘 다 맞음. FLUX.1 Schnell이 최신이지만, SD + LoRA가 커뮤니티/자료가 더 풍부. **MVP는 SD + 픽셀 LoRA + Aseprite**, 여유 되면 FLUX.1 Schnell로 마이그레이션.

| **스템 분리** | Suno Generate Stems → 동적 오디오 가능 | 언급 없음 | **Gemini만 언급 — 중요한 포인트** |
| **Stable Audio** | Web Audio API 구현까지 상세 기술 | BGM+SFX 통합 가능, 라이선스 안전 | **장기 대안** |
| **라이선스** | 양쪽 동일: 무료=비상업, 유료=상업 OK | 동일 | **Pro/유료 플랜 필수** |

### 불일치/보완 지점
- Gemini가 **프롬프트 엔지니어링 3레이어**(기본/가사/루프퍼스트)를 상세히 설명 — 실전에서 유용
- Gemini가 **Suno v4 Sounds 기능 + 스템 분리**를 구체적으로 설명 — Perplexity에는 없음
- **결론**: Suno v4의 새 기능(Sounds, Stems)을 적극 활용. Gemini의 프롬프트 전략을 따름.

| **라이선스** | — | 유료 플랜에서 상업 OK, SFX 팩 판매는 금지 | **웹앱 임베드는 OK** |

### 보완 지점
- Gemini는 SFX 도구보다 **Web Audio API 구현 아키텍처**에 집중 (AudioContext, GainNode, DynamicsCompressor)
- Perplexity는 **어떤 도구로 SFX를 만들지**에 집중
- **결론**: 도구는 Perplexity 추천(ElevenLabs), 구현은 Gemini의 Web Audio API 패턴

## 4. Web Audio API — Gemini만 상세

Gemini가 제공한 핵심 구현 패턴:

```
AudioBufferSourceNode (개별 소스, 일회용)
  → GainNode (개별 볼륨)
    → GainNode (마스터 버스)
      → DynamicsCompressorNode (클리핑 방지)
        → AudioDestinationNode (스피커)
```

- **AudioContext 하나만** 생성 (여러 개 = 타이밍 동기화 불가 + 에러)
- **Autoplay Policy 대응**: 사용자 첫 클릭에서 `audioContext.resume()` 필수
- **fetch + decodeAudioData** 패턴으로 비동기 로딩
- 기술스펙 (A6)의 SoundManager 설계와 정확히 일치 — 바로 구현 가능

## 6. 저작권 주의사항

**양쪽 모두 강조한 것:**
1. "in the style of [아티스트명]" 프롬프트 금지
2. AI 초안 + 인간 마감 = "하이브리드 워크플로우"가 법적으로 안전
3. 미국 저작권청: 순수 AI 생성물은 저작권 등록 불가, 인간 기여 필요
4. Steam 배포 시 추가 리스크 (라이선스 증명 요구) — 웹앱은 상대적으로 안전

**풀림 대응:**
- 도트 아트: AI 생성 후 Aseprite에서 수동 보정 → 인간 기여 확보
- BGM: AI 생성 후 DAW에서 루프 편집/믹싱 → 인간 기여 확보
- 사용 도구/플랜/날짜 기록 유지 (라이선스 감사 대비)
