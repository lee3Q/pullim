# AI 불쾌/불편 사례집

```yaml
업데이트_주기: 발생 시마다 추가
마지막_업데이트: 2026-03-11
트리거_조건: "불쾌 경험 발생 즉시, 분기 정리"
불확실성_항목: []
```

## 핵심 프레임

**불쾌** = 사용 여부를 결정하는 수준. 이탈 원인.
**불편** = 만족도를 낮추는 수준. 사용은 계속함.

> 불편은 후순위. 불쾌 제거가 먼저.

---

## 불쾌 사례 (치명도 순)

### 1. 맥락 소실 + 반복 작업 강요
- **상황**: 창업 신청서 작업 중 AI가 이전 맥락을 잃고 중복 내용 생성, 데이터 혼재
- **불쾌 이유**: "AI로는 이걸 끝까지 못 하겠다"는 신뢰 붕괴
- **하네스 대응**: 세션 맥락 파일 운영, 핵심 결정사항 별도 기록
- **풀림 적용**: 세션 중 맥락 체크포인트 명시. 이전 대화 핵심 요약 노출

### 2. 확신 오류 ("없어" 단정)
- **상황**: 방법이 있었는데 "그런 방법은 없다"고 단정
- **불쾌 이유**: 사용자가 이미 더 많이 알고 있을 때 발생. 신뢰 역전
- **하네스 대응**: CLAUDE.md "불가능 금지" 규칙 박음. 방법 먼저 찾기
- **풀림 적용**: "확실하지 않다"를 명시하는 응답 패턴

### 3. 과거 데이터 사실화
- **상황**: 최신 정보가 없는 영역을 현재인 것처럼 답변
- **불쾌 이유**: 믿고 썼다가 틀림. 이중 피해
- **하네스 대응**: 지식 사전에 업데이트 주기 + 불확실성 항목 명시
- **풀림 적용**: 날짜 기반 정보는 출처/시점 병기

### 4. 할루시네이션
- **상황**: 존재하지 않는 데이터/인물/근거 생성
- **불쾌 이유**: 가장 원론적이나 여전히 치명적
- **하네스 대응**: 검증 에이전트 도입, 반박 루프
- **풀림 적용**: 사실 주장 시 근거 요구 레이어

### 5. 톤 불일치 (급박할 때 장문)
- **상황**: 사용자가 시간 압박 상황인데 긴 설명 나열
- **불쾌 이유**: 정서적 엇박자. "이게 내 상황을 모른다"
- **풀림 적용**: 감정 온도 감지 후 응답 길이/톤 조정

---

## 불편 사례 (참고용, 후순위)

- 응답 속도 느림
- 포맷 미흡 (줄바꿈 등)
- 요약이 약간 부정확
- 한국어/영어 혼용 어색

---

## 풀림 온보딩 아이디어 (2026-03-11)

> "평소 맘에 안 드는 사람이나 피하고 싶은 사람의 특징을 생각해보신 적 있나요?"

사용자가 싫어하는 사람 특징 → 불쾌 프로파일 추출 → AI 응답 규칙 변환
직접 "뭐가 불편해요?" 보다 솔직하고 구체적인 답 나옴.
반박: 이 방식이 불편감을 온보딩에서 유발할 수 있음 → 부드러운 프레이밍 필요
수정: "어떤 대화가 에너지를 빼앗나요?" 정도로 완화 가능

## 반박 기록
- "불쾌/불편 구분이 주관적" → 맞음. 사용자별 다름. 따라서 프로파일화가 해법
- "할루시네이션은 모델 수준 문제" → 맞음. 하지만 하네스로 노출 빈도 줄일 수 있음
