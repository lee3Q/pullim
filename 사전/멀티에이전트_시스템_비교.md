## Tycono

- **GitHub**: https://github.com/seongsu-kang/tycono
- **한 줄 정의**: "Company-as-Code" — YAML/Markdown으로 조직 정의, AI 에이전트들이 계층 구조 안에서 자율 작동하는 오픈소스 플랫폼
- **실행**: `npx tycono` (로컬, 클라우드 의존 없음)
- **엔진**: Claude CLI를 subprocess로 실행. Claude Code 위에 Claude Code가 올라타는 구조
- **개발 속도**: 2026-03-03 출시, 12일 만에 beta.6. 하루 5~10 커밋

### 핵심 개념

- **Wave**: CEO가 작업 던지면 CEO→CTO→팀원으로 재귀 위임. 자동 완료.
- **Authority Validator**: 역할별 권한 범위를 코드 레벨에서 강제
- **Knowledge Gate**: 역할별 마크다운 지식베이스 읽기/쓰기 접근 제어
- **SSE 멀티플렉싱**: 여러 에이전트 실시간 스트림을 단일 채널로 병합
- **Token Ledger**: API 비용 실시간 추적
- **Git Save**: 작업 결과 자동 git commit
- **RPG 오피스 뷰**: 픽셀아트 사무실에서 에이전트 활동 시각화
- **에이전트 루프**: 최대 20턴, 재귀 위임 깊이 ≤ 3

## 내 시스템(풀림 창업팀)과 비교

### 내가 더 나은 것

| 항목 | 이유 |
|------|------|
| 도메인 특화 | 풀림 창업 컨텍스트(한국 시장, 코칭, 규제) 깊게 반영. tycono는 범용 인프라 |
| 세션 연속성 | 세션_맥락.md로 다음 세션 이어받기. tycono에 없음 |
| 컨텍스트 최소화 | 팀원에게 필요한 맥락만 전달 (토큰 효율). tycono는 전체 CLAUDE.md 주입 |
| 안전 거부권 | 최서영 Veto 시스템 명확. tycono 없음 |
| 인간 개입 트리거 | 대표 개입 시점 5가지 명확 정의 |

### 내가 부족한 것

| 항목 | tycono 방식 | 현재 내 방식 |
|------|------------|------------|
| 자율성 | Wave 한 번 → 자동 완료 | 대표 매번 관여 필요 |
| 계층 위임 | CEO→CTO→팀원 재귀 (코드) | COS가 모든 팀원 직접 소환 |
| 권한 강제 | 코드 레벨 authority-validator | 프롬프트 "안 하는 것" 선언뿐 |
| 지식 접근 제어 | Knowledge Gate | 경로 명시만, 제어 없음 |
| 비용 추적 | token-ledger 실시간 | 없음 |
| 관찰성 | 픽셀아트 UI + 실시간 스트리밍 | 텍스트 보고만 |

### 적용 가능한 개념 (현실적)

1. **Knowledge Gate 개념** → team_state.yaml에 팀원별 접근 가능 파일 목록 추가
2. **계층 위임** → PM이 받은 안건을 CTO에게 서브태스크로 내리는 구조 실험
3. **비용 기록** → 세션 종료 시 토큰 사용량 세션_맥락.md에 메모하는 습관

**적용 불필요**: 픽셀아트 UI, subprocess 실행, git auto-commit (ROI 없음)
