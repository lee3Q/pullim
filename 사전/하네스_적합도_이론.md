## 하네스 엔지니어링 정의

AI 모델 주변에 환경·규칙·피드백 루프를 설계하는 작업.
모델 = 두뇌, 하네스 = 신체·운영 체계.

프롬프트 엔지니어링 → 컨텍스트 엔지니어링 → 하네스 엔지니어링 순으로 진화.
"어떤 모델인가"보다 "어떤 하네스인가"가 성능을 결정하는 시대.

---

## 적합도 함수 문제

**절대 적합도** (인간 판단 기준)
- 미래에 바뀜. 의존하면 표류.
- 결국 모델 성능의 기준은 인간 → 인간 기준이 변하면 함수도 변해야 함

**상대 적합도** (이전 자신보다 나아졌는가)
- 계산 가능, 절대 기준 불필요
- "어제보다 판단이 더 일관적이고 덜 틀렸는가"

반박: 로컬 최대값에 갇힌다. 전역 최적 도달 불가.
해결: 탐색(exploration) 비율 자체를 AI가 결정해야 함 (epsilon-greedy 개념)

## 자율 AI 비전 (이상규 정의)

> "나는 어떻게 작동할 때 최고인가를 스스로 찾아나가는 AI"
> "규제조차 스스로 하게 만드는 방식"
> "10만 개 모델이 같이 살면 어떤 규칙이 창발되는가"

핵심 문제: 자기참조 시스템은 불변 상수 없이 불안정.
제안: 상수 = "더 나은 판단을 했는가를 스스로 측정하는 메타인지 레이어"

## 네거티브 앵커 기법 (2026-03-11 발견)

사용자가 "뻔한 출력"을 미리 예측 → AI가 그것을 회피 타깃으로 삼음.
"좋은 답을 해라"보다 "이런 답은 가치 없다"가 더 효과적.

풀림 적용: 온보딩에서 사용자 싫어하는 패턴 수집 → 응답 규칙 네거티브 앵커로 사용.
