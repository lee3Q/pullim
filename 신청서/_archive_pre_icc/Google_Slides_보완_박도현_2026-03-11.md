슬라이드 제목: 진행 과정

슬라이드 레이아웃: 좌에서 우로 흐르는 5단계 수평 프로세스 바(progress bar) 형태로 구성한다. 각 단계를 둥근 사각형 박스로 표현하고 화살표로 연결한다.

각 단계 내용 및 상태:

1단계 — 문제/대안 검증 [완료]

2단계 — 솔루션 검증(낮은 수준 MVP) [진행 중 ← 현재 위치]
- 진행 중 표시: Warm Coral(#E8856C) 또는 하이라이트 색상으로 강조. "현재 위치" 라벨 또는 화살표 마커 추가.
- 내용: v1 테스트 2회 완료. v2 테스트 1회 완료 (정지원: WTP 월 1~3만원). 데모 배포: pullim.vercel.app

3단계 — 제품/서비스 검증(높은 수준 MVP) [예정]
- 미완료 표시: 쿨 그레이(#9B9EA3) 배경
- 내용: 웹앱 프로토타입 (4~5월)

4단계 — 수익모델 검증 [예정]
- 미완료 표시: 쿨 그레이(#9B9EA3) 배경
- 내용: 유료 전환 테스트 (5~6월)

5단계 — 핵심지표/채널/재무 타당성 검증 [예정]

하단 1줄 강조 박스 추가 (Warm Coral 또는 Primary 배경):
> v2 테스트: "구성 자체가 좋다", "AI 구조적 정리가 오히려 좋았다", WTP 월 1~3만원 확인

## 4. 스토리라인 완결성 검토

### 현재 19장 순서 논리 분석

```
현재: 표지→창업계기→페르소나→고객분포→Before/After→5단계파이프라인→첫걸음→시장분석
     →경쟁사→BM→안전설계→고객검증→UnitEcon→KPI→역산퍼널→로드맵→기술아키텍처→시제품현황→월별예산
```

**문제점 3가지:**
1. KPI(슬14) → 역산퍼널(슬15) 사이에 "현재 어디까지 왔나"(진행과정)가 없어 KPI 수치의 근거 맥락이 약함
2. 로드맵(슬16) → 기술아키텍처(슬17) 사이에 "우리가 어디로 가는가"(비전)가 없어 기술 설명이 갑자기 등장
3. 월별예산(슬19) 이후 "누가 만드는가"(팀소개)가 없어 Founder-Problem Fit 전달 불가 — 검증 기준 1-1(🔴)에 직접 저촉

### 3개 추가 후 최종 슬라이드 순서 제안 (22장)

```
슬1 표지 → 슬2 창업계기 → 슬3 고객페르소나 → 슬4 고객분포 → 슬5 Before-After
→ 슬6 5단계파이프라인 → 슬7 첫걸음 → 슬8 시장분석 → 슬9 경쟁사
→ 슬10 BM → 슬11 안전설계 → 슬12 고객검증 → 슬13 UnitEcon → 슬14 KPI
→ [신규 슬15] 진행과정 → 슬16 역산퍼널 → 슬17 로드맵
→ [신규 슬18] 비전 → 슬19 기술아키텍처(수정) → 슬20 시제품현황(수정) → 슬21 월별예산
→ [신규 슬22] 팀소개
```

**한 줄 판단:** 진행과정은 KPI 직후(검증 근거 → 현재 위치 연결), 비전은 로드맵 직후(어디로 가나 → 왜 가나 연결), 팀소개는 마지막(PPT 전체를 본 심사위원이 "누가?" 를 최후에 확인하는 구조로도 유효)으로 배치하면 스토리라인 완결성 충족.
