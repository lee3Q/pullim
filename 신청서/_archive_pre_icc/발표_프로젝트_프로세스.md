## Phase 1: 정답지 생성 (예상 1~1.5시간)

### Step 1-1: 팀원별 병렬 설명

COS가 4명의 팀원을 **병렬** 소환한다. 각 팀원은 담당 슬라이드를 순서대로 설명.

**소환 방법:**
```
Agent 소환:
- subagent_type: oh-my-claudecode:deep-executor
- model: sonnet

프롬프트 구성:
1. "네 프롬프트 파일을 읽어라: ~/study/main/창업/팀/prompts/{파일명}.md — 그게 너다."
2. "대본 파일을 읽어라: ~/study/main/창업/신청서/PPT_발표대본_v2_2026-03-11.md"
3. 하네스 1(발표_팀원설명_하네스.md)의 프롬프트 템플릿을 사용
4. 변수 치환: {팀원명}, {팀원역할}, 담당 슬라이드 번호/제목/대본
5. "담당 슬라이드를 순서대로 전부 설명해라. 슬라이드별로 구분해서 출력."
```

**4명 병렬:**
- A: 박도현 → prompts/PM_박도현.md → 슬1,2,3,4,8,10,12,14,15,16,18,21,22
- B: 한재원 → prompts/CTO_한재원.md → 슬6,13,17,19,20
- C: 서윤하 → prompts/AI_Lead_서윤하.md → 슬5,7,9
- D: 최서영 → prompts/Domain_Expert_최서영.md → 슬11

### Step 1-2: 대표 질문 (인터랙티브)

팀원 설명 출력 후, 대표에게 슬라이드별로 보여주며:
"이 설명 읽고 질문 있으면 던져. 없으면 '다음'."

대표 질문 → COS가 해당 팀원 재소환하여 답변 → 답변도 정답지에 포함.

### Step 1-3: 외부 심사위원 검증 (병렬)

모든 슬라이드 설명 완료 후, 하네스 2(발표_심사위원검증_하네스.md)를 사용하여
**전 슬라이드를 3~4그룹으로 나눠 병렬 검증**.

```
Agent 소환:
- subagent_type: oh-my-claudecode:deep-executor
- model: opus (엄격 심사위원은 Opus)

프롬프트: 하네스 2 템플릿에 변수 치환
- {슬라이드번호}, {슬라이드제목}, {대본내용}, {팀원설명내용}
- 슬라이드 5~6개씩 묶어서 한 에이전트에 전달
```

검증 결과 중 **수정 제안이 있는 슬라이드**만 정답지에 반영.

### Step 1-4: 정답지 확정 + Q&A 추가

1. 팀원 설명 + 심사위원 수정안 → 슬라이드별 정답지 통합
2. Q&A (슬23): 대본 v2의 Q1~Q9을 정답지에 그대로 포함
3. `~/study/main/창업/신청서/발표_정답지_2026-03-13.md`에 저장

**정답지 형식 (슬라이드당):**
```
## 슬라이드 {번호}: {제목}

### 핵심 주장
{1문장}

### 근거/데이터
{수치와 사실}

### 암기 팩트
- {팩트1}
- {팩트2}

### 예상 질문 + 답변
Q: {질문1}
A: {답변1}

Q: {질문2}
A: {답변2}

### 심사위원 수정안 (있으면)
{수정 제안}
```

## Phase 2: 채점 루프 (예상 1~2시간)

### 진행 방식

1. COS가 대표에게: "슬라이드 {번호} 봐. 말로 설명해봐."
2. 대표가 텍스트로 입력 (대본 없이, 슬라이드만 보고)
3. COS가 하네스 3(발표_채점_하네스.md) 사용하여 채점 에이전트 소환

```
Agent 소환:
- subagent_type: oh-my-claudecode:deep-executor
- model: sonnet

프롬프트: 하네스 3 템플릿에 변수 치환
- {슬라이드번호}, {슬라이드제목}
- {정답지내용}: 해당 슬라이드의 정답지
- {대표발표내용}: 대표가 입력한 텍스트
```

4. 채점 결과 대표에게 전달
5. **100점 미만** → 교정 내용 확인 → 재시도
6. **100점** → 다음 슬라이드

### 효율화 규칙

- 슬라이드를 3~4개씩 묶어서 한 번에 발표해도 됨 (대표 판단). 묶어서 발표 시 하네스는 슬라이드당 1회씩 순차 실행.
- 90점 이상이면 교정 확인 후 다음으로 넘겨도 됨 (대표 판단)
- 시간 부족 시 **핵심 슬라이드 우선**: 슬2(창업계기), 슬6(파이프라인), 슬11(안전), 슬12(고객검증), 슬22(팀소개)

## Phase 3: 외부 최종 검증 (예상 30분)

### 실행 조건
Phase 2에서 전 슬라이드 100점 달성 (또는 대표 승인으로 넘긴 것 포함).

### 진행

1. 정답지 전체 + 대표의 최종 발표 전체를 합쳐서 하네스 4(발표_외부최종검증_하네스.md)에 주입

```
Agent 소환:
- subagent_type: oh-my-claudecode:deep-executor
- model: opus (최종 검증은 Opus)

프롬프트: 하네스 4 템플릿에 변수 치환
- {전체_정답지}: 정답지 전문
- {전체_대표발표내용}: Phase 2에서 100점 받은 발표 전문
```

2. **90점 이상** → "발표 통과" → Phase 4
3. **90점 미만** → 지적 슬라이드만 Phase 2 재실행 → 재검증

## 주의사항

1. **PPT 수정 불가** — 모든 보완은 대본/말로만
2. **대표 시간 보호** — COS가 에이전트 작업하는 동안 대표는 쉬어도 됨
3. **Q&A 정답지** — 대본 v2의 Q1~Q9가 최종본 (24차 예상질문 통합 완료)
4. **모든 에이전트는 sonnet** (외부 심사위원 + 최종 검증만 opus)
5. **정답지는 세션 중 누적 저장** — 컨텍스트 한계 대비
