## 슬라이드 19: 기술 아키텍처

### 핵심 주장
Haiku-Sonnet-Opus 3계층 비용 최적화 파이프라인과 접근제어 설계로, 코드가 아니라 운영 노하우와 데이터 축적이 진짜 해자다.

### 발표 대본 (5분 압축)

기술 핵심만 말씀드리겠습니다.

Haiku가 고민 유형을 분류합니다. Sonnet이 Socratic 질문으로 핵심을 파악합니다. Opus 3개가 병렬로 분석하고 토론합니다.

**여기서 중요한 건, 3관점이 고정된 역할이 아닙니다. 고민 유형에 따라 전문가 페르소나가 바뀝니다. 건강 고민이면 의사의 역발상이, 진로 고민이면 철학자의 역발상이 나옵니다. 이 유연성이 프롬프트를 복사해도 재현할 수 없는 핵심 이유입니다.**

데이터 보호를 말씀드리면, PPT에 "완전 암호화"라고 적혀 있는데, **정확히 구분하겠습니다. Supabase RLS는 접근 제어입니다. 다른 사용자 데이터에 행 단위로 접근이 차단됩니다. 암호화는 별도로 HTTPS 전송 암호화와 Supabase 기본 저장 암호화가 적용됩니다. 접근 제어와 암호화 모두 갖춘 구조입니다.**

**해자에 대해서도 솔직히 말씀드리겠습니다. 코드 자체는 해자가 아닙니다. LangChain이나 CrewAI로 비슷한 구조를 만들 수 있습니다. 해자는 1년간 이 방식을 직접 쓰면서 실패하고 튜닝한 운영 노하우와, 세션이 쌓일수록 축적되는 고민 패턴 데이터입니다.**

### 암기 팩트
- 3계층: Haiku(분류) → Sonnet(Socratic 대화) → Opus 3명(병렬 분석+토론)
- **3관점 유연성**: 고민 유형별 전문가 페르소나 변동 → 프롬프트 복사 방어의 핵심 근거
- **RLS = Row Level Security = 접근 제어** (암호화와 혼용 금지)
- 전송: HTTPS 암호화 / 저장: Supabase 기본 암호화
- **해자 재정의**: 코드 아님 → "1년 운영 노하우 + 세션 데이터 축적 + 페르소나 유연성"
- LangChain 존재 인정 후 경험+데이터로 방어

### 예상 질문 + 답변

Q: "Supabase RLS가 민감 데이터 보호에 충분한가요?"
A: "두 가지를 구분합니다. RLS는 접근 제어입니다. 같은 데이터베이스 안에서 사용자 A가 사용자 B의 데이터에 접근하는 것을 행 단위로 차단합니다. 암호화는 별도입니다. 전송은 HTTPS, 저장은 Supabase 플랫폼 수준 암호화가 적용됩니다."

Q: "LangChain이나 CrewAI 쓰면 2주 안에 비슷한 거 못 만드나요?"
A: "구조는 만들 수 있습니다. 하지만 고민 유형에 따라 전문가 페르소나를 어떻게 배치해야 유효한 분석이 나오는지, Socratic 질문이 어떤 맥락에서 작동해야 하는지는 1년간 실패하며 쌓은 세부 튜닝입니다. 그리고 세션 데이터가 쌓일수록 개인화 정확도가 올라가는 구조라 시작점이 늦을수록 격차가 벌어집니다."

Q: "Anthropic API 종속이 리스크 아닌가요?"
A: "현재 Anthropic 메인입니다. 파이프라인 각 레이어는 교체 가능하게 설계돼 있어 Haiku-Sonnet-Opus 역할을 Gemini나 GPT 계열로 대체 가능한 구조입니다."

Q: "3관점이 결국 같은 AI 아닌가요? 진짜 다른 관점이 나오나요?"
A: "같은 모델 기반입니다. 그걸 부정하지 않습니다. 핵심은 역할 분리와 페르소나 유연성입니다. 건강 고민이면 의사 시각의 역발상이, 커리어 고민이면 경영자 시각의 역발상이 배치됩니다. 단일 AI에게 '여러 관점으로 분석해줘'라고 하는 것과, 파이프라인에서 역할이 분리된 에이전트가 각자 분석 후 토론하는 것은 산출물 품질에서 차이가 납니다."

## 슬라이드 20: 시제품 개발 현황

### 발표 대본 (5분 압축)

현재 시제품입니다.

1인 개발로 풀스택을 구현했습니다. 22개 소스 파일, 1,642줄입니다.

**프로토타입 구축은 완료됐고, 현재 v2 파이프라인 통합 중입니다.** Next.js와 Supabase, Anthropic API를 활용한 구조라 코드 자체는 간결합니다. 핵심 로직에 집중한 결과이고, 1인 개발로 유지보수 가능한 이유이기도 합니다.

### 암기 팩트
- 22개 소스 파일, 1,642줄 — 숫자 자랑 아님, "작동 중"이 포인트
- **v1 완료**: 9개 핵심 모듈 / **v2(멀티 에이전트)**: 3월 내 마무리
- **데모 유도 표현 전면 삭제** — "지금 바로 확인하세요" 절대 금지
- "프로토타입 구축 완료, 현재 v2 파이프라인 통합 중"으로 대체

- 9개 모듈: 고민입력, 유형분류(Haiku), Socratic질문(Sonnet), 3관점분석(Opus), 토론합성, 첫걸음문서생성, 위기감지, 대화인터페이스, 인증/RLS

### 예상 질문 + 답변

Q: "22개 파일 1,642줄이면 주말 해커톤 수준 아닌가요?"
A: "Next.js와 API 기반 풀스택이라 중복 코드가 없습니다. 군더더기를 뺀 결과입니다. 중요한 건 사용자가 고민을 입력하고 첫 걸음 문서가 나오는 전체 플로우가 돌아가고 있다는 점입니다."

Q: "v1과 v2의 차이가 뭔가요? 지금 올라가 있는 건 어느 버전인가요?"
A: "v1은 단일 AI Socratic 대화입니다. v2는 3명 병렬 분석과 토론이 추가된 멀티 에이전트 구조입니다. 현재 v1 기반 프로토타입이 구축돼 있고, v2 파이프라인은 통합 중입니다. 내부 테스트 환경에서 v2 검증을 진행하고 있습니다."

Q: "지금 직접 써볼 수 있나요?"
A: "프로토타입은 구축 완료 상태입니다. 현재 v2 파이프라인 통합과 내부 테스트를 진행 중이라, 안정화 후 공개 테스트를 진행할 계획입니다."

Q: "9개 모듈이 뭔가요?"
A: "고민 입력, Haiku 유형 분류, Sonnet Socratic 질문, Opus 3관점 분석, 토론 합성, 첫 걸음 문서 생성, 위기 감지 안전장치, 대화 인터페이스, 인증과 RLS입니다."

서버 인프라 50만원, 베타 테스트 및 UI/UX 130만원은 **조건부 집행입니다. 베타 피드백에서 UI 문제가 반복 지적될 때 씁니다.**

## 슬라이드 22: 팀 소개

### 핵심 주장
1인 창업이 강점이자 현재 단계에서 최적 선택이다. 리스크는 인지하고 있고, 베타 이후 확장 계획이 있다.

### 발표 대본 (5분 압축)

저 이상규는 한성대학교 기업경영·법정책 트랙 재학 중입니다.

AI-Native 1인 창업자로 기획부터 개발까지 직접 담당합니다. 22개 파일, 1,642줄의 풀스택 코드를 혼자 구현한 것이 증거입니다.

**1인 구조의 리스크를 모르지 않습니다. 제가 멈추면 제품도 멈춥니다. 의도적 선택입니다. PMF 검증 전에 팀을 키우면 방향도 안 정해진 상태에서 조율 비용만 증가합니다. 베타 이후 UI/UX와 마케팅 영역부터 협업자를 확보합니다.**

1년간 AI를 삶의 실제 의사결정에 직접 써온 경험이 이 제품의 원천이자, 제가 첫 번째 고객인 이유입니다.

### 암기 팩트
- 한성대 기업경영·법정책 트랙
- 22개 파일, 1,642줄, 1인 풀스택 (Claude Code 활용)
- **Bus factor 인정**: 리스크 인지 + 의도적 선택 + 베타 후 협업자 확보
- 1인 최적 이유: PMF 전 조율 비용 > 1인 리스크
- 베타 후 우선 영입: UI/UX + 마케팅
- **"스스로" 오탈자 회피**: 대본에서 해당 단어 사용하지 않음

### 예상 질문 + 답변

Q: "1인 개발이면 대표가 아프면 서비스 전체가 멈추지 않나요?"
A: "맞습니다. Bus factor 1 리스크입니다. 현재 단계에서 의도적으로 감수하는 리스크입니다. PMF 검증 전에 팀을 키우면 방향 미확정 상태에서 조율 비용만 올라갑니다. 베타 이후 유료 전환 신호가 오면 UI/UX와 마케팅 영역부터 협업자를 확보합니다."

Q: "법정책 전공이 이 사업과 관련이 있나요?"
A: "직접 관련이 있습니다. AI 멘탈케어는 규제 리스크가 큰 영역입니다. Woebot이 치료 영역에 진입했다가 폐업한 게 대표적 사례입니다. 저는 처음부터 웰니스/코칭 포지셔닝으로 경계를 그었고, 법정책 배경이 이 판단에 영향을 줬습니다."

Q: "디자인이나 마케팅 실적이 없는데?"
A: "현재까지는 기능 구현과 검증 우선이었습니다. MVP 단계 디자인은 작동 가능한 수준이면 충분하고, 본격 마케팅은 PMF 신호 이후입니다."

**Q2. TAM 근거가 무엇인가요?**

저희가 집중하는 건 TAM이 아니라 SOM입니다. 20~30대 130만명 중 0.6%인 1,000명이 초기 목표입니다. SAM 10%는 NIA 생성형 AI 이용률 33.3% 중 멘탈케어 수요를 보수적으로 1/3 적용한 수치입니다."

**Q3. 세션당 543원은 어떻게 나온 수치인가요? 검증됐나요?**

"Anthropic 공식 API 단가 기준으로 계산한 추정값입니다. 세션 1회를 대화 약 40턴으로 가정하고, Haiku 라우팅 약 2원, Sonnet 대화 약 150원, Opus 토론 3명 약 391원을 합산했습니다.

추정값임을 명확히 밝힙니다. 5월 베타 출시 후 실제 사용량으로 업데이트 예정입니다. Anthropic 공식 단가를 그대로 적용한 계산이라 방향성은 신뢰할 수 있습니다."

**Q4. 기존 ChatGPT, Claude와 어떻게 다른가요?**

"두 가지 차이입니다.

첫째, 구조입니다. ChatGPT는 사용자가 좋은 질문을 해야 좋은 답이 나옵니다. 풀림은 고민만 입력하면 파이프라인이 이끕니다. 사용자가 프롬프트 엔지니어링을 할 필요가 없습니다.

둘째, 산출물입니다. ChatGPT는 대화로 끝납니다. 풀림은 세션이 끝나면 의사결정 정리 문서가 남습니다. '그래서 어떻게 하지?'가 남는 것과, 첫 행동 1개가 적힌 문서가 남는 것은 다릅니다.

**추가로, 3관점 분석에서 고민 유형에 따라 전문가 페르소나가 바뀝니다. 단순히 '세 가지 관점으로 분석해줘'가 아니라, 건강 고민이면 의사 시각이, 커리어 고민이면 경영자 시각이 자동 배치됩니다. 이 유연성은 시스템 프롬프트 하나로 재현할 수 없습니다.**"

**Q5. 안전 문제는 어떻게 대응하나요?**

"3층 설계입니다.

GREEN — AI는 답을 주지 않고 질문만 합니다. 결론은 항상 사용자의 것입니다.

YELLOW — 감정적 어려움 신호가 감지되면 분석 에이전트를 중단하고 공감 모드로만 전환합니다.

RED — 위기 키워드 감지 시 즉시 세션을 중단하고 자살예방상담전화 1393을 연결합니다.

Woebot은 Crunchbase 기준 $123.5M을 투자받고 2025년 6월 종료됐습니다. 치료 영역에 진입했다가 규제와 재정 문제에 부딪혔습니다. 저희는 처음부터 웰니스/코칭으로 포지셔닝을 명확히 했습니다."

**Q6. 멘탈케어 앱인가요, 의사결정 도구인가요?**

"풀림은 의사결정 지원 도구입니다. 규제 포지셔닝은 웰니스/코칭입니다. 심리치료나 의료 서비스가 아닙니다.

다만 사람들이 가장 많이 구조화 지원을 필요로 하는 고민이 진로, 관계, 일상의 결정이기 때문에, 고객 문제를 제시할 때 멘탈케어 언어를 씁니다. 포지셔닝과 마케팅 언어를 구분하고 있습니다.

**사실 멘탈케어 AI는 아직 미개척 시장입니다. 기존 서비스들은 상담사 연결 플랫폼이지 AI가 직접 의사결정을 구조화해주는 서비스는 없습니다. 저희는 기존 카테고리에 들어가는 게 아니라 새 카테고리를 개척하는 위치입니다.**"

**Q7. 이 구조를 다른 팀이 2주 안에 모방 못 하나요?**

"구조는 모방할 수 있습니다. LangChain, CrewAI로 비슷한 파이프라인을 2주 안에 만드는 것 자체는 가능합니다. 그걸 부정하지 않겠습니다.

해자가 코드에 있지 않다는 걸 저도 압니다. 해자는 두 가지입니다.

하나, 1년간 이 방식으로 직접 고민을 풀어본 운영 노하우입니다. 특히 고민 유형별로 전문가 페르소나를 어떻게 배치해야 유효한 분석이 나오는지 — 이건 실패를 반복하며 쌓인 세부 로직입니다.

둘, 세션 데이터입니다. 사용자가 쌓일수록 고민 패턴 분석이 정교해집니다. 나중에 시작한 팀은 데이터에서 뒤집기 어렵습니다."

**Q8. "풀림"이라는 이름이 기존 브랜드와 겹치지 않나요?**

"확인했습니다. KIPRIS에서 직접 검색했고, 저희가 출원할 제9류 소프트웨어, 제42류 SaaS, 제44류 건강관리서비스에 '풀림' 상표는 등록돼 있지 않습니다.

동일 한글명의 광고대행사와 화장품 브랜드가 존재하지만, 상표는 지정 상품·서비스 분류별로 등록되기 때문에 업종이 다르면 법적 충돌이 없습니다. MVP 출시 전 선제적 상표 출원도 검토 중입니다."

**Q9. 혼자서 이 일정 다 가능한가요?**

단, 1인 구조는 리스크도 있습니다. 제가 멈추면 제품도 멈춥니다. 그걸 알면서 지금은 이 구조가 최선이라고 판단합니다. PMF 검증 전에 팀을 키우면 방향도 안 정해진 상황에서 조율 비용만 올라갑니다.

**Q-추가A. 시장이 정말 있나요? 멘탈케어 AI가 될까요?**

"기존 멘탈케어 시장은 상담사 연결 플랫폼입니다. 마인드카페, 트로스트 전부 '사람 상담사를 온라인으로 만나게 해주는 것'이 핵심이었습니다. AI가 직접 의사결정을 구조화해주는 서비스는 국내에 아직 없습니다.

저희는 기존 시장에 끼어드는 게 아니라 새 카테고리를 개척하는 위치입니다. 어머니의 요양병원 친구분들 사례에서도 확인했는데, 전문 상담은 비용과 시간 문제로 못 받는 분들이 많습니다. AI 기반 구조화 도구가 그 공백을 메우는 첫 번째 시도입니다."

**Q-추가B. 인터뷰 대상이 50대 주부라고 하셨는데, 어떻게 인터뷰하게 된 건가요?**

"어머니입니다. 60대 초반이시고, 요양병원에서 친구분들과 대화하시면서 상담 수요를 직접 확인해주셨습니다. 전문 상담을 받고 싶지만 비용과 시간 문제로 못 받는 분들이 많다는 이야기를 들었습니다. 제가 AI로 고민을 정리하는 걸 보시고 직접 사용해보신 뒤 '매우 좋음', WTP 1~3만원을 주셨습니다. 베타 테스터로도 참여 의사를 밝히셨습니다.

타겟 연령대가 아닌 분이 이 정도 반응을 보인 건, 타겟인 2030에서 더 강한 반응이 나올 수 있다는 단서입니다."

저희는 처음부터 다른 길을 선택했습니다. 치료가 아니라 웰니스/코칭 영역의 의사결정 구조화 도구입니다. 의료 행위가 아니기 때문에 동일한 규제 리스크를 갖지 않습니다."
