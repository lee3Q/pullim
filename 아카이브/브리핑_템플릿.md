## 1. 출근 브리핑 (세션 시작)

창업 모드 진입 시 비서가 team_state.yaml + 대시보드.md를 읽고 아래 형식으로 브리핑.

### 브리핑 포맷

```
========================================
 풀림(Pullim) 창업팀 브리핑
 {날짜}
========================================

[현재 단계] {phase} — {stage}

[Sprint] {sprint_name}
  목표:
  1. {goal_1} — {상태}
  2. {goal_2} — {상태}
  3. {goal_3} — {상태}

[블로커] {blockers 또는 "없음"}

[대기 안건]
  - {decisions_pending 항목들}

[마지막 회의] {last_meeting 또는 "아직 없음"}
[다음 행동] {next_action}

========================================
"{안건 요약}. 회의 시작할까?"
========================================
```

### 브리핑 규칙

- team_state.yaml과 대시보드.md **외** 파일은 읽지 않는다
- 브리핑은 **한 메시지**로 끝낸다 (추가 분석/제안 없이)
- 대표가 회의 시작을 지시하면 → 회의 프로토콜 진입
- 대표가 다른 작업을 지시하면 → 해당 작업 진행 (비서 보조 또는 에이전트 소환)

## 2. 회의 킥오프 포맷

대표가 "회의 시작"을 지시하면 비서가 아래 형식으로 킥오프.

### 킥오프 포맷

```
========================================
 팀 회의 #{번호}
 {날짜} | 안건: {N}개
========================================

[안건 1] {제목}
  배경: {왜 이 안건이 올라왔는지 1-2문장}
  관련 팀원: {이름, 이름, ...}
  관련 파일: {경로 (있으면)}

[안건 2] {제목}
  배경: ...
  관련 팀원: ...

[안건 N] ...

[발언 순서] {안건 1 기준}
  {이름} → {이름} → {이름} → {이름}
  (근거: {순서 결정 이유 한 줄})

========================================
안건 1부터 시작합니다. {첫 발언자 이름} 소환합니다.
========================================
```

### 킥오프 규칙

- 안건은 team_state.yaml의 decisions_pending + 대표 추가 안건
- 안건 순서: 긴급도 > 의존성 (다른 안건의 전제가 되는 것 먼저)
- 킥오프 출력 후 바로 첫 에이전트 소환 (대표 추가 확인 없이, 단 대표가 수정하면 반영)

## 3. 안건별 컨텍스트 패키지

각 에이전트를 소환할 때 전달하는 정보 구조.

### 컨텍스트 패키지 구조

```yaml
context_package:
  # 1. 에이전트 정체성 (항상 포함)
  identity:
    prompt_path: "~/study/main/창업/팀/prompts/{역할}_{이름}.md"
    instruction: "이 파일을 읽어라. 그 사람이 너다."

  # 2. 안건 (항상 포함)
  agenda:
    title: "안건 제목"
    description: "안건 상세 (2-5문장)"
    question: "구체적으로 답해야 할 질문"

  # 3. 팀 상태 요약 (항상 포함, 3줄 이내)
  team_status:
    phase: "Customer Discovery"
    sprint: "Sprint 0 — Customer Discovery"
    key_fact: "인터뷰 0건, MVP 미착수, 창업동아리 D-3"

  # 4. 이전 발언 (있으면)
  previous_statements:
    - speaker: "한재원"
      summary: "3-5줄 요약"
    - speaker: "서윤하"
      summary: "3-5줄 요약"

  # 5. 참고 파일 경로 (안건에 따라 다름)
  reference_files:
    - path: "~/study/main/창업/seed.yaml"
      relevance: "제품 스펙"
    - path: "~/study/main/창업/PRD_AI_의사결정_도우미_v1.md"
      relevance: "기능 상세"

  # 6. 요청 (항상 포함)
  request:
    format: |
      1. 핵심 의견 (3-5문장)
      2. 우려/리스크 (있으면)
      3. 이전 발언에 대한 반응 (있으면)
      4. 구체적 다음 행동 1-3개
```

### 안건 유형별 참고 파일 매핑

| 안건 유형 | 참고 파일 |
|----------|----------|
| MVP 기능/기술 | seed.yaml, PRD |
| 인터뷰/고객 발굴 | 인터뷰_결과, 리서치_종합 |
| 포지셔닝/전략 | 포지셔닝_기록, 리서치_종합 |
| 안전/규제 | PRD (안전 섹션), 리서치_종합 (규제 섹션) |
| 창업동아리/외부 | 리서치_종합 (심사 기준), PRD |
| 비용/수익 모델 | seed.yaml, 리서치_종합 (시장 규모) |

## 4. 회의 결론 포맷

각 안건 종료 시 비서가 정리하는 형식.

### 안건 결론 포맷

```
[안건 {N} 결론]
제목: {안건 제목}
결정: {결정 내용 1-2문장}
방식: {합의 / 조건부합의 / 표결 / 대표결정}
조건: {있으면}

실행 항목:
  1. {담당자} — {구체적 행동} (마감: {날짜})
  2. {담당자} — {구체적 행동} (마감: {날짜})

반대 의견: {있으면 기록, 없으면 "없음"}
```

### 회의 종료 포맷

```
========================================
 회의 #{번호} 종료
 {날짜} | 소요: {대략적 시간/라운드 수}
========================================

[결정 사항]
1. {안건1}: {결정 1줄}
2. {안건2}: {결정 1줄}

[실행 항목 종합]
| # | 담당 | 행동 | 마감 |
|---|------|------|------|
| 1 | {이름} | {행동} | {날짜} |
| 2 | {이름} | {행동} | {날짜} |

[다음 회의 안건] {있으면}
[다음 행동] {대표가 지금 바로 할 것 1개}

========================================
team_state.yaml, 대시보드.md 갱신 완료.
========================================
```

## 5. 대표 전용: 빠른 명령어

회의 중 대표가 사용할 수 있는 짧은 명령:

| 명령 | 동작 |
|------|------|
| "다음" | 현재 안건 종료, 다음 안건으로 |
| "넘겨" | 현재 발언자 스킵, 다음 발언자 |
| "내가 결정" | 토론 중단, 대표가 직접 결정 |
| "재원 불러" / "윤하 불러" 등 | 특정 팀원 추가 소환 |
| "정리해" | 현재까지 논의 요약 요청 |
| "끝" | 회의 종료 → 종료 프로토콜 실행 |
| "이것도 안건" | 새 안건 추가 |

## 6. 안건 없을 때

대기 안건(decisions_pending)이 비어 있고 대표가 특별히 지시하지 않은 경우:

비서의 대응:
1. Sprint 목표 중 미진행 항목 확인
2. "대기 안건 없음. Sprint 목표 중 {X}가 미시작. {담당자}에게 진행 상황 확인할까?"
3. 또는 "안건 없음. 뭘 할까?"로 대표에게 위임
