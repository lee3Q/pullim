## 2. 시작 팀원 결정

### 채택: 3명 시작 (CPO + CGO + CTO)

리서치에서 제안한 4명(CPO/CSO/CTO/CMO)은 **현재 단계에 과잉**이다. Pre-seed 단계에서 독립된 Strategy와 Marketing은 할 일이 없다.

| 역할 | 왜 지금 필요한가 |
|------|----------------|
| **CPO (Chief Product Officer)** | 고객 인터뷰 설계, Socratic 질문 세트 설계, MVP 스펙 관리, UX 판단. Customer Discovery 단계의 핵심 역할. 가설 → 검증 → 피벗 루프의 드라이버 |
| **CGO (Chief Growth Officer)** | 전략(Strategy) + 마케팅(Marketing) + 성장(Growth) 통합. Pre-seed에서 전략과 마케팅을 분리하면 각각 할 일이 너무 적다. 창업동아리 신청서, 초기 사용자 확보, GTM(Go-To-Market) 전략, 경쟁 분석을 한 사람이 담당 |
| **CTO (Chief Technology Officer)** | MVP 기술 구현 (Next.js + Supabase + Claude API), 프롬프트 엔지니어링, 인프라. 대표가 비개발자이므로 기술 판단을 위임할 전문가 필수 |

### HR: 별도 에이전트가 아니라 메타 시스템으로 운영

HR을 "팀원"으로 만들면 Pre-seed 단계에서 낭비다. 대신 HR은 **팀 운영 프로토콜 내장 시스템**으로 구축한다. 아무 팀원이든 충원 제안 가능 → 회의 → 대표 승인 → HR 시스템이 프롬프트 초안 작성.

### 탈락 역할과 근거

| 역할 | 탈락 사유 |
|------|-----------|
| **CSO (전략)** | Pre-seed에서 전략은 "고객 인터뷰 결과에 반응하기"다. 별도 전략 담당이 할 일이 없다. CGO가 흡수 |
| **CMO (마케팅)** | 제품이 없는데 마케팅할 게 없다. 창업동아리 신청서 + 초기 사용자 확보 수준은 CGO가 처리 |
| **CFO (재무)** | 매출 0원, 비용 = LLM API + 대표 생활비. 재무 관리할 것이 없다. 시드 펀딩 단계에서 소집 |
| **Ethics/Safety** | 규제 리스크는 실재하나(Woebot 사례), 지금은 "의료기기 아닌 웰니스 포지셔닝"으로 회피 중. MVP 출시 직전에 소집해도 늦지 않다. CTO가 위기 감지 기본 구현 담당 |
| **Research** | 독립 리서치 에이전트 불필요. 팀원 누구든 리서치 수행 가능. 필요 시 대표에게 Perplexity 요청 |

## 3. 팀 운영 방식 권고

### 3-1. 의사결정 체계 (DACI 변형)

| 유형 | 정의 | 프로세스 | 예시 |
|------|------|---------|------|
| **일상적** | 각 역할 범위 내 | 자율 실행 → 다음 회의에서 보고 | CTO가 라이브러리 선택 |
| **전술적** | 2개 이상 역할에 영향 | 제안서 작성 → 24시간 내 대표 승인 | MVP 스펙 변경 |
| **전략적** | 사업 방향에 영향 | 팀 토론 → 대표 최종 결정 | 포지셔닝 변경, 피벗 |
| **위기** | 즉각 대응 필요 | 대표 즉결 | 서비스 장애, 법적 문제 |

### 3-2. 회의 체계

| 회의 | 시점 | 목적 | 참여 |
|------|------|------|------|
| 아침 브리핑 | 세션 시작 시 | 어제 진행, 오늘 목표, 블로커 | 전원 |
| 저녁 리뷰 | 세션 종료 시 | 완료 사항, 내일 계획, 제안 처리 | 전원 |
| 임시 회의 | 필요 시 | 특정 안건 논의 | 관련 팀원 + 대표 |

### 3-3. 제안-승인 워크플로우

```
[아무 팀원] 제안서 작성 → ~/창업/팀/제안/ 에 저장
    ↓
[다음 회의] 안건으로 상정 → 팀 토론
    ↓
[대표] 승인/거절/보류 결정
    ↓
[승인 시] 실행 담당자 배정 → ~/창업/팀/의사결정/ 에 기록
```

### 3-4. 운영 5원칙

1. **Human-on-the-Loop**: 대표는 모든 전략적 결정의 최종 승인자. 일상적 결정은 팀 자율
2. **검증 의무**: 리서치 기반 주장은 출처 명시. "~인 것 같다"가 아니라 "~에 따르면"
3. **컨텍스트 주입**: 매 세션 시작 시 team_status.md 읽기. 맥락 단절 방지
4. **출력 채널 분리**: 대표 보고 ≠ 팀 내부 문서. 대표에게는 요약본, 상세는 파일로
5. **주간 감사**: 주 1회 "이번 주 뭘 했고, 다음 주 뭘 할 건지" 정리
