## 2. 라우팅 로직 설계

### 2.1 1차 분류 (LISTEN 1~2턴)

**방법: LLM 라우팅 + 키워드 보조**

라우팅 전용 프롬프트를 Gemini Flash-Lite(무료)에 전달:

```
사용자가 아래 고민을 가지고 왔다. 아래 3가지 레벨 중 하나로 분류하라.

[Quick] 되돌릴 수 있는 간단한 선택/비교. 예: 메뉴 선택, 색상 고르기, 간단한 일정.
[Talk] 감정 표현이 중심인 대화/상담. 정보보다 공감이 필요. 예: 번아웃, 관계 고민 토로.
[Deep] 되돌리기 어려운 복잡한 의사결정. 예: 이직, 창업, 이별, 투자.

사용자 발화: "{user_message}"

JSON으로 답변: {"level": "quick|talk|deep", "confidence": 0.0~1.0, "reason": "이유"}
```

**키워드 보조 (LLM 호출 전 프리필터):**

```typescript
const QUICK_KEYWORDS = ["vs", "뭐 먹", "뭐 할", "골라", "어떤 게", "A or B", "추천"];
const DEEP_KEYWORDS = ["이직", "퇴사", "창업", "이혼", "이별", "투자", "대출", "수술", "진학"];
const CRISIS_OVERRIDE = true; // detectCrisis는 라우팅 전에 항상 먼저 실행
```

키워드 매칭 → confidence 높으면 LLM 스킵 (비용 절감)
키워드 불일치 → LLM 라우팅 호출

### 2.2 위기 강제 전환 (교차검증 반영)

```
위기 감지 우선순위 (라우팅보다 먼저):
1. detectCrisis() 실행 (현행 룰 기반, 모델 무관)
2. RED → 즉시 중단 + 전문기관 안내 (현행 유지)
3. YELLOW → 레벨 무관 Claude Sonnet 강제 + safetyGuard 프롬프트
4. GREEN → 정상 라우팅 진행
```

### 2.3 소프트 확인 전환 (교차검증 반영)

자동 전환 대신 **사용자에게 확인**:

```
[업그레이드 트리거]
- Quick → Talk: 3턴 이상 대화 지속 시
  → "이 고민, 좀 더 깊이 얘기해볼까?" (선택지로 제시)

- Talk → Deep: "분석해줘", "비교해줘", "데이터 있어?" 키워드 감지 시
  → "구슬로 다각도 분석을 해볼 수 있어. 해볼래?" (선택지로 제시)

[다운그레이드 트리거]
- Deep → Quick: 1턴 만에 "A로 할래" 확정 시
  → 구슬/리서치 스킵, 바로 CONCLUDE 진행 (확인 없이 자연스럽게)

- Talk/Deep 중 사용자: "가볍게 얘기하자" / "복잡하게 안 해도 돼"
  → 즉시 Talk/Quick으로 전환 (사용자 명시 요청이므로 확인 불필요)
```

## 3. 레벨별 파이프라인 상세

### 3.1 Quick 파이프라인

```
ENTER → LISTEN(1~2턴) → [라우팅: Quick] → CONCLUDE → COMPLETE
```

**LISTEN 프롬프트 변경:**
- 기존 소크라틱 질문 대신 **구조화된 비교 질문**
- "A와 B 중에서 가장 중요한 기준이 뭐야?" (1턴)
- "그 기준이면 [A/B]가 나을 것 같은데, 맞아?" (2턴)

**CONCLUDE:**
- 간결한 1~2문장 정리
- 구슬/리서치 언급 없음
- "더 깊이 생각해보고 싶으면 알려줘" (Talk 업그레이드 유도)

**모델:** Gemini 2.5 Flash (무료 250 RPD)
**구슬:** 0개

### 3.2 Talk 파이프라인

```
ENTER → LISTEN(자유 대화) → [선택적] CRYSTAL → CONCLUDE → COMPLETE
```

**LISTEN:**
- 현행 소크라틱 질문 프롬프트 유지
- 턴 제한 없음 (사용자가 원할 때까지)
- 3턴마다 중간 정리 (현행 유지)

**구슬 사용 (선택적):**
- 사용자가 "정리해줘", "구슬 써볼래" 요청 시에만
- CRYSTAL_SELECT → CRYSTAL_ANALYZE 진행
- 이종모델 분석은 생략 (단일 모델 분석)

**CONCLUDE:**
- 대화 요약 + 핵심 질문 정리
- 리서치/토론 결과 없음 (없었으므로)

**모델:** Claude Sonnet 4.6 (한국어 공감 필수)
- 후속 A/B 테스트: Haiku 3.5 대체 가능성 검증 예정
**구슬:** 0~3개 (선택적)

### 3.3 Deep 파이프라인

```
ENTER → LISTEN → RESEARCH → VERIFY → DISCUSS_1 → CRYSTAL_SELECT → CRYSTAL_ANALYZE
→ DISCUSS_2 → DEBATE → DISCUSS_3 → JUDGE → CONCLUDE → COMPLETE
```

**변경 없음** — 현행 풀 파이프라인 유지
**모델:** Claude Sonnet + Gemini Pro + Perplexity Sonar
**구슬:** 3~5개

## 4. API 라우트 변경

### 신규 API: `/api/ultimate/route-concern`

```typescript
// POST /api/ultimate/route-concern
// 입력: { messages: Message[], turnCount: number }
// 출력: { level: ConcernLevel, confidence: number, reason: string }
```

1. `detectCrisis()` 먼저 실행
2. RED → 위기 응답 반환
3. YELLOW → `{ level: "talk", confidence: 1.0, reason: "crisis_yellow" }` + Sonnet 강제
4. GREEN → 키워드 프리필터 → (필요 시) Gemini Flash-Lite LLM 분류

### 기존 API 변경

| API | 변경 내용 |
|-----|----------|
| `/api/ultimate/listen` | `concernLevel` 파라미터 추가. Quick이면 비교 프롬프트, Talk/Deep이면 현행 |
| `/api/ultimate/analyze` | Quick에서는 호출 안 됨 (프론트에서 스킵) |
| `/api/ultimate/debate` | Quick/Talk에서는 호출 안 됨 |
| `/api/ultimate/conclude` | `concernLevel`에 따라 결론 프롬프트 분기 |

### 모델 선택 로직 (`lib/llm/` 변경)

```typescript
// lib/llm/model-router.ts (신규)
export function getModelForLevel(level: ConcernLevel, stage: StageName): ModelProvider {
  if (level === "quick") {
    return "gemini";  // Flash-Lite 또는 Flash
  }
  if (level === "talk") {
    return "claude";  // Sonnet (추후 Haiku A/B 테스트)
  }
  // deep
  switch (stage) {
    case "RESEARCH": return "gemini";  // Perplexity sonar (별도 처리)
    case "CRYSTAL_ANALYZE": return "gemini";  // Gemini Pro (교차 분석)
    default: return "claude";  // Sonnet
  }
}
```

## 6. 비용 시뮬레이션 (수정)

| 레벨 | 비율 | 모델 | 세션당 토큰 (in/out) | 세션당 비용 |
|------|------|------|---------------------|-----------|
| Quick 30% | 3,000 세션 | Gemini Flash (무료) | 500/300 | $0 |
| Talk 40% | 4,000 세션 | Sonnet $3/$15 | 3,000/1,500 | $0.032 |
| Deep 30% | 3,000 세션 | Sonnet+Pro+Sonar | 5,000/3,000 | $0.060 |
| 라우팅 100% | 10,000 세션 | Gemini Flash-Lite (무료) | 200/50 | $0 |

**월 총 비용: $0 + $128 + $180 + $0 = ~$308 ← 이전 시뮬레이션 오류**

**재계산 (정밀):**
- Talk 4,000 세션 × (3,000 × $3/1M + 1,500 × $15/1M) = 4,000 × $0.0315 = **$126**
- Deep 3,000 세션 × (5,000 × $3/1M + 3,000 × $15/1M) = 3,000 × $0.060 = **$180**
- Quick + 라우팅: **$0** (무료 티어)
- Perplexity (Deep 30%): 3,000 × (2,000 × $1/1M + 1,000 × $1/1M) = **$9**
- Gemini Pro (Deep 분석): 3,000 × (2,000 × $1.25/1M + 1,000 × $10/1M) = **$38**

**총합: ~$126 + $180 + $9 + $38 = $353/월**

⚠️ **현재($243)보다 비싸다!** Deep 비율 30%에서 Sonnet output 비용이 지배적.

### 수정안: Deep 비율 조정 + Talk 모델 최적화

**현실적 비율 가정:**
- Quick: 40% (간단한 고민이 더 많음)
- Talk: 40%
- Deep: 20% (진짜 복잡한 고민만)

| 레벨 | 세션 수 | 비용 |
|------|--------|------|
| Quick 40% | 4,000 | $0 (무료) |
| Talk 40% | 4,000 | $126 |
| Deep 20% | 2,000 | $120 + $6 + $25 = $151 |
| 라우팅 | 10,000 | $0 |
| **합계** | | **~$277/월** |

**Talk을 Haiku($1/$5)로 전환 시:**
- Talk: 4,000 × (3,000 × $1/1M + 1,500 × $5/1M) = 4,000 × $0.0105 = **$42**
- **합계: ~$193/월** (현재 $243 대비 21% 절감)

**Talk을 Gemini Flash($0.30/$2.50)로 전환 시:**
- Talk: 4,000 × (3,000 × $0.30/1M + 1,500 × $2.50/1M) = 4,000 × $0.00465 = **$19**
- **합계: ~$170/월** (30% 절감)

### 결론
- 라우팅만으로는 비용 절감 제한적 — **핵심은 Talk 모델 전환**
- Sonnet 유지 시: $277 (오히려 증가, Deep의 Pro/Sonar 추가 때문)
- Haiku 전환 시: $193 (21% 절감)
- Flash 전환 시: $170 (30% 절감)
- **모델 저비용화 + 라우팅 조합 시**: $124~170 달성 가능
