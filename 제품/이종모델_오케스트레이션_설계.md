## 모델 할당 전략

### 구슬 → 모델 매핑

사용자가 구슬 3개를 선택하면, 각 구슬에 서로 다른 모델을 배정한다.
배정은 **고정이 아니라 라운드 로빈** — 모델이 특정 구슬에 고착되면 편향이 고정된다.

```
사용자 선택: [금화, 나침반, 거울]

세션 A: 금화→Claude, 나침반→GPT, 거울→Gemini
세션 B: 금화→GPT, 나침반→Gemini, 거울→Claude
세션 C: 금화→Gemini, 나침반→Claude, 거울→GPT
```

배정 방식: `session_id의 해시 % 3` → 시작 오프셋 결정 → 라운드 로빈

### 모델별 역할

| 역할 | 모델 | 이유 | 비용 |
|------|------|------|------|
| 라우팅 | Claude Haiku 4.5 | 빠름, 저비용 | ~1원 |
| 리서치 검색 | Tavily API | 무료 1,000회/월 | 0원 |
| 리서치 요약 | Claude Sonnet 4.6 | 요약 품질 | ~18원 |
| 구슬 분석 1 | Claude Sonnet 4.6 | 코드/긴 문서/안정성 | ~18원 |
| 구슬 분석 2 | GPT-5.4 | 범용/에이전트/창작 최상위 | ~17원 |
| 구슬 분석 3 | Gemini 3.1 Pro | 한국어/번역/다국어 최강 | ~14원 |
| 불일치 감지 | Claude Sonnet 4.6 | 합성 능력 | ~13원 |
| 토론 R1×2 + R2 | 교차 모델 | 각 모델의 분석을 다른 모델이 비평 | ~38원 |

## 구슬 재화 — 점진적 소모 모델

세션 시작 전에 비용을 정하지 않고, **진행하면서 단계마다 구슬을 소모할지 사용자가 선택**.

```
입장 + 듣기:        무료 (구슬 0개)
리서치(검색):       +1구슬 ("두루마리를 펼쳐볼까?")
구슬 분석 1모델:    +1구슬
  → "더 깊이 볼까?" → 추가 모델당 +1구슬씩
토론(모델 간 비평): +1구슬 (불일치 발견 시에만 제안)
Judge + 결론:       무료 (이미 쓴 구슬의 가치 완성)
```

결과:
- 가벼운 고민 (저녁 메뉴): 1~2구슬 → ~50~100원
- 중간 고민: 3~4구슬 → ~150~200원
- 무거운 고민 (이직, 창업): 5~6구슬 → ~250~300원

유료: 주 50구슬 / 무료: 주 10구슬 + 광고(4회 시청 = 1구슬)
품질은 동일 — 사용 횟수로만 차등.

세계관 UX: "구슬 쓸까?" 가 아니라 현자가 세계관 언어로 묻는다.
```
🧙 "구슬 두 개가 다른 말을 하는군.
    더 깊이 들여다볼 수 있네. 구슬 하나를 더 쓰겠나?"
[깊게 보기 +1구슬] / [여기서 정리]
```

## 파이프라인 상세 (9단계)

### 0. 입장 + 라우팅
```
입력: 사용자 고민 텍스트
처리: Haiku로 라우팅 (concern_type + 4축 점수 + 추천 구슬 3개)
출력: { concern_type, scores, recommended_crystals }
```

V2의 `ROUTING_V2_PROMPT` 재활용, `recommended_experts` → `recommended_crystals` 변경.

### 1. 리서치 (신규)
```
입력: 사용자 고민 + concern_type
처리:
  1) Sonnet이 검색 쿼리 3개 생성
  2) Tavily API로 병렬 검색
  3) Sonnet이 검색 결과 요약 + 출처 URL 보존
출력: { queries, raw_results, summary, sources[] }
```

검색 쿼리 생성 프롬프트:
```
사용자 고민: {concern}
고민 유형: {concern_type}

이 고민에 대해 데이터 기반 분석을 위한 검색 쿼리 3개를 생성해라.
1. 통계/수치 관련 (예: "한국 1인 창업 생존율 통계 2025")
2. 사례/경험 관련 (예: "AI SaaS 1인 창업 성공 사례")
3. 전문가 견해 관련 (예: "창업 vs 취업 경제학 연구")

JSON으로만 출력: { "queries": ["...", "...", "..."] }
```

### 2. 검증 (리서치 팩트체크)
```
입력: 리서치 결과
처리: Judge 모델(Gemini Pro)이 주요 수치/주장 팩트체크
출력: { verified_claims[], flagged_claims[], confidence }
```

사용자에게 비노출. 현자가 "걸러준" 것으로 처리.

### 3. 논의 1 (데이터 공유)
```
입력: 검증된 리서치 결과
처리: 캐릭터 렌더링 (Sonnet) — 데이터를 세계관 톤으로 전달
출력: 데이터 카드 UI + 사용자에게 "가장 무겁게 느껴지는 것" 선택 요청
```

### 4. 관점 분석 (구슬) ← 핵심
```
입력: 사용자 고민 + 리서치 결과 + 사용자가 선택한 무거운 데이터
처리: 3개 모델이 **동시에** 독립 분석
출력: { crystal_analyses[3], disagreements[] }
```

#### 프롬프트 구조 (3개 모델 공통)

```
[분석 렌즈: {crystal_name}]
이 렌즈는 {crystal_description}

[사용자 상황]
{concern_summary}

[리서치 데이터]
{research_summary}

[분석 규칙]
- 이 렌즈의 관점에서만 분석해라.
- 500자 이내.
- 구체적 수치와 근거를 포함해라.
- 마지막에 사용자에게 던질 핵심 질문 1개.
- 다른 렌즈의 관점을 참조하지 마라.

[출력 형식]
{
  "observation": "이 렌즈로 본 현실",
  "insight": "보이지 않던 것",
  "risk": "이 관점의 리스크",
  "question": "사용자에게 질문"
}
```

**같은 프롬프트, 다른 모델** → 진짜 불일치가 나옴.

#### 불일치 감지 알고리즘

```typescript
interface DisagreementPoint {
  topic: string;           // 불일치 주제
  positions: {
    crystal: CrystalName;
    model: ModelProvider;
    stance: string;        // 요약
  }[];
  severity: 'minor' | 'major' | 'critical';
  user_implication: string; // "이것이 당신 고민의 핵심 갈림길"
}
```

감지 방식:
1. 3개 분석 결과를 Sonnet에게 넘김
2. "세 분석에서 서로 다른 방향을 제시하는 지점을 찾아라" 프롬프트
3. 불일치 0개면 "세 구슬이 같은 방향" → 확신 강화
4. 불일치 1~2개면 "핵심 갈림길" → 토론 단계에서 깊게
5. 불일치 3개 이상이면 "복잡한 상황" → 추가 구슬 제안

### 5. 논의 2 (사용자 반응)
```
입력: 3개 분석 결과 + 불일치 지점
처리: 캐릭터가 "어떤 구슬의 말이 가장 가슴에 와닿았는가?" 질문
출력: 사용자 선택 + 추가 맥락
```

### 6. 토론 (구슬 간 교차)
```
입력: 3개 분석 + 불일치 지점 + 사용자 선택
처리: 2라운드 토론
출력: 수렴된 결론
```

#### 라운드 1: 비선택 구슬 → 선택 구슬에 반론
```
[너는 {crystal_A}의 관점이다]
사용자가 {crystal_B}의 분석에 공감했다.

[선택된 분석]
{crystal_B_analysis}

[너의 분석]
{crystal_A_analysis}

[핵심 불일치]
{disagreement}

[지시]
- 선택된 분석에서 놓치고 있는 것 1개를 짚어라.
- 300자 이내.
- 사용자 선택을 존중하되, 보완점은 명확히.
```

**중요**: 라운드 1은 **원래 분석을 만든 모델이 아닌 다른 모델**이 수행.
→ 구슬 A의 반론을 구슬 A를 분석한 모델이 하면 자기 합리화 위험.
→ 구슬 A의 분석은 Claude가 했지만, 반론은 GPT가 수행.

#### 라운드 2: 선택 구슬이 수용/반박
```
[반론 2개를 받고 최종 정리]
- 수용할 것은 수용, 유지할 것은 유지.
- 최종 분석 300자 + 핵심 질문 1개.
```

### 7. 논의 3 (사용자 확인)
```
처리: 캐릭터가 토론 결과 공유 + 사용자 반응 확인
분기: [동의] → 8단계 / [다른 구슬로 다시] → 4단계 / [추가 입력] → 추가 토론 1라운드
```

### 8. 검증 (최종)
```
입력: 전체 논리 흐름 (리서치→분석→토론)
처리: Judge 모델이 논리 일관성, 누락, 모순 체크
출력: 문제 있으면 캐릭터가 "한 가지 더 짚어주겠네..." / 없으면 9단계로
```

### 9. 결론 + 다음 단계
```
입력: 전체 세션 데이터
처리: Sonnet이 종합 정리 → 캐릭터 톤 렌더링
출력: {
  situation_summary,
  options[]: { direction, risk, reward },
  key_crossroad,         // 불일치에서 나온 핵심 갈림길
  user_tendency,         // 발화 패턴 기반 성향
  action_commitment,     // "뭘 해볼 건가" → 선택 → 기한
  next_session_date      // "기다리고 있겠네"
}
```

## API 호출 흐름도

```
[사용자 입력]
    │
    ▼
[0. 라우팅] ─── Haiku ──→ concern_type + 추천 구슬
    │
    ▼
[1. 리서치] ─── Sonnet(쿼리생성) → Tavily(검색) → Sonnet(요약)
    │
    ▼
[2. 팩트체크] ── Gemini Pro ──→ 검증 결과 (비노출)
    │
    ▼
[3. 논의 1] ─── Sonnet(캐릭터) ──→ 데이터 카드 UI
    │
    ▼
[4. 구슬 분석] ─┬─ Claude Sonnet ──→ 구슬 A 분석
                ├─ GPT 4.1 mini ───→ 구슬 B 분석   ← 병렬
                └─ Gemini Flash ───→ 구슬 C 분석
    │
    ├─ Sonnet ──→ 불일치 감지
    │
    ▼
[5. 논의 2] ─── Sonnet(캐릭터) ──→ 사용자 반응 수집
    │
    ▼
[6. 토론] ──┬─ R1: 모델 교차 반론 (2건 병렬)
            └─ R2: 선택 구슬 최종 정리
    │
    ▼
[7. 논의 3] ─── 확인 (분기 가능)
    │
    ▼
[8. 검증] ──── Gemini Pro(Judge) ──→ 논리 체크
    │
    ▼
[9. 결론] ──── Sonnet(캐릭터) ──→ 정리 + 약속 + "기다리고 있겠네"
```

총 API 호출: ~12회 (병렬 포함)
총 대기 시간: ~15초 (병렬 3 + 순차 9, 각 ~1.5초 평균)

## 폴백 전략

### 모델 실패 시

| 실패 모델 수 | 대응 |
|-------------|------|
| 0 | 정상 (3구슬 3모델) |
| 1 | 남은 2개 모델로 진행 + "구슬 하나가 흐려졌군..." 연출 |
| 2 | 남은 1개 모델로 3구슬 모두 분석 + 경고 |
| 3 | 오프라인 모드: 리서치 데이터 기반 정리만 제공 |

#### 폴백 우선순위
```
1순위: Claude Sonnet (가장 안정적)
2순위: Gemini Flash (무료, 안정)
3순위: GPT 4.1 mini
```

#### 타임아웃
- 각 모델 응답: 30초 (초과 시 폴백)
- 전체 파이프라인: 3분 (초과 시 현재까지 결과로 정리)

### API 키 미설정 시

```typescript
const availableProviders = {
  claude: !!process.env.ANTHROPIC_API_KEY,
  gpt: !!process.env.OPENAI_API_KEY,
  gemini: !!process.env.GOOGLE_AI_API_KEY,
};

// 사용 가능한 모델 수에 따라 모드 결정
const mode = Object.values(availableProviders).filter(Boolean).length;
// 3: 풀 오케스트레이션
// 2: 2모델 오케스트레이션 + 1모델 이중 분석
// 1: 단일 모델 (V2 호환 모드)
// 0: 오류
```

## 타입 시스템 (V2 → 끝판왕)

### 새 타입

```typescript
// 구슬
export type CrystalName =
  | "금화" | "나침반" | "거울" | "저울" | "모닥불"
  | "타인" | "심연" | "전략" | "뒤집기" | "몸";

// 모델 프로바이더
export type ModelProvider = "claude" | "gpt" | "gemini";

// 캐릭터
export type CharacterName = "현자" | "비서" | "코치" | "친구";

// 테마
export type ThemeName = "모험가" | "전략실" | "달빛정원";

// 구슬 분석 결과
export interface CrystalAnalysis {
  crystal: CrystalName;
  model: ModelProvider;         // 어떤 모델이 분석했는지
  observation: string;
  insight: string;
  risk: string;
  question: string;
  raw_response: string;         // 원문 보관
  latency_ms: number;
}

// 불일치
export interface Disagreement {
  topic: string;
  positions: {
    crystal: CrystalName;
    model: ModelProvider;
    stance: string;
  }[];
  severity: "minor" | "major" | "critical";
  user_implication: string;
}

// 리서치 결과
export interface ResearchResult {
  queries: string[];
  sources: { url: string; title: string; snippet: string }[];
  summary: string;
  verified: boolean;
  flagged_claims: string[];
}

// 끝판왕 세션
export interface Session {
  id: string;

  // 메타

  listen_summary: string | null;
  created_at: string;
  completed_at: string | null;
  total_cost_won: number;       // 세션 총 비용 (원)
  model_usage: Record<ModelProvider, { calls: number; tokens: number }>;
}

export type StageName =
```
