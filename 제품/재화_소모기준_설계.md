# 재화 소모 기준 설계 — 점진적 소모 모델

> 날짜: 2026-03-20
> 기반: 구독티어_재설계.md, 무료티어_설계.md, 렌즈_재화_관계_설계.md, 수익모델_심화설계.md
> 교차검증: Claude + GLM-5 (2자 완료)
> 상태: **교차검증 반영 확정**

---

## 1. 설계 원칙

1. **1재화 = 1단계**: 파이프라인 1단계를 여는 데 재화 1개. 가장 직관적인 단위
2. **투명성**: 사용자가 매 단계마다 소모를 보고, 다음 단계 진행을 선택한다
3. **점진적 소모**: 세션 시작 시 전액 차감 아님. 단계별 차감, 중간 이탈 시 보존
4. **품질 차등 없음**: 무료/유료 동일한 풀 파이프라인. 차등은 재화 수량만
5. **적자 방지**: 일/세션 캡 + 토큰 예산 시스템

---

## 2. 재화 네이밍 (확정)

렌즈(관점)와 재화(비용)는 **완전 분리**한다. (→ 렌즈_재화_관계_설계.md)

| 테마 | 분석 렌즈 (관점, 무료) | 재화 (비용, 소모) |
|------|---------------------|-----------------|
| 모험가 | 수정구슬 🔮 | **불씨** 🔥 |
| 달빛정원 | 꽃봉오리 🌸 | **달빛** 🌙 |
| 전략실 | 분석 렌즈 🔍 | **크레딧** 💳 |

- 렌즈 = 항상 10개, 사라지지 않음. 고르는 것.
- 재화 = 소모품. 파이프라인 단계를 열 때 쓰임.
- 1불씨 = 1달빛 = 1크레딧 (가치 동일, 표시만 다름)

> 교차검증 합의: Claude "불씨" 동의, GLM-5 "에너지/불꽃" 제안 → 방향 일치. 렌즈_재화_관계_설계.md의 "불씨" 확정을 따른다.

## 3. 소모 단위: 1재화 = 1파이프라인 단계

### 3-1. 단계별 소모 & 비용

| 파이프라인 단계 | 재화 소모 | 비용 | 비고 |
|---------------|----------|------|------|
| 입장 + 듣기 | **무료** | 0원 | 항상 무료 — 고민 진입 장벽 제거 |
| 리서치 (Tavily + 요약) | 1 | ~40원 | 선택 가능 ("두루마리 펼치기") |
| 구슬 분석 — 1모델 | 1 | ~25원 | 이종 모델 독립 분석 |
| 구슬 분석 — 추가 모델 (각) | 1 | ~25원 | 최대 2개 추가 (총 3모델) |
| 토론 (불일치 합성) | 1 | ~50원 | 구슬 2개 이상 분석 시 선택 가능 |
| Judge + 결론 | **무료** | 0원 | 항상 무료 — 세션 마무리 보장 |

### 3-2. 재화당 가중 평균 비용

| 구분 | 값 |
|------|-----|
| 가중 평균 (사용 분포 반영) | **~25-30원/재화** |
| 범위 | 25원(분석) ~ 50원(토론) |

> 교차검증 반영: 초안의 "1구슬=50원"은 폐기. per-interaction 모델에서 1재화=25-30원이 정확.

### 3-3. 세션별 자연 소모 분포

고정 경로 없음. 사용자가 단계마다 선택하면 자연스럽게 소모량이 결정된다.

| 고민 무게 | 경로 예시 | 재화 | 비용 |
|----------|----------|------|------|
| 가벼운 | 듣기 → 리서치 → 분석 1모델 → 결론 | 2 | ~65원 |
| 보통 | 듣기 → 리서치 → 분석 2모델 → 결론 | 3 | ~90원 |
| 무거운 | 듣기 → 리서치 → 분석 3모델 → 토론 → 결론 | 5 | ~165원 |
| 풀 | 듣기 → 리서치 → 분석 3모델 → 토론 → 결론 (+ 추가 토론) | 6 | ~215원 |

> 초안의 "5단계 고정 경로(한마디/가벼운/보통/깊은/최심층)" 폐기.
> 교차검증 합의: 점진적 소모 모델에서는 경로를 미리 이름 붙일 필요 없음. 자연 발생.

## 4. 점진적 소모 흐름 (모험가 기준)

```
[잔여 불씨: 🔥🔥🔥🔥🔥🔥🔥🔥🔥🔥  (10개)]

1. 입장 + 듣기: 무료
   🧙 "모험가여, 오늘은 무슨 바람이 불어 찾아왔는가?"
   [고민 입력]

2. 리서치:
   🧙 "세상의 기록을 살펴보겠네. 불씨 하나로 두루마리를 펼치겠나?"
   [🔥 두루마리 펼치기] / [넘어가기]
   → 잔여: 🔥🔥🔥🔥🔥🔥🔥🔥🔥 (9개)

3. 수정구슬 선택: 무료
   🧙 "어떤 눈으로 세상을 보고 싶은가?"
   → 수정구슬 10개 표시, 1~3개 선택 (비용 없음)

4. 구슬 분석 (선택한 수만큼 불씨 소모):
   🧙 "금화의 구슬이 있구나. 불씨를 비춰볼까?"
   [🔥 금화 비추기] → 분석 결과 → 잔여: 🔥🔥🔥🔥🔥🔥🔥🔥 (8개)

   🧙 "나침반과 거울도 기다리고 있네."
   [🔥 나침반 비추기] / [여기서 정리]
   [🔥 거울 비추기] / [두 개로 충분해요]

5. 토론 (2개 이상 분석 시):
   🧙 "구슬들이 다른 말을 하는군. 부딪혀볼까?"
   [🔥 토론 열기] / [넘어가기]

6. Judge + 결론: 무료
   🧙 "모든 구슬이 비춰졌네. 정리해주겠네."
```

**핵심 UX**: 매 단계에서 [🔥 진행] / [넘어가기] 선택. 사용자가 비용을 통제한다.

## 5. 라우터 AI (MVP: OFF → 데이터 후 ON)

### 5-1. MVP 전략

> 교차검증 합의: Claude "upward bias" vs GLM-5 "데이터 없이 편향 위험" → **MVP에서 라우터 OFF, 사용자 직접 선택**.

| 단계 | 라우터 | 이유 |
|------|--------|------|
| **MVP** | OFF — 사용자가 단계별 직접 선택 | 오분류 리스크 회피. 데이터 축적 |
| **v2** (데이터 100건+) | ON — 추천 표시, 사용자 최종 선택 | 추천-선택 일치율 기반 보정 |
| **v3** | 자동 + 편향 보정 | 과소추천 방지 upward bias 적용 가능 |

### 5-2. v2 라우터 프롬프트 (향후 활성화 시)

```
[라우터 — 재화 소모 추정]

사용자 입력을 분석하여 예상 재화 소모량을 반환하라.

판단 기준:
1. 리서치가 필요한가? (시장/법률/통계 → +1재화)
2. 관점이 몇 개 필요한가? (단순 1개, 복합 2-3개 → +1~3재화)
3. 관점 간 충돌이 예상되는가? (→ 토론 +1재화)

반환:
{
  "estimated_cost": 2~6,
  "reason": "추정 이유 1줄",
  "breakdown": { "research": 1, "analysis": 2, "debate": 1 }
}
```

### 5-3. 라우터 학습 데이터 (수집용)

```typescript
interface RouterLearning {
  sessionId: string;
  userInput: string;
  // 사용자가 실제로 선택한 단계들
  stagesChosen: string[];
  totalCost: number;
  // 세션 만족도 (별점 or 재방문 여부)
  satisfaction: number;
}
```

## 7. 안전장치

### 7-1. 일일 캡 — soft wall + hard wall 2단계

> 교차검증 반영: Claude "soft/hard 2단계" 제안, GLM-5 "티어별 차등" 제안 → 둘 다 채택.

```
[Soft wall] 일일 재화의 50% 소모 시
  → "오늘 많이 이야기했네. 잠시 쉬었다 오는 것도 좋겠네." + 계속 사용 가능
  → 모험 3개, 여정 8개, 현자 15개 도달 시

[Hard wall] 일일 상한 도달 시
  → "오늘은 여기까지일세. 내일 모닥불이 다시 탈 걸세."
  → 모험 6개, 여정 15개, 현자 30개 도달 시
```

**Soft wall 목적**: 감정적 과다 사용(emotional binge) 부드러운 제어. 위기 안전 프로토콜과 연계.

### 7-2. 세션 캡

- 1세션 최대: 8재화 (리서치 1 + 분석 3 + 토론 1 + 추가 토론 2 + 여유 1)
- 추가 토론 라운드: 최대 2회 hard cap

### 7-3. 토큰 예산 시스템

| 파이프라인 단계 | input 상한 | output 상한 | 초과 시 |
|---------------|-----------|-----------|--------|
| 리서치 | 검색 5회 | 2K tokens | 검색 횟수 제한 |
| 구슬분석 (각) | 2K | 1.5K | 분석 깊이 축소 |
| 토론 합성 | 4K | 2K | 핵심 불일치만 추출 |
| Judge | 5K | 1K | pass/fail만 반환 |

초과 처리:
```
< 20%  → 흡수 (사용자에게 투명)
20-50% → graceful wrap-up (해당 단계 조기 종료)
> 50%  → hard stop + 다음 단계 전환
```

**사용자에게는 초과가 보이지 않는다.** 재화 N개로 안내했으면 N개만 차감.

### 7-4. 비용 기준 안전장치

| 수준 | 조건 | 액션 |
|------|------|------|
| 정상 | 세션 비용 < 300원 | 정상 진행 |
| 주의 | 세션 비용 300-500원 | 로그 기록 |
| 경고 | 세션 비용 > 500원 | graceful wrap-up |
| 긴급 | 단일 API 호출 > 300원 | 즉시 중단 + 알림 |

## 9. 구현 데이터 모델

```typescript
interface FuelBalance {
  userId: string;
  tier: 'adventure' | 'journey' | 'sage';
  weeklyAllocation: number;    // 10 | 50 | 100
  remaining: number;           // 현재 잔여 (이월분 포함)
  usedToday: number;           // 오늘 사용량 (soft/hard wall 체크)
  carryOver: number;           // 이월분 (다음 주에만 유효)
  resetDay: string;            // 주간 리셋 요일 (월요일 00:00)
}

interface SessionConsumption {
  sessionId: string;
  userId: string;
  stages: StageConsumption[];  // 단계별 소모 기록
  totalFuel: number;           // 총 재화 소모
  totalCostKrw: number;        // 실제 API 비용 (원)
  tokenOverageKrw: number;     // 초과 토큰 흡수 비용 (원)
}

interface StageConsumption {
  stage: 'research' | 'analysis' | 'debate';
  fuelCost: number;            // 이 단계의 재화 소모 (0 or 1)
  model: string;               // 사용된 모델
  tokensUsed: number;
  tokenBudget: number;
  skipped: boolean;            // 사용자가 "넘어가기" 선택 시
}
```

## 10. 교차검증 결과 요약

| 항목 | Claude | GLM-5 | 최종 반영 |
|------|--------|-------|----------|
| 단가 매핑 | 1구슬=50원 불일관 | 45원 버퍼 필요 | **1재화=25-30원** (per-interaction 전환) |
| 네이밍 | "불씨" 동의 | "에너지/불꽃" | **불씨/달빛/크레딧** (확정) |
| 이월 | 부분 이월 필요 | 이탈 리스크 높음 | **여정 50%/현자 100%** (확정) |
| 라우터 | upward bias | MVP OFF, 데이터 후 | **MVP OFF → v2 ON** (합의) |
| 일일 캡 | soft+hard 2단계 | 티어별 차등 | **둘 다 채택** |
| 5단계 경로 | 자연 발생으로 충분 | 미리 이름 불필요 | **고정 경로 폐기** → 점진적 소모 |
